# 79 · 0.4.0.11 — Retry-failed-application flow

## Goal

Add a single-click recovery path for DRAFTs with persistent submission
failures. Today: operator clicks "View" on stuck-queue card → goes
back to Discover review-and-apply → manually re-edits → Submit.
After this plan: operator clicks "Retry" on the application detail
slide-over OR stuck-queue card → cleared failure + re-queued for auto-apply
(if Settings allow) OR ready for manual submit.

## Why

`docs/design/research/0.4.0-AUDIT.md § C` lists this as gap 0.4.0.11
(MEDIUM). Postmortem capture (plan 52 / 0.2.3.02) gives the operator
diagnostic context; this plan completes the recovery loop.

Concretely useful for failure kinds that are "transient on next try"
— `rate_limit`, `unknown` (often a temporary 503), `low_confidence`
(after operator tunes the threshold per plan 78 M4). Less useful for
`auth_required` and `captcha` (those need credential re-config), but
the retry action is still safe — it just re-queues.

## Proposal

Single PR; 2 commits.

### D.1 Commit 1 — service + route

`src/services/application_service.py` — new function:

```python
async def retry_failed(
    session: AsyncSession,
    application_id: int,
    *,
    user_id: int,
) -> Application:
    """Clear submission_artifacts.last_failure + re-queue for auto-apply.

    Returns the updated Application. Raises ApplicationServiceError if
    application doesn't exist or belongs to another user. Raises
    IllegalStateTransition if application.status != DRAFT.
    """
    application = await get_application(session, application_id)
    if application is None or application.user_id != user_id:
        raise ApplicationServiceError(f"application {application_id} not found")
    if application.status != ApplicationStatus.DRAFT:
        raise IllegalStateTransition(
            f"can only retry DRAFTs (was {application.status.value})"
        )
    if application.submission_artifacts is None or "last_failure" not in application.submission_artifacts:
        raise IllegalStateTransition("no last_failure to retry")

    # Strip the failure marker. Keep retry_count for audit.
    artifacts = dict(application.submission_artifacts)
    artifacts.pop("last_failure", None)
    application.submission_artifacts = artifacts
    application.updated_at = datetime.now(UTC)
    session.add(application)

    # Re-queue if Job exists
    if application.job_id:
        job = (await session.exec(select(Job).where(Job.id == application.job_id))).one_or_none()
        if job is not None and job.queue_state == JobQueueState.SAVED:
            # Only flip to QUEUED if user has auto-apply enabled; otherwise stay SAVED
            settings = (await session.exec(
                select(Settings).where(Settings.user_id == user_id)
            )).one_or_none()
            if settings is not None and settings.auto_apply_enabled:
                job.queue_state = JobQueueState.QUEUED_FOR_AUTO_APPLY
                job.updated_at = datetime.now(UTC)
                session.add(job)

    await _emit_event(
        session, user_id=user_id, application_id=application_id,
        kind=AppEventKind.AUTO_APPLY_QUEUED,
        payload={"trigger": "retry_requested", "previous_retry_count": artifacts.get("retry_count", 0)},
    )
    await session.flush()
    return application
```

**New route:** `src/ui/routes/tracking.py`

```python
@router.post(
    "/api/v1/applications/{application_id}/retry",
    name="applications_retry",
)
async def post_retry_application(
    application_id: int,
    session: AsyncSession = Depends(get_session),
    user: User | None = Depends(require_authed_session),
    _csrf: None = Depends(require_csrf),
):
    try:
        await application_service.retry_failed(
            session, application_id, user_id=_effective_user_id(user)
        )
    except application_service.IllegalStateTransition as exc:
        raise HTTPException(status_code=409, detail=str(exc))
    except application_service.ApplicationServiceError:
        raise HTTPException(status_code=404, detail="Application not found")
    await session.commit()
    return Response(status_code=204, headers={"HX-Trigger": "applicationRetried"})
```

### D.3 Test plan

- `test_retry_failed_clears_last_failure` — fixture DRAFT with
  `last_failure` populated, call retry, verify `submission_artifacts`
  no longer contains `last_failure`.
- `test_retry_failed_requeues_when_auto_apply_enabled` — Job in SAVED
  + auto_apply_enabled=True → Job flips to QUEUED_FOR_AUTO_APPLY.
- `test_retry_failed_no_requeue_when_auto_apply_disabled` —
  auto_apply_enabled=False → Job stays SAVED.
- `test_retry_failed_rejects_non_draft` — status=APPLIED → 409.
- `test_retry_failed_rejects_no_failure` — DRAFT with empty artifacts
  → 409.
- `test_retry_failed_idor_returns_404` — cross-user attempt → 404.
- `test_retry_failed_emits_app_event` — AppEventKind.AUTO_APPLY_QUEUED
  with `trigger=retry_requested`.
- Playwright manual QA — Tracking → click failed DRAFT → Retry
  button → confirm dialog → Application re-queues + toast.
