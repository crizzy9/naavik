# 66 · 0.3.1 — Tailored resume + cover letter FREE-tier

## A · Goal

Ship the FREE-tier resume + cover letter generation pipeline — voice-grounded constitution preamble (assembled from `Bullet.text` + `Profile.summary_*` + `ProfileAnswer.answer` + new `Settings.ai_writing_voice_samples`) + ATS-friendly Typst variant (`onepage_ats.typ`, PDF/A-1b, single-column, plain `•` bullets, ligature-disabled Helvetica) + recruiter-priority tailored headline + adaptive cover letter format + hiring-manager personalization + ethics pre-flight + page-count retry-drop + parse-fidelity validator + keyword coverage check. One-click endpoint `POST /api/v1/applications/{id}/generate-bundle` produces resume + cover letter + screener-answers in one atomic call with audit trail in new `Application.generation_trace` JSONB column. Six ROADMAP rows (`0.3.1.01–06`). Cost: ~$0.06-0.12/app at Sonnet 4.6 with Anthropic prompt caching. Premium Claude-mythos layer (`0.3.4`) is out of scope here — independently shippable.

## B · Why

`ROADMAP § 0.3.1` (lines 373–389) is the application-side consumer of the 0.3.0 scoring substrate that landed 2026-05-21 via PR #166. `JobScore.suggested_bullets`, `JobScore.matched_tags`, `JobScore.strengths`, and `JobScore.gaps` are all populated and waiting for the generation pipeline to consume. The Discover · review-and-apply screen (`SCREENS.md § 8`) is mocked + has component partials; the action bar "Submit application" button currently has no backing endpoint.

Existing `document_generator.py` (979 LOC, BACKEND § K.4) ships the structural skeleton — `generate_resume` + `generate_cover_letter` + `answer_screeners` + `pre_generate` + cost cap + reuse heuristic + page-count retry-drop — but the LLM prompts are minimal placeholders. Voice grounding, AI-tell suppression, recruiter-priority headline, keyword coverage, ATS parse fidelity, ethics pre-flight, hiring-manager personalization, audit trail — none of these exist yet.

The synthesized research memo (`docs/design/research/0.3.1-resume-generation-sota.md`, 1500 lines) locked 10 strategic OQs pre-dispatch. ROADMAP § 0.3.1 captures the locks verbatim. This plan converts those locks into a file-by-file implementation contract and graduates the FREE-tier content into a new canonical `docs/design/RESUME_GENERATION.md` (the PREMIUM `0.3.4` plan will extend the same doc with Stage 9 mythos layer).

**Why now:** 0.3.0 just shipped (cost-cap-aware scoring substrate). User can now ask "score this job" and get back `JobScore` w/ suggested bullets. The natural next user action is "ok now tailor the resume" — and that flow currently dead-ends. 0.4.0 auto-apply gates on `Job.score >= threshold` AND requires a generated bundle; without 0.3.1, the auto-apply queue stays empty by construction.

## C · Tactical decisions locked by this plan

All 10 ROADMAP OQs locked; the 16 tactical decisions below cover engineering choices ROADMAP did not address. Plan recommends one in each case; engineer follows without re-deciding.

### T1 — Voice grounding corpus sources

**Decision: composite corpus assembled per-call from 5 sources.** `services/voice_grounding.py:assemble_corpus(user_id, session) -> VoiceCorpus`:

1. **`Bullet.text` rows** (full set; not just `JobScore.suggested_bullets`; ~50-100 × ~200 chars).
2. **`Profile.summary_full` + `Profile.summary_short`**.
3. **`ProfileAnswer.answer` rows** (shipped 0.2.7.14; user's prior screener answers; ~20-100 × ~300 chars; STRONG voice signal).
4. **`Settings.ai_writing_voice_samples`** (new field, T12 + OQ-9; 0-5000 chars; supplemental).
5. **Past `GeneratedDocument.bullet_selection.trimmed_lines`** (when present; reinforces voice from prior generations).

Total corpus ~25-50K tokens. Returns `VoiceCorpus{full_text: str, vocab_fingerprint: list[str], sentence_length_stats: dict, idiomatic_phrases: list[str]}`. Stats computed with stdlib only (no `textstat` dep this PR; folded into 0.3.3 if needed).

**Why per-call vs cached:** corpus invalidation on every `Bullet.edited_at` write is expensive bookkeeping. Per-call assembly via DB queries is fast (~50ms) and always fresh. Anthropic prompt caching (T2) makes the LLM token cost identical to a cached path because the cache breakpoint sits on the system message after the corpus is injected.

### T2 — Anthropic prompt caching breakpoint placement

**Decision: 2 breakpoints — one on constitution+corpus prefix, one on per-stage user message.** Per [Anthropic prompt caching docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), the cache key references the entire prompt prefix (tools → system → messages) up to and including the `cache_control` marker. Place breakpoint on the system message containing the constitution preamble (T3) + voice corpus (T1) — this prefix is identical across all stages within one bundle generation, hitting the 5-minute TTL cache window (~12 calls per bundle complete within ~10s). Second breakpoint on the per-stage instruction block (less stable, but cached across retries within a stage).

**Cost math (Sonnet 4.6, $3 in / $15 out, $0.30 cache_read, $3.75 cache_write):**
- Stage 1 cache write: ~25K input tokens × $3.75/MTok = $0.094.
- Stages 2-12 cache reads: 11 × (25K × $0.30/MTok) = $0.082.
- Output: ~3K tokens × $15/MTok = $0.045.
- **Total ~$0.22 per bundle.** Worst case (no cache hit, fresh each call): ~$0.90. Best case (cold cache for stage 1 only): ~$0.12.

**Cache invalidation:** the breakpoint suffix includes a `voice_fingerprint_hash` (T11 audit trail) — when `Bullet`/`Profile`/`Settings.ai_writing_voice_samples` mutate, the corpus changes, the hash changes, and Anthropic auto-invalidates that prefix. Mechanically free for the implementer.

**Anthropic SDK:** `cache_control={"type": "ephemeral"}` on the relevant content block. `src/llm/anthropic.py:AnthropicProvider` needs a small extension to accept a `cache_breakpoints: list[int]` kwarg passed through from `tracked_call`. Engineer scopes — touch is ~30 LOC.

### T3 — Constitution preamble shape

**Decision: structured Python template; rendered into system-message string; cached via T2.** New `src/services/constitution.py:render_preamble(corpus: VoiceCorpus, profile: Profile) -> str`. Output shape:

```
You are tailoring a resume for {profile.full_name}.

THEIR VOICE — Match this exactly when generating any output:
- Sentence-length distribution: short ~{short_pct}% / medium ~{med_pct}% / long ~{long_pct}%
- Idiomatic phrases they use: {top_10_idiomatic}
- Distinctive vocabulary: {top_30_vocab_fingerprint}

THEIR EXPERIENCE (corpus follows; everything below is the candidate's own writing):
{voice_corpus.full_text}

HONESTY CONSTRAINTS:
- NEVER claim experience not grounded in the corpus above.
- NEVER inflate titles or fabricate credentials.
- Every bullet you emit must trace to a corpus bullet — if you cannot, drop the bullet.

STYLE CONSTRAINTS:
- Avoid AI-tell vocabulary (full list below; see FORBIDDEN section).
- Vary sentence length; aim for variance across all output bullets.
- Prefer specific verbs over generic ("shipped", "led", "designed" > "leveraged", "navigated").
- Prefer concrete numbers over qualitative claims.

FORBIDDEN VOCABULARY (case-insensitive substring match):
{full_blocklist}  # see T4

TASK:
{stage_user_message}
```

The structured shape lets us extract `voice_fingerprint_hash` (T11) by hashing `voice_corpus.full_text + blocklist_version`. Cached system message.

### T4 — AI-tell vocabulary blocklist

**Decision: 30 baked-in entries + `Settings.ai_writing_voice_samples`-derived dynamic additions (when present).** Curated baked-in list (`src/services/ai_tell_blocklist.py:BAKED_IN_BLOCKLIST`):

```
em-dash (—), delve, delving, leverage, leveraging, leveraged, robust, robustly,
moreover, furthermore, in conclusion, underscore, underscores, harness, harnessing,
navigate (as verb), pivotal, paramount, intricate, nuanced, multifaceted, holistic,
synergy, synergistic, deeply, comprehensive, extensive, substantial, significantly,
particularly, ultimately, tapestry, landscape (as in "evolving landscape of"),
dive deep into, it's important to note, in today's fast-paced
```

**Two-layer enforcement:**
1. **Prompt-level** — full list rendered into constitution preamble (T3) under FORBIDDEN.
2. **Post-process strip** — `services/ai_tell_blocklist.py:strip_violations(text, blocklist) -> tuple[str, list[str]]` does regex sweep on LLM output; if any blocked token found, returns `(scrubbed_text, list_of_violations)`. Engineer wraps trim/headline/cover-letter outputs; violations recorded to audit trail; if violations exceed 3 in a bundle, one re-prompt is attempted with explicit "you used <words>; rewrite without them."

**Em-dash handling:** regex replaces ` — ` with `, ` (or `. ` mid-sentence; heuristic per regex group). Em-dash is the single most-common AI tell per the research memo § T1-B sources.

**Dynamic additions:** if `Settings.ai_writing_voice_samples` is set, scan it for `delve`, `leverage`, etc. — if the user uses these words naturally, REMOVE them from the blocklist for this user. Implemented as `effective_blocklist(user_voice_corpus) -> set[str]`.

### T5 — Burstiness target

**Decision: validate-and-regenerate worst offender, not per-bullet rewrite.** Per research § T1-C: AI writing has uniformly-sized sentences; human writing has burstiness (high variance). Post-generation step in `services/burstiness_check.py:check_and_score(bullets: list[str]) -> BurstinessReport`:

1. Compute sentence-length stats across all output bullets (mean, variance, std-dev).
2. If `std_dev >= 6` (heuristic from research § T1-C): PASS.
3. If `std_dev < 6`: identify the bullet closest to the mean (the "most-uniform offender"). Re-prompt LLM with: "Rewrite this single bullet with markedly different sentence structure than the others. Aim for {short|long} ({N} words). Other bullets to preserve variance from: {list}".
4. Cap at 1 retry per bundle (cost discipline). Record `burstiness_std` to audit trail.

**Why not multi-retry:** the research memo § T1-C says "VARY sentence length; don't write three medium sentences in a row" — but for a 12-bullet resume where each bullet is one line, the per-bullet variance is already small. The cross-bullet variance is the actionable metric. One regenerate of the worst offender is the marginal-cost-vs-marginal-benefit sweet spot.

### T6 — ATS-friendly Typst template

**Decision: new `src/typst/templates/onepage_ats.typ` parallel to existing `onepage.typ`.** Existing template stays (T15 backward-compat — keeps the "human-recruiter / non-ATS" variant; per OQ-8 lock, 2-template choice). New template:

- `#set page(paper: "us-letter", margin: 0.3in)` — same as `onepage.typ`.
- `#set text(font: ("Helvetica", "Arial", "Liberation Sans"), size: 10pt, features: ("liga": 0,))` — **ligatures-disabled** (T6.1: prevents `fi`/`fl`/`ff` PUA Unicode that Taleo can't recover per research § B.1).
- **Strict single column** — no `#grid`, no `#box` with side-by-side content. Headers + dates rendered as separate lines, not in a 2-col grid. (`onepage.typ` uses `#grid(columns: (1fr, auto), ...)` for role-line; rewrite as inline text with right-aligned dates via `#h(1fr) #text(...)`.)
- **Plain `•` bullets** (U+2022) — same as existing `bullet_line` macro. Confirm no `★ ➤ ▸ ✓ ◆` glyphs anywhere.
- **MM/YYYY date format** — `_format_date` in `document_generator.py` already uses `%b %Y` → "Jan 2024". Confirm pass-through.
- **No header/footer with content** — `#set page` defaults to no header/footer; contact info stays in body top.
- **PDF/A-1b output** — Typst `--pdf-standard a-1b` flag (per [Typst PDF docs](https://typst.app/docs/reference/pdf/)). `src/typst/compiler.py:compile_typst` needs a small extension to accept a `pdf_standard: str | None = None` kwarg threaded through to the `typst compile` subprocess. ~10 LOC.
- **Section headings** — exact strings: "Professional Experience" / "Education" / "Skills" / "Projects" / "Summary" — per research § B.4 cross-ATS allowlist. `onepage.typ` currently uses "Experience" — change to "Professional Experience" in the new template only; old template unchanged.
- **Headline below name** — render `TailoredHeadline.headline_one_line` (T7) as a 9pt line under the 14pt name, before the contact line.

**Template selection logic** (T15): `services/document_generator.py:_select_template(application, settings) -> str` returns `"onepage_ats"` when `application.board` is in the ATS-known set (`{WORKDAY, GREENHOUSE, LEVER, ASHBY, ICIMS, TALEO, SAP_SUCCESSFACTORS, BAMBOOHR, JAZZHR, LINKEDIN}`) and `"onepage"` otherwise (manual / company-direct / portfolio_sync). Per OQ-8 auto-select-by-board lock.

### T7 — Recruiter-priority headline

**Decision: new `tailor_headline.py` prompt + `services/recruiter_optimization.py:tailor_headline` service function.** Per research § D.3.

**Pydantic schema** (`src/llm/prompts/tailor_headline.py`):

```python
class TailoredHeadline(BaseModel):
    title: str = Field(max_length=40)              # JD-matched title where ethical
    years: int = Field(ge=0, le=50)                # extracted from Profile.experiences spans
    specialty: str = Field(max_length=40)          # 1-2 specialty phrases JD-aligned
    sponsorship_signal: str | None = Field(default=None, max_length=40)
    # e.g. "Open to ML/AI roles, H1B+i-140 transfer" — only when work_authorization is constrained
    headline_one_line: str = Field(max_length=100)  # rendered output; ≤100 chars; ` · ` separated
    keywords_emphasized: list[str] = Field(default_factory=list, max_length=8)
```

**Generation gated on:** `JobScore.score >= 0.50` per research § D.3 (don't tailor headline for jobs the candidate won't apply to). Below threshold, fall back to `Profile.headline` static value.

**Prompt input:** `Profile.headline` + `Profile.summary_full` + years-of-experience aggregate + `Job.role` + `Job.role_family` + `Job.description[:1500]` + `Profile.work_authorization` + `JobScore.matched_tags`.

**Validators:** `headline_one_line` must equal `f"{title} · {years} yrs · {specialty}" + (f" · {sponsorship_signal}" if sponsorship_signal else "")`; total ≤100 chars; each ` · ` chunk ≤30 chars.

**Surface:** rendered in `onepage_ats.typ` as 9pt line under the 14pt name. New audit trail key `bullet_selection.headline_used`.

### T8 — Keyword coverage validator

**Decision: top-30% must contain each JD must-have keyword ≥1×; score 0-1; threshold 0.75 (JobScan parity).** New `src/services/keyword_coverage.py:compute_coverage(jd_must_haves, resume_text, top_pct=0.30) -> CoverageReport`.

```python
@dataclass(slots=True)
class CoverageReport:
    score: float                          # fraction of must-haves found in top 30%
    found_keywords: list[str]
    missing_keywords: list[str]
    top_section_text: str                 # the top-30% text scanned, for debugging
```

**JD must-haves source:** `JobScore.matched_tags` ∪ `Job.skills_required[:5]` (top 5; the rest are nice-to-haves). Falls back to LLM extraction (one cached call per Job) if `matched_tags` is empty.

**Resume text source:** the assembled resume's `experiences[].bullets` flat-list + headline + summary. Top 30% by line count (heuristic — by-character is too sensitive to bullet length).

**Coverage threshold:** 0.75 passes silently; 0.50-0.75 surfaces a warning chip ("Resume covers N/M JD keywords"); <0.50 attempts one re-selection cycle with explicit "include bullets containing missing keywords: <list>" instruction. Cap at 1 retry per bundle.

**Audit trail:** `bullet_selection.keyword_coverage_score`, `bullet_selection.keyword_coverage_missing`.

### T9 — ATS parse-fidelity validator

**Decision: pdfplumber heuristic, 8-field round-trip score; smart-default tiers per OQ-7.** New `src/services/ats_parser_fidelity.py:validate_parse_fidelity(pdf_path: Path) -> ParseScoreReport`.

```python
@dataclass(slots=True)
class ParseScoreReport:
    score: float                              # 0.0-1.0
    fields_found: dict[str, bool]             # 8 canonical fields
    fields_recovered: dict[str, str]          # extracted values
    notes: list[str]                          # heuristic flags
```

**8 canonical fields:**
1. `name` (top of page, bold, 14pt) — extracted via pdfplumber → look at first line.
2. `email` — regex `[\w.+-]+@[\w-]+\.[\w.-]+` in top 5 lines.
3. `phone` — regex with common formats.
4. `first_experience_company` — under "Professional Experience" header.
5. `first_experience_title` — same role.
6. `first_experience_start_date` — MM YYYY pattern adjacent to first experience.
7. `education_institution` — under "Education" header.
8. `skills_section_present` — "Skills" header found.

**Score = fields_found_count / 8.**

**Smart-default tiers per OQ-7:**
- `>0.90`: ship silently; record to audit trail.
- `0.75-0.90`: ship + emit discreet info-toast via HTMX header response (`HX-Trigger: parse-fidelity-warning`).
- `<0.75`: trigger one retry cycle — fall back to a more-conservative variant (e.g., shorter bullets, fewer projects, plainer skills section). If still <0.75 after retry, surface to user via the bundle response (chip on Discover · review & apply: "Parse fidelity X% — some ATS may miss content").

**Dependencies:** `pdfplumber>=0.11.0` — already a transitive dep via Crawl4AI per CLAUDE.md (`pdfminer.six`). Verify by `uv run python -c "import pdfplumber"`; if absent, add to base deps as ~50 KB lightweight import.

**Test corpus:** new `tests/data/ats_corpus/` with 5 sample resumes (engineer creates from seed profile variants) + expected-field-extraction maps as JSON. Regression test: each known-good resume passes ≥7/8; each known-bad (column layout, fancy bullets) fails ≥2 fields.

### T10 — Adaptive cover letter format (OQ-5)

**Decision: new `src/llm/prompts/draft_cover_letter_sota.py` w/ Claude-picks-format dispatch.** Old `draft_cover_letter.py` retained for backward compat (T15) — `prompts/__init__.py:18` re-exports.

### T11 — Hiring manager extractor

**Decision: regex-first + LLM-fallback + UI manual-override.** New `src/services/hiring_manager_extractor.py:extract_hiring_manager(job_description: str, llm_provider, *, session, user_id) -> HiringManagerHit | None`.

**Regex first** (cheap; no LLM cost):

```python
PATTERNS = [
    r"Reporting to\s+([A-Z][a-z]+(?:\s+[A-Z][a-z]+){1,3})",         # "Reporting to Jane Smith"
    r"Manager:\s+([A-Z][a-z]+(?:\s+[A-Z][a-z]+){1,3})",
    r"You'?ll report to\s+([A-Z][a-z]+(?:\s+[A-Z][a-z]+){1,3})",
    r"Contact:\s+([A-Z][a-z]+(?:\s+[A-Z][a-z]+){1,3})",
    r"Hiring Manager:\s+([A-Z][a-z]+(?:\s+[A-Z][a-z]+){1,3})",
]
```

If regex hits, return `HiringManagerHit{name, title=None, source="regex", confidence=0.9}`.

**LLM fallback** (only when regex misses AND `len(job_description) >= 200`): one LLM call w/ structured schema `{name: str | None, title: str | None}`. Returns `source="llm"`, `confidence=0.5-0.8`.

**Manual override:** UI text field on Discover · review & apply ("Hiring manager name (optional)") POSTs to bundle endpoint kwarg `hiring_manager_override`. Source = `"manual"`, confidence = `1.0`.

**Output applied in cover letter:** when `name` is present + confidence >= 0.5 → "Dear {first_name},". Else → "Dear {Job.company} Hiring Team,".

**Audit trail:** `Application.generation_trace.hiring_manager` = `{name, title, source, confidence}`.

### T13 — Cost-cap mid-generation fallback (OQ-10)

**Decision: graceful skip + warning banner + degraded-mode marker in audit trail.** Per OQ-10 lock + existing `CostCapExceededError` in `document_generator.py`.

**Mid-generation behavior** in the new orchestrator (`services/bundle_generator.py:generate_bundle`):

1. **Pre-flight probe** before stage 1: `is_cost_capped(session, user_id, settings)`. If true, return `BundleResult(skipped_reason="cost_cap_reached")` immediately (no LLM spend).
2. **Mid-flight probe** between each stage: same probe. If true mid-flight:
   - Complete current stage best-effort (if mid-LLM-call, await it; don't kill).
   - Skip remaining stages (set `degraded_mode=True`).
   - Mark each skipped stage in `generation_trace.stages_skipped: list[str]`.
   - Surface degraded-mode warning to user via response payload `degraded: true` + `degraded_reason: "cost_cap_reached"`.
   - Discover · review & apply renders amber banner: "LLM budget exhausted mid-generation; some stages were skipped. Documents may be lower quality — regenerate after midnight when budget resets, or raise the cap in Settings · LLM."
3. **Audit trail:** every bundle's `generation_trace.degraded_mode: bool` + `generation_trace.cost_cap_at_exhaustion: float | null` (the cap value when exhausted) + `generation_trace.stages_skipped: list[str]`.

**Aligns with 0.3.0 silent-fallback pattern** (orchestrator skips layer 4 + persists `judge_skipped=true` + Settings · LLM banner). Same shape, applied per-stage instead of per-layer.

### D.8 — Risk + mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Anthropic prompt-cache TTL (5 min) expires mid-bundle on a slow run | MEDIUM | Cost balloons 2-5× | Bundle executes ~12 LLM calls sequentially in <10s typical; user-perceptible latency budget is ≥10s so we'd see a slow-bundle bug long before cache expiry. Audit-trail captures cache hit rate (via Anthropic response headers); 0.3.3 row filed if observed. |
| `pdfplumber` not installed or imports break | LOW | Parse-fidelity validator no-ops | `pdfplumber` is a transitive dep via Crawl4AI; if absent, add to base deps (~50 KB). Graceful import check at module-load; if missing, validator returns `score=1.0` w/ note "validator unavailable" and audit trail records `parse_fidelity_skipped=true`. |
| Typst `--pdf-standard a-1b` flag unsupported on the Nix-pinned typst version | MEDIUM | PDF/A-1b output silently fails | Test in CI before merge: `typst compile --pdf-standard a-1b` smoke test. If flag absent, fall back to plain PDF + record `pdf_standard="default"` to audit trail + log warning. Typst 0.13+ supports the flag (verified via context7 / Typst docs). |
| LLM hallucinates `source_bullet_id` not in Profile | MEDIUM | Ethics pre-flight rejects valid bundle | Ethics check matches by exact integer ID; if LLM emits made-up IDs, drop those bullets quietly (audit trail records). Cap at 2 retries before surfacing red-flag to user. |
| AI-tell blocklist false-positive on user-natural vocabulary | MEDIUM | User sees their own words stripped | T4 dynamic blocklist subtracts user-naturally-used terms detected in `Settings.ai_writing_voice_samples`. Audit trail records dynamic removals. |
| Tailored headline rendered ≥100 chars after concatenation | LOW | Two-line headline breaks single-line layout | Validator clamps at 100 chars in Pydantic; if exceeded, truncate w/ `…` + log; tests assert. |
| `Application.generation_trace` JSONB grows large (every regenerate appends?) | LOW | Row size bloat | OVERWRITE on regenerate (not append). Single bundle generation = single trace. Audit history is the GeneratedDocument rows (one per resume/letter), not the trace. |
| Bundle endpoint races with auto-apply cron's existing `pre_generate` path | MEDIUM | Duplicate work / overlapping LLM calls | Bundle endpoint takes the same `DocsState` lock-by-flip-to-GENERATING that `generate_resume` already does; auto-apply cron's `pre_generate` reuses if state is READY (existing reuse heuristic in `can_reuse_existing_resume`). Compatible. |
| Cost-cap mid-flight skip leaves partial state on disk | MEDIUM | Stale PDFs from prior stages | Mid-flight skip only kicks in AFTER current stage completes (per T13).
