# Plan 87 — 0.4.5.03 conftest autouse → opt-in marker invert

## Goal

Invert the `tests/conftest.py:_patch_services_to_sample_data` fixture from `autouse=True` (opt-out via `_SERVICE_DIRECT_TEST_MODULES` allow-list) to opt-in via `@pytest.mark.uses_sample_data_shims` decorator. The autouse default + per-module allow-list pattern is fragile (new service-direct tests forget to register themselves and get silently double-patched); flipping the default to opt-in is the canonical pytest convention.

Cap concession: plan 75 row 14's escape hatch tripped here — file count exceeds 50-file/100-LOC cap (162 test files − 24 already-allow-listed = ~138 file marker annotations). Plan 87 carries the volume on its own PR so reviewer load stays focused on the mechanical pattern. No design decisions; no PLAN_GATE pause; reviewer scope is "every annotation matches the inverted-default contract."

## Scope (locked)

### W1 — Invert the fixture in `tests/conftest.py`

- Path: `tests/conftest.py:115-` (the `_patch_services_to_sample_data` fixture).
- Edit: change `@pytest.fixture(autouse=True)` → `@pytest.fixture` (manual opt-in). Replace the `_SERVICE_DIRECT_TEST_MODULES` skip-logic with: fixture body activates ONLY when the test (or its module / class) is marked with `pytest.mark.uses_sample_data_shims`. Mechanism: marker check via `request.node.iter_markers("uses_sample_data_shims")`.
- DELETE the `_SERVICE_DIRECT_TEST_MODULES` frozenset (no longer needed; opt-in default is the inverse).
- Register the marker in `pytest.ini` or `pyproject.toml` `[tool.pytest.ini_options].markers` so pytest doesn't warn about unknown markers.

### W2 — Annotate the ~138 sample-data-shim-relying test files

The 162-file test corpus splits into:
- 24 files already in `_SERVICE_DIRECT_TEST_MODULES` (service-direct, don't need the shim) — these get NOTHING added (opt-in default is "no shim").
- ~138 files that currently rely on the autouse shim implicitly (their tests assume sample_data is patched in).

For each of those ~138 files, add a module-level marker:

```python
import pytest
pytestmark = pytest.mark.uses_sample_data_shims
```

placed immediately after the existing top-of-file imports.

**Audit pass first:** before applying en masse, run a quick check on a sample of ~10 files chosen across categories (UI tests, service tests, integration tests) to confirm marker placement is consistent. Then apply mechanically.

### W3 — Test the inversion

- Add new test `tests/test_conftest_opt_in_marker_works.py` (~20 LOC):
  - Test 1: unmarked test gets no `application_service.get_application` monkey-patching.
  - Test 2: marked test gets the shim and `application_service.get_application` returns the sample_data shadow row.
- Run full `uv run pytest -x` — every pre-existing test still passes (no regressions because every file relying on the shim gets the marker).
- Run a deliberate negative test: temporarily comment out the marker on ONE shim-relying test file → that file's tests fail with the expected `AttributeError` / "service not patched" failure mode → restore the marker.

## Risk + mitigation

| # | Risk | Mitigation |
|---|---|---|
| R1 | Some files DON'T need the shim, but the autouse default has been silently activating it (false positives). The blanket `pytestmark = uses_sample_data_shims` annotates them anyway → unnecessary overhead per test. | Acceptable — overhead is negligible (monkey-patch dict ops); cost of audit-per-file is higher than cost of redundant marker. Future refactor can prune markers from files that truly don't need the shim. |
| R2 | A file the engineer thought relies on the shim actually doesn't, vice versa. | Step 4-5 catches both: missing-marker → fails at step 5 batch; spurious-marker → still passes (no-op overhead). Step 7 audit pass can detect spurious markers by removing one at a time and observing PASS / FAIL flip. |
| R3 | The marker pattern catches "module-level applied" but pytest's marker semantics for class-level + function-level tests can drift. | Use `pytestmark` at module level (most predictable; covers all tests in the file). Avoid finer-grained markers unless a specific file mixes shim-relying + shim-not-relying tests. |
| R4 | The `_SERVICE_DIRECT_TEST_MODULES` set has historical drift — some entries may be stale (test deleted but constant entry stuck). | Audit each entry against `glob tests/test_*.py`; delete stale entries before W1 lands. |
| R5 | Reviewer scope: ~138 file diffs is a lot. PR review-time tractability is the concern this plan exists to address by sizing itself. | Trade: focused diff (one-line addition per file) + dedicated PR. Reviewer scans for "every file got the same one-line marker block in the same location." Architect mechanical scan acceptable. |
