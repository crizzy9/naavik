# 23 · PC.6a — Broader `require_password_complete` gate

## Goal

Extend the `require_password_complete` dependency (already authored in plan 18 at `src/services/auth.py:273`) from the 6 routes PC.6 wired (5 in `src/api/applications.py:33,65,84,127,155` + 1 in `src/ui/routes/settings.py:417`) to the ~29 mutation routes in `src/api/profile.py` + `src/api/settings.py` + `src/ui/routes/*.py` that PC.6's deviations explicitly flagged as out-of-scope. Goal: a flagged user (server-generated dev password, `User.must_change_password=True`) gets 303 → `/auth/change-password` from EVERY state-changing surface, not just the 6 PR #50 covered. Ships zero new dependencies, zero new env vars; ~29 route signatures changed, ~3 new tests verifying the gate fires per route group.

## Why

PR #50 hacker Finding 1 (HIGH; deferred per `docs/plans/archive/18-pc6-password-complexity.md` § Deviations row 1): the find-replace that plan 18 spec'd against ~25 routes only landed on 5 — the rest of the mutation surface (`src/api/profile.py`, `src/api/settings.py`, every `src/ui/routes/*.py`) was still on the plan-09 fake-session stub (`ui/auth_stub.is_authenticated`, cookie `naavik_session=fake-1`) with **NO FastAPI auth dep at all**. PC.6's intent — "flagged users cannot mutate state until they rotate their server-generated password" — is delivered for `api/applications/*` only. A flagged user can today PUT `/api/v1/profile/full_name`, PUT `/api/v1/settings/llm`, POST `/api/v1/discover/{id}/save`, POST `/api/v1/applications/manual`, POST `/api/v1/outreach/send`, etc. — all without redirecting to `/auth/change-password`. PC.6a closes that gap before 2.12 (vault sunset) touches `src/api/settings.py` and before any real-auth migration ships, because the gate is small (~29 line-level changes) and self-contained.

## Proposal

### A · Substrate decision (LOAD-BEARING)

Naive find-replace of `Depends(get_current_user)` → `Depends(require_password_complete)` won't work: most target routes have no auth dep at all. They authenticate via the plan-09 fake-session stub (cookie `naavik_session=fake-1` checked by `src/ui/auth_stub.is_authenticated`, used inline or implicitly by accepting any request). Adding `Depends(require_password_complete)` to a fake-session route requires a real JWT cookie — which dev sessions, 15 test files, and `tests/visual/capture.py` don't carry. Naive landing → 401 on every gated route for everyone.

This is the central engineering question of PC.6a. Three options:

#### Option matrix

| Option | Capability | Cost | Risk | Maintenance | Lock-in |
|---|---|---|---|---|---|
| **A. Defer PC.6a until real auth migrates off the fake-session stub** | Cleanest separation — the gate gets added once the substrate is real | 0 LOC now; but the issue stays open + flagged users keep their mutation surface | LOW (no behavior change) but defers the documented HIGH hacker finding indefinitely | None now; couples to a future "auth substrate migration" plan that doesn't exist | Defers the work into a bigger blob |
| **B. New parallel `require_authed_session` dep that resolves real-JWT-first, fake-session-fallback, then applies the must-change-password redirect** | Ships now; honors both substrates atomically; retires cleanly when 2.12 + real-auth migration land (one symbol to delete) | ~25 LOC new dep + ~29 route signature edits + 3 tests | LOW — clearly scoped wrapper; brief explicitly forbids modifying `require_password_complete` so a parallel dep is the only legal path | Single deletion site post-real-auth migration | None — the wrapper IS the migration path |
| C. Modify `require_password_complete` to fall back to fake-session when JWT absent | Single dep symbol; no parallel wrapper | Forbidden by the PC.6a brief ("Modifying `require_password_complete` itself") | — | — | — |

**Recommendation: B.** A is the path PR #50 already deferred to; punting again ships zero defense for the documented HIGH finding. C is forbidden by the brief. B is the narrow, reversible path: a new `require_authed_session` (or similar; bikeshed in Q3) lives next to `require_password_complete` in `src/services/auth.py`, consumes both substrates, applies the must-change-password check exactly once, and gets deleted in one diff when the fake-session stub retires (2.12 cleanup or follow-up). Trade-off accepted: two auth deps for the duration of the substrate transition; the wrapper documents the transition explicitly in its docstring.

#### B in detail — the wrapper

New helper in `src/services/auth.py`, placed directly after `require_password_complete` (current line 295):

```python
async def require_authed_session(
    request: Request,
    session: AsyncSession = Depends(get_session),
    naavik_session: str | None = Cookie(default=None, alias=SESSION_COOKIE),
) -> User | None:
    """Plan 23 (PC.6a, 2026-05-18): transitional auth dep that gates state-
    changing UI + API routes whose substrate is the plan-09 fake-session
    cookie (not real JWT) until a real-auth migration ships.

    Resolution order:
      1. If `naavik_session` parses as a valid JWT (real auth, post-PC.6)
         → look up the user; apply `require_password_complete` semantics
         (303 + HX-Redirect to `/auth/change-password` when flagged).
      2. If `naavik_session == FAKE_SESSION_VALUE` ("fake-1", plan-09 dev /
         test stub) → return None. No user resolution; gate passes.
      3. If cookie is missing or otherwise invalid → 401 (matches
         `get_current_user`).

    Retires when the fake-session stub is deleted (post-2.12 or a follow-
    up real-auth migration). Search-replace target at that time:
    `Depends(require_authed_session)` → `Depends(require_password_complete)`.

    Routes that USE this dep accept `_user: User | None` because the
    fake-session path returns None; the handler body keeps reading
    `sample_data` accessors the same way it does today. Real-auth callers
    (post-migration) will tighten the annotation in the same change that
    deletes this wrapper.
    """
    if not naavik_session:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Not authenticated",
        )

    # Fake-session path — plan-09 stub. Skip user resolution; gate passes.
    # Documented sunset: deleted when fake_session_stub goes away.
    from ui.auth_stub import FAKE_SESSION_VALUE as _FAKE
    if naavik_session == _FAKE:
        return None

    # Real-auth path — resolve user + apply must-change-password check.
    user_id = verify_jwt(naavik_session)
    if user_id is None:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Session expired",
        )
    user = await get_user_by_id(session, user_id)
    if user is None or not user.is_active:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Account disabled",
        )
    if user.must_change_password:
        raise HTTPException(
            status_code=status.HTTP_303_SEE_OTHER,
            detail="Password change required.",
            headers={
                "HX-Redirect": "/auth/change-password",
                "Location": "/auth/change-password",
            },
        )
    return user
```

This is a **superset** of `require_password_complete` for the substrate transition. It does NOT modify `require_password_complete` itself (which stays at line 273 unchanged); it does NOT modify the fake-session stub semantics; it does NOT modify `get_current_user`. It is one new symbol, ~30 LOC, two-call-sites away from being deleted (the route signatures + the wrapper definition).
