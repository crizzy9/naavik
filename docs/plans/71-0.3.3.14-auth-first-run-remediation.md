# 71 · 0.3.3.14 · Auth flow + 401 remediation (first-run UX)

## Goal

Diagnose + remediate the auth-flow gap reported by owner ("we have no auth flow" + "401 errors when saving"). Most likely root cause: operator running `uv run fastapi dev` from outside `nix run .#dev` doesn't pick up `NAAVIK_DEBUG=1` env var (exported only by `flake.nix:devEnv`), so the `~/.naavik/dev-credentials` artifact (plan 10c) never gets written. Operator hits Login page with no signup option (because a seeded User exists → `signup_disabled=True`) and no displayed credentials. Plan delivers: a verification suite + RUNBOOK § first-run-auth section + a fresh-start diagnostic surface that detects + surfaces the broken-first-run state. Independent of plan 69 (data flow); parallel-shippable.

## Why

Owner local QA reports (verbatim):
- **"Login doesn't work — no auth flow"** — bug 5
- **"401 errors when saving"** — bug 7

Auth-flow audit:
- `/login` exists + renders correctly (`src/ui/routes/auth.py:72-97`) — signup form gated by `_compute_signup_disabled` (User table count > 0 AND `allow_multiple_users=False`)
- `/api/v1/auth/signup` exists + bcrypt + JWT cookie set (`src/api/auth.py:158-270`)
- `/api/v1/auth/login` exists + bcrypt verify + JWT cookie set (`src/api/auth.py:106-146`)
- `services.auth.require_authed_session` enforces 401 on missing/invalid JWT cookie (`src/services/auth.py:522-604`)
- `~/.naavik/dev-credentials` artifact written by `main.py` lifespan ONLY when triple-gate: `NAAVIK_DEBUG=1` AND `NAAVIK_DEV_PASSWORD` unset AND `Settings.deployment_mode == SELF_HOSTED` (plan 10c)

**Hypothesized failure flow (operator running `uv run fastapi dev` outside Nix):**

1. Operator clones repo, runs `uv sync`, runs `uv run fastapi dev src/main.py`
2. App boots, lifespan seeds DB (existing seed.py creates 1 User + Profile + Settings + sample Jobs/Contacts/etc.)
3. `NAAVIK_DEBUG` env var NOT set (only `flake.nix:devEnv` exports it)
4. → triple-gate fails: dev-credentials artifact NOT written
5. Operator opens browser → `/login` displays
6. `_compute_signup_disabled` returns `True` (1 User exists + `allow_multiple_users=False`)
7. → Signup form replaced by amber "This instance already has an account" banner
8. Operator has NO WAY to log in (doesn't know seeded password) + NO WAY to sign up
9. Operator tries any save (e.g. modify profile in `/profile/edit`) → HTMX `hx-put` triggers `Depends(require_authed_session)` → no JWT cookie → 401

That's the regression. Plan 10c was designed for the `nix run .#dev` operator. The `uv run fastapi dev` operator slipped through.

Secondary diagnosis: even when in `nix run .#dev`, the dev-credentials artifact has mode 0600 + sits at `~/.naavik/dev-credentials` (per plan 10c). Operators may not realize it exists. README mentions it but RUNBOOK doesn't have an entry.

## Proposal

### Option matrix (Q2 from master plan 68)

What surface should we add to surface the broken-first-run state?

| Option | UX | Backend change | Pros | Cons |
| --- | --- | --- | --- | --- |
| **A. README + RUNBOOK update only** | Operator must read docs to recover | None | Zero LOC; honest about the limitation | Onboarding-tax; many operators skip docs |
| **B. Fresh-start diagnostic page** | When `_compute_signup_disabled` is True AND no JWT cookie AND no dev-credentials artifact present, render a one-screen `/setup-help` page w/ recovery steps (set NAAVIK_DEBUG=1 + restart; OR run `nix run .#dev`; OR manually seed user via `uv run python -c "..."`) | New route + template | Surfaces problem at point-of-failure | New surface to maintain |
| **C. Auto-onboarding redirect** | When no User exists, always redirect `GET /` → `/onboarding`. When 1 User exists but no auth → `/login` w/ signup form forced visible OR w/ a `?force-signup=1` query param | Modify `_compute_signup_disabled` to honor `?force-signup=1` | Closest to a "just works" UX | Doesn't help when User EXISTS but operator doesn't know creds (the actual reported bug) |
| **D. Detect missing dev-credentials + warn in lifespan** | At lifespan end, if `NAAVIK_DEBUG=1` AND no dev-credentials file written, log a warning. If `NAAVIK_DEBUG` is unset AND no User exists, print a startup banner suggesting `NAAVIK_DEBUG=1` to enable first-run credential write | Tweak `main.py` lifespan + add startup banner | Earliest possible surface (boot-time) | Subtle — operator may not see logs |

**Architect recommendation: Option A + Option B + Option D combined.** A is mandatory (docs are wrong without it). B is high-leverage (the `/setup-help` page catches the broken state). D is cheap insurance (boot-time warning).

### File-by-file edits (recommended combo: A + B + D)

1. **`docs/RUNBOOK.md`** — NEW § "First-run authentication failure modes" before the existing "UI shows mock data" entry. Document 3 scenarios:
   - **Scenario 1 — `nix run .#dev` operator**: `cat ~/.naavik/dev-credentials` for credentials
   - **Scenario 2 — `uv run fastapi dev` operator**: set `NAAVIK_DEBUG=1` env var + restart OR seed user manually
   - **Scenario 3 — 401 on save**: re-login at `/login` to refresh JWT cookie
2. **`README.md` § Operations** — add "First-run authentication" sub-section. Document the triple-gate that enables `~/.naavik/dev-credentials`. Mention `/setup-help` (from Option B). Mention `nix run .#dev` exports `NAAVIK_DEBUG` automatically.
3. **`src/ui/routes/auth.py`** — NEW route `GET /setup-help` (Option B). Page renders when:
   - No JWT cookie OR fake-session cookie
   - `signup_disabled` is True (User exists)
   - No `~/.naavik/dev-credentials` file (probe via `Path(app_settings.data_dir) / "dev-credentials" .exists()`)

   Page body shows:
   - Diagnostic state (which conditions are met)
   - Recovery options (set NAAVIK_DEBUG + restart; OR `nix run .#dev`; OR manually unseed via SQL; OR enable multi-user signup via Settings)
   - Link to RUNBOOK section

   No auth required for this route — it's a recovery surface.

4. **`src/ui/templates/pages/setup_help.html`** — NEW template extends `components/auth_shell.html` (same shell as login). Renders the diagnostic table + recovery steps.
5. **`src/ui/routes/auth.py:get_login`** — modify to detect Scenario 1/2 (no JWT + signup_disabled + no dev-credentials file) and prepend a small banner above the form: "Need help getting in? See [Setup help](/setup-help)." Optional cross-link.
6. **`src/main.py` lifespan** (Option D) — after seed runs, if `app_settings.debug` is False AND User count > 0 AND `Settings.deployment_mode == SELF_HOSTED`, log a single WARN line: `"NAAVIK_DEBUG is unset; ~/.naavik/dev-credentials not written. Set NAAVIK_DEBUG=1 to enable first-run credential surfacing, or see RUNBOOK § First-run authentication."` If `NAAVIK_DEBUG=1` and `~/.naavik/dev-credentials` NOT written (e.g. `NAAVIK_DEV_PASSWORD` was set), log an INFO line referencing the env var override.
7. **`src/services/auth.py:require_authed_session`** — improve the 401 response body for HTMX consumers. Currently raises `HTTPException(401)` which HTMX renders as a generic toast. Modify to set `HX-Redirect: /login` header when 401 fires on `/api/v1/*` POST/PUT/DELETE from a session-less HTMX request (no cookie at all). This way, a save attempt without auth redirects to login instead of silent toast. Keep the 401 status code; just add the header.
8. **`tests/test_first_run_walkthrough.py`** — NEW. End-to-end test:
   - Boot fresh test DB (no User)
   - GET `/` → redirect to `/login` (or `/onboarding` if Option C also enabled — verify against owner pick)
   - GET `/login` → signup form visible (no User exists yet)
   - POST `/api/v1/auth/signup` → User created + JWT cookie set
   - GET `/` → 200 (Overview)
   - POST `/api/v1/profile/*` (a save action) → 204 (no 401)
   - DELETE JWT cookie → POST same save → 401 with HX-Redirect: /login header
   - With seeded User + no NAAVIK_DEBUG: GET `/setup-help` → 200 + recovery page
9. **`tests/test_setup_help_route.py`** — NEW. 3 tests:
   - Auth-less GET `/setup-help` → 200
   - Page contains "RUNBOOK" + "NAAVIK_DEBUG" + "Set NAAVIK_DEBUG=1" recovery steps
   - Page contains diagnostic table reflecting actual state

### Risk + mitigation

| Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- |
| `_compute_signup_disabled` modifications break the signup_disabled banner that plan 10c shipped | LOW | MEDIUM | Plan keeps original gate logic intact; only adds the optional `/setup-help` link below. Banner remains primary surface for "signup disabled" state. |
| `/setup-help` could leak info about whether a User exists / data_dir state (mild fingerprinting) | LOW | LOW | Page is intentionally public + diagnostic — info-disclosure is the feature, not a bug. No secrets shown (just env-var names + file paths). |
| `HX-Redirect: /login` change to `require_authed_session` 401 affects non-HTMX consumers (curl, API SDKs) | LOW | LOW | Header is HTMX-specific; non-HTMX consumers still get 401 + JSON detail body. HTMX itself only acts on `HX-Redirect` header. |
| `~/.naavik/dev-credentials` probe might race with main.py lifespan write | LOW | LOW | Probe is read-only `Path.exists()`; idempotent. Lifespan write is atomic mkstemp + chmod 0600. |
| Lifespan WARN log noise on every restart in self-hosted production | LOW | LOW | WARN gated on `app_settings.debug` False AND `Settings.deployment_mode == SELF_HOSTED` AND User count > 0; in cloud mode, never fires. Only first-time self-host operators see it. |
| Tests assume in-memory DB has no User; rely on `test_session` fixture pattern | MEDIUM | LOW | Pattern established by `tests/test_pages.py` (plan 49 dev #2). |
| Plan 71's `setup-help` route conflicts with plan 69's route rewire (potential merge conflict) | LOW | LOW | Plans land on independent branches; merge conflict resolves trivially (both add to `src/ui/routes/auth.py`). |
