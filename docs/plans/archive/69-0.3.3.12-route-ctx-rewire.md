# 69 · 0.3.3.12 · Route + ctx-builder rewire to service layer

## Goal

Migrate 13 files (8 route handlers + 5 ctx-builders) off the `_KNOWN_LEGACY_OFFENDERS` allowlist in `tests/test_no_sample_data_imports_in_routes.py` — they currently call `from db import sample_data as sd` and read/write in-memory module-level lists. Replace every `sd.*` call with the equivalent `services.*` call (all service-layer fns shipped in plan 60 commit 1 are already in tree). After this PR the allowlist is empty + the regression-lint enforces "no sample_data imports outside db/seed.py + db/sample_data*.py + tests/". This is the missing commit 2 of plan 60 (which was descoped to follow-up + moved to `0.8.0.38` + now promoted back to `0.3.3.12` as HIGH priority per master plan 68).

## Why

Owner local QA reports (verbatim):

1. **Discover page is broken** — `/discover` calls `dctx.build_discover_ctx` which reads via `sd.discover_queue()`, `sd.saved_jobs()`, `sd.auto_apply_queue()`, `sd.stuck_drafts()` — all in-memory now (post-plan-60). DB-backed scrapers may write Jobs that never appear in these accessors.
2. **Profile page is broken** — `_build_profile_ctx` calls `sd.get_profile()`, `sd.get_experiences()`, `sd.get_bullets_for_experience()`, etc. — all in-memory.
3. **Save doesn't persist** — `post_save`, `post_skip`, `post_auto_submit` call `sd._set_job_queue_state()` which appends to `JOB_QUEUE_STATES` (in-memory dict). Restart wipes. Likewise `_create_draft`, `_append_outreach_message`, `_append_manual_application`, `_append_scraped_job`.
4. **Stub data still reaching the UI** — owner directive: "get rid of all the stubbed data we had and move over fully to the db." This plan closes that directive completely for the route surface.
5. **Overview pipeline-live broken** — `get_overview` calls `sd.kpi_*`, `sd.priority_actions`, `sd.email_signal_feed`, `sd.pipeline_strip_counts` — all in-memory. The new `overview_service.compute_kpis` + `compose_priority_actions` + `pipeline_strip_counts` + `email_service.recent_signals` are sitting unused.

Root cause is documented in master plan 68's `## Why this slipped` § Root cause 1 — plan 60 commit 2 was descoped per dispatch-budget concerns + the follow-up went to Backlog/0.8.0.38. The descope was correct given the budget at the time; what wasn't correct was failing to promote the follow-up back when 0.3.0/0.3.1/0.3.4 work raised stakes (multiple UI surfaces NOW depend on DB-backed data for scoring + bundle generation to work).

### Build sequence — 3 commits on `feat/0.3.3.12-route-ctx-rewire`

**Commit 1 — Route handlers + ctx-builders (the bulk of the work)**

Engineer rewires each of 13 files. Pattern per file:

```python
# Before
from db import sample_data as sd
async def get_foo(...):
    profile = await sd.get_profile()

# After  
from db.session import get_session
from sqlmodel.ext.asyncio.session import AsyncSession
from services import profile_service
async def get_foo(
    request: Request,
    session: AsyncSession = Depends(get_session),
    user: User | None = Depends(require_authed_session),
):
    user_id = _effective_user_id(user)  # existing helper per ui/routes/jobs.py pattern
    profile = await profile_service.get_profile(session, user_id)
```
