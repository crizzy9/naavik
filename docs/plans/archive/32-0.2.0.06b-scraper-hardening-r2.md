### D.1 — `stream_many` per-URL `HttpUrl` validation

**Hacker finding F1 (LOW residual, was MEDIUM at round 1).** Plan 31 D.1 added `pydantic.HttpUrl` + `TypeAdapter` validation to `Crawl4AIClient.fetch_html(url)` only. `Crawl4AIClient.stream_many(urls: list[str])` at `src/scraper/crawl4ai_client.py:104-134` passes the list verbatim to `crawler.arun_many(urls=urls, ...)`. A scraper subclass that composes listing URLs from `ScrapeQuery.company_filter` (or any future user-controlled field) re-opens the same `file://` / `gopher://` / `javascript:` surface plan 31 closed on the single-URL path.

**Locked fix.** Validate per-URL at the top of `stream_many`; skip-with-log on rejection; pass only the validated list to `crawler.arun_many`. Reuse the existing module-level `_HTTP_URL_ADAPTER` — do NOT create a new adapter.

```python
# src/scraper/crawl4ai_client.py — stream_many head (after the docstring)
async def stream_many(
    self,
    urls: list[str],
) -> AsyncIterator[tuple[str, str | None]]:
    """... (existing docstring + new line:)

    URLs validate through `pydantic.HttpUrl` (same gate as `fetch_html`);
    rejected URLs log + skip without yielding. Per plan 32 D.1.
    """
    validated: list[str] = []
    for raw in urls:
        try:
            validated.append(str(_HTTP_URL_ADAPTER.validate_python(raw)))
        except ValidationError as exc:
            log.warning(
                "crawl4ai stream-many rejected: url=%s reason=%s",
                safe_url(raw),
                safe_exc(exc),
            )
    if not validated:
        return
    streaming_config = self._run_config.clone(stream=True)
    dispatcher = MemoryAdaptiveDispatcher(...)  # unchanged
    async with AsyncWebCrawler(config=self._browser_config) as crawler:
        async for result in await crawler.arun_many(
            urls=validated,  # was: urls=urls
            ...
        ):
            ...
```

**Trade-off accepted.** Mixed valid+invalid input lists yield only the valid subset; caller sees fewer `(url, html|None)` tuples than URLs passed in. This is the desired behavior — skip + log is safer than partial-yield with a sentinel "rejected" tuple. Engineer note: place validation BEFORE `streaming_config = self._run_config.clone(...)` so we don't pay the clone cost on an empty-after-validation input.

### D.2 — `safe_msg` helper + 2 callsite swaps

**Hacker finding F2 (LOW).** `crawl4ai_client.py:99` (`fetch_html` failure branch) and `crawl4ai_client.py:131` (`stream_many` failure branch) log `result.error_message` raw:

```python
log.warning("crawl4ai fetch failed: url=%s err=%s", safe_url(url), result.error_message)
```

`result.error_message` is a Crawl4AI-internal string carrying the upstream exception's `__str__` — same secret-leak risk as `safe_exc` was created to gate. Today this lands in app logs only (not `JobScrapeRun.errors[]`), but the same string surfaces verbatim in `0.2.0.11`'s operator UI scrape-run detail panel.

**Locked fix.** New `safe_msg(s: str | None) -> str` in `src/scraper/redaction.py`. Parallels `safe_exc` — 200-char cap; preserves printable content; bound a "<no-msg>" sentinel for None/empty. Wrap both `log.warning` callsites in `crawl4ai_client.py`.

```python
# src/scraper/redaction.py — appended after safe_exc
def safe_msg(msg: str | None) -> str:
    """Truncate a free-form upstream message to 200 chars; strip non-printables.

    Used for Crawl4AI's `result.error_message` and any other untrusted
    upstream string that lands in `log.warning` or `JobScrapeRun.errors[]`.
    Parallels `safe_exc` shape — same 200-char cap, same C0/DEL/ANSI strip.
    """
    if not msg:
        return "<no-msg>"
    return _strip_control_chars(msg)[:_MAX_EXC_MSG_LEN]
```

`_strip_control_chars` is the helper extracted in D.3 so `safe_exc` and `safe_msg` share the same sanitization. Callsite swaps:

```python
# src/scraper/crawl4ai_client.py:97-100 (fetch_html branch)
log.warning(
    "crawl4ai fetch failed: url=%s err=%s",
    safe_url(url),
    safe_msg(result.error_message),  # was: result.error_message
)

# src/scraper/crawl4ai_client.py:129-133 (stream_many branch)
log.warning(
    "crawl4ai stream-result failed: url=%s err=%s",
    safe_url(result.url),
    safe_msg(result.error_message),  # was: result.error_message
)
```

Import line at `src/scraper/crawl4ai_client.py:29` becomes `from scraper.redaction import safe_exc, safe_msg, safe_url`.

### D.3 — `safe_exc` non-printable strip

**Hacker finding F3 (LOW).** `safe_exc(exc)` at `src/scraper/redaction.py:36-43` slices the message to 200 chars but passes ANSI escape sequences, CRLF, and null bytes through verbatim. Operator logs corrupt cleanly; the operator-UI `<pre>` block in `0.2.0.11` would render the ANSI bytes uninterpreted (cosmetic) but the CRLF + null bytes break log parsers and log-shippers (real).

**Locked fix.** Extract a private `_strip_control_chars(s: str) -> str` helper shared by `safe_exc` and `safe_msg`. Strips C0 control chars (`\x00-\x1f`) AND DEL (`\x7f`) AND ANSI escape sequences (`\x1b[...m` and friends), but PRESERVES `\t` (`\x09`) and `\n` (`\x0a`) for legibility.

```python
# src/scraper/redaction.py — appended near top after _MAX_EXC_MSG_LEN
import re

_ANSI_ESCAPE_RE = re.compile(r"\x1b\[[0-?]*[ -/]*[@-~]")
# C0 controls except \t (0x09) and \n (0x0a); plus DEL (0x7f)
_CONTROL_CHARS_RE = re.compile(r"[\x00-\x08\x0b-\x1f\x7f]")


def _strip_control_chars(s: str) -> str:
    """Drop ANSI escape sequences + C0 controls + DEL; preserve \\t and \\n."""
    return _CONTROL_CHARS_RE.sub("", _ANSI_ESCAPE_RE.sub("", s))


def safe_exc(exc: BaseException) -> str:
    """... (existing docstring; body becomes:)"""
    msg = _strip_control_chars(str(exc))[:_MAX_EXC_MSG_LEN]
    return f"{type(exc).__name__}: {msg}"
```

ANSI strip uses the standard CSI grammar (`\x1b\[[0-?]*[ -/]*[@-~]`) — covers SGR (`\x1b[31m`), cursor moves, mode sets. Preserving `\n` matches engineer expectations for multi-line exception messages (e.g. `pydantic.ValidationError` carries one error per line). DEL strip is paranoia — some Postgres `ARRAY(String)` drivers choke on `\x7f`.

def test_safe_msg_truncates_and_strips_controls():
    raw = "fatal: \x1b[31mERROR\x1b[0m\n  details=" + "x" * 400 + "\x00\x07"
    redacted = safe_msg(raw)
    assert "\x1b" not in redacted
    assert "\x00" not in redacted
    assert "\x07" not in redacted
    assert "\n" in redacted  # preserved for multi-line legibility
    assert len(redacted) <= 200
    assert safe_msg(None) == "<no-msg>"

    assert "ValueError:" in redacted
    assert "\x1b" not in redacted
    assert "\r" not in redacted

## Forward refs (NOT in this plan; surface for `0.2.0.07` plan author)

Two watch items hacker flagged for the `0.2.0.07` per-source scrapers plan — listed here so the architect authoring that plan reads them off this file:

1. **Reject URLs with non-empty `userinfo`.** `https://user:pass@host/path` parses as a valid `HttpUrl` today. Per-source scrapers that compose URLs from `ScrapeQuery.company_filter` should reject any URL where `urlsplit(url).username or urlsplit(url).password` is truthy — an attacker who controls the filter can inject basic-auth credentials that leak to the target host.

2. **Destination-IP RFC1918 / IMDS / link-local denylist.** `HttpUrl` validates scheme + format but does NOT block `http://127.0.0.1`, `http://169.254.169.254` (AWS IMDS), `http://10.0.0.0/8` / `192.168.0.0/16` / `172.16.0.0/12` (RFC1918). Before any user-controlled value composes a URL in `0.2.0.07`, resolve the destination IP and reject the four classes above. Implementation lives in the URL-composer layer of each subclass (or a shared helper in `src/scraper/url_guard.py`).

Neither is in scope for `0.2.0.06b`. They're URL-composer-layer concerns that don't exist until `0.2.0.07` ships a real composer.
