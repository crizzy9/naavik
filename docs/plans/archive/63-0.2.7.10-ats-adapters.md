# 63 · 0.2.7.10 — ATS adapters: Workday / LinkedIn / Indeed / Generic (design + scaffold)

## A · Goal

Author the contract layer for Playwright-driven ATS adapters (Workday / LinkedIn / Indeed / Generic) and ship the per-adapter infrastructure (shared browser-context pool, ATSCredential metadata UI surface, postmortem `screenshot_path` wiring, structured Pydantic schemas, registry stub) so that each individual adapter — when actually built — slots in as a single self-contained file implementing the existing `ATSAdapter` ABC at `src/services/ats/base.py:60`. **This plan does NOT ship any of the 4 production adapters.** Each adapter is a separate follow-up row (Workday → `0.4.0.NN`; LinkedIn / Indeed / Generic → `0.8.0.NN`) with its own plan, prompt, and dispatch budget — that's where the real ATS credentials, manual-review queues, anti-detection tuning, and weeks of iteration belong. The graduated design doc is `docs/design/ATS_ADAPTERS.md`.

## B · Why now

ROADMAP row `0.2.7.10` (line 323) has been outstanding since 2026-05-01 triage. Three concrete forcing functions, listed in escalation order:

1. **`PostmortemTrace.screenshot_path` (`src/services/ats_postmortem.py:88`) has been a reserved-field placeholder for one month** (plan 52 / `0.2.3.02` shipped 2026-05-20). The field exists; no adapter populates it; reviewers reading `analysis.md` see a comment "0.2.3.01 placeholder" pointing at a row that has since been renamed to 0.2.7.10. Either delete the field or wire it up; deletion loses the postmortem contract for Playwright adapters that will eventually ship.
2. **`_ManualFallbackAdapter` (`src/services/ats/__init__.py:45`) returns `auth_required` for 5 of 8 boards** (Workday / LinkedIn / Indeed / COMPANY_DIRECT / MANUAL). That's the silent UX dead-end on the auto-apply path: high-score job at Workday gets queued, every cron tick returns `auth_required`, job pulled out of queue (`process_auto_apply_queue:702`), operator sees "stuck" without any actionable indication of "this board needs Playwright; you can't unlock it yet, ETA 0.4.0+". The dispatcher tells the truth ("requires Phase 1.x adapter"), but the UI surface above it doesn't.
3. **The auto-apply path is partially-completed by design**, but operators evaluating Naavik for self-host see "auto-apply works on Greenhouse/Lever/Ashby and silently fails on Workday/LinkedIn/Indeed/Generic" — and they have no way to know which boards their company-list-of-interest skews to until they hit the fail. A "configured boards" indicator + an explicit "Workday/LinkedIn/Indeed adapters in Phase 4+" disclosure is the minimum honesty surface.

These three forcing functions are solved by the **scaffolding + design doc**, not by shipping production adapters. The production-adapter work is genuinely weeks of work per board (credential acquisition + Playwright stability + anti-detection tuning + LinkedIn-ban-risk testing) — work the user explicitly directed to defer at 0.2.7 triage when this row was filed as multi-week. This plan locks the design contract today so that whenever Phase 4 starts, the per-adapter PR can be ~400 LOC of board-specific Playwright instead of ~2000 LOC of board-specific Playwright + new substrate + new schema + new doc.

### C.3 `_browser_pool.py` design — shared Playwright context pool

The scaffolding module owns the substrate that every follow-up Playwright adapter consumes. It mirrors the `Crawl4AIClient` (`src/scraper/crawl4ai_client.py`) pattern but is tuned for ATS-submission semantics (auth-bearing context, 1-shot-per-submission lifetime) instead of scrape semantics (anonymous, streaming, batched).

```python
# src/services/ats/_browser_pool.py — sketch
import asyncio
import logging
from contextlib import asynccontextmanager
from pathlib import Path
from playwright.async_api import BrowserContext, async_playwright, Browser

log = logging.getLogger(__name__)

class ATSBrowserPool:
    """Shared Playwright Browser instance + per-submission BrowserContext pool.

    One Browser per process; one BrowserContext per `submit()` call (acquired
    via `acquire()` context manager). Hard cap on concurrent contexts via
    `asyncio.Semaphore` — Workday/LinkedIn each spawn full Chromium tabs so
    RAM is the bottleneck. Default `max_concurrent_contexts=4` (Phase 4 tunes
    per cloud-tier instance size; ROADMAP follow-up `0.4.0.NN` lands the
    Settings.ats_browser_concurrency knob).

    Lifecycle:
    - `start()` boots a Browser (browser type = chromium; default; per-adapter
      override via constructor arg) once per process via FastAPI lifespan.
    - `acquire(board)` returns a fresh BrowserContext with the board-specific
      user-agent (rotated from `scraper.user_agents.pick_user_agent`),
      viewport (1440x900 default), and credential-injection hook (cookie
      injection from env via `_inject_session_cookies`).
    - `stop()` closes Browser + Playwright on shutdown.

    Tests: zero-state context isolation via async fixture; Semaphore-cap test
    asserts a 5th concurrent acquire blocks until a previous releases.
    """

    def __init__(
        self,
        *,
        max_concurrent_contexts: int = 4,
        headless: bool = True,
        browser_type: str = "chromium",
    ) -> None:
        self._sem = asyncio.Semaphore(max_concurrent_contexts)
        self._headless = headless
        self._browser_type = browser_type
        self._playwright = None
        self._browser: Browser | None = None
        self._started = False

    async def start(self) -> None:
        if self._started:
            return
        self._playwright = await async_playwright().start()
        launch_fn = getattr(self._playwright, self._browser_type).launch
        self._browser = await launch_fn(headless=self._headless)
        self._started = True
        log.info("ATSBrowserPool started: %s headless=%s", self._browser_type, self._headless)

    async def stop(self) -> None:
        if self._browser is not None:
            await self._browser.close()
            self._browser = None
        if self._playwright is not None:
            await self._playwright.stop()
            self._playwright = None
        self._started = False

    @asynccontextmanager
    async def acquire(self, *, board: str, user_agent: str | None = None):
        if not self._started:
            await self.start()
        async with self._sem:
            ua = user_agent or pick_user_agent()
            context: BrowserContext = await self._browser.new_context(
                user_agent=ua,
                viewport={"width": 1440, "height": 900},
            )
            try:
                await self._inject_session_cookies(context, board)
                yield context
            finally:
                await context.close()

    async def _inject_session_cookies(self, context: BrowserContext, board: str) -> None:
        """Pull board-specific session cookie from env via env_secrets;
        inject as context cookie. No-op when env slot is unset (adapter
        will hit auth-required path and return predictable failure)."""
        # Implementation lives in each adapter's skeleton; pool only owns
        # the dispatch shape. Tests for the dispatcher live in
        # tests/test_ats_browser_pool.py.
        ...


# FastAPI lifespan integration (existing main.py pattern):
#
#   @asynccontextmanager
#   async def lifespan(app):
#       app.state.ats_browser_pool = ATSBrowserPool()
#       # Don't start eagerly — only boot Chromium when first adapter call
#       # arrives. start() is idempotent + handled by acquire().
#       yield
#       await app.state.ats_browser_pool.stop()
```

**Why one shared pool + per-submission context (not per-adapter pools).** Two reasons:

1. **Browser instance reuse cuts cold-start latency.** Each new Chromium boot is ~800ms; persisting one Browser across submissions amortizes that to zero. A 5-min auto-apply cron firing 10 submissions saves ~8s.
2. **State isolation lives at the BrowserContext layer, not the Browser layer.** Each `acquire()` call gets a fresh context (= fresh cookies, fresh storage, fresh fingerprint). Two consecutive Workday submissions for two different users don't bleed state because the context is destroyed on `release`.

**Anti-pattern explicitly rejected:** per-Page Browser ("spawn fresh chromium per submit"). RAM cost is 4-5x and the Browser launch latency overwhelms a 5-min cron cadence.

### C.4 `_playwright_base.py` design — mixin for the 4 adapters' shared state

```python
# src/services/ats/_playwright_base.py — sketch
from abc import abstractmethod
from typing import Any
from playwright.async_api import BrowserContext, Page

from .base import (
    ApplicationBundle, ATSAdapter, FAILURE_AUTH_REQUIRED, FAILURE_CAPTCHA,
    FAILURE_FIELD_MISMATCH, FAILURE_UNKNOWN, SubmissionResult,
)
from ._browser_pool import ATSBrowserPool


class _PlaywrightATSAdapter(ATSAdapter):
    """Shared mixin for Playwright-backed adapters.

    Subclasses implement `_submit_with_context(page, application, bundle) ->
    SubmissionResult` and override `board_name`. The mixin owns:

    - Browser-pool acquire + per-submission user-agent
    - Top-level try/except → screenshot_b64 capture into SubmissionResult.raw
    - Failure-mode classification (catches `playwright.async_api.TimeoutError`
      → FAILURE_UNKNOWN; CAPTCHA-detection helper inspects DOM for hcaptcha /
      reCAPTCHA iframe → FAILURE_CAPTCHA)
    - State-machine checkpoint persist (writes `submission_artifacts.<board>_checkpoint`
      JSONB sub-key on each `_advance_step` call — Workday's 5-7 pages resume
      gracefully on transient failure within the same session)
    """

    requires_browser_pool: bool = True
    board_name: str = "abstract"

    def __init__(self, *, browser_pool: ATSBrowserPool | None = None) -> None:
        self._pool = browser_pool  # injected by `dispatch()` factory; None
                                   # in unit tests stays None → can_submit→False

    def requires_credential(self) -> bool:
        return True

    async def submit(self, application, bundle: ApplicationBundle) -> SubmissionResult:
        if self._pool is None:
            return SubmissionResult(
                ok=False,
                error=FAILURE_AUTH_REQUIRED,
                error_message=f"{self.board_name} adapter has no browser pool wired",
            )
        async with self._pool.acquire(board=self.board_name) as context:
            page = await context.new_page()
            try:
                return await self._submit_with_context(page, application, bundle)
            except Exception as exc:  # noqa: BLE001 — diagnostic capture
                screenshot_b64 = await self._safe_screenshot(page)
                return SubmissionResult(
                    ok=False,
                    error=FAILURE_UNKNOWN,
                    error_message=f"{self.board_name} adapter raised: {exc!r}",
                    raw={
                        "request_url": page.url,
                        "response_status": None,
                        "response_body": "<playwright-runtime-exception>",
                        "screenshot_b64": screenshot_b64,
                        "exception_type": type(exc).__name__,
                    },
                )

    @abstractmethod
    async def _submit_with_context(
        self, page: Page, application, bundle: ApplicationBundle
    ) -> SubmissionResult: ...

    async def _safe_screenshot(self, page: Page) -> str | None:
        """Best-effort base64 PNG. None on failure (page already closed, etc.)."""
        try:
            png = await page.screenshot(full_page=True, type="png")
            import base64
            return base64.b64encode(png).decode("ascii")
        except Exception:  # noqa: BLE001
            return None

    async def _checkpoint(
        self, application, step_name: str, state: dict[str, Any]
    ) -> None:
        """Persist mid-submission checkpoint. Workday: page-id + form-state
        snapshot for resume on transient failure within same context."""
        # Implementation lands in 0.4.0.NN — scaffolding stub here.
        ...
```

Two things deliberately reserved for the per-adapter PR: (a) `_submit_with_context` body (each adapter's page sequence — Workday is 5-7 pages, Easy Apply is 1-3); (b) board-specific CAPTCHA-detection selectors (hcaptcha vs reCAPTCHA vs Cloudflare Turnstile per board).

### C.5 `screenshot_path` wiring (postmortem extension)

`src/services/ats_postmortem.py:_build_trace` already accepts `raw` and reads `raw["text"]` / `raw["response_status"]` / `raw["response_body"]`. The screenshot extension:

```python
# Inside _build_trace, after existing body extraction:
screenshot_b64 = raw.get("screenshot_b64")
screenshot_path: str | None = None
if screenshot_b64 is not None:
    try:
        png_bytes = base64.b64decode(screenshot_b64)
        screenshot_path = _atomic_write_screenshot(
            application_id=application.id, ts=ts, png_bytes=png_bytes
        )
    except Exception as exc:  # noqa: BLE001 — diagnostic; never block
        log.warning("postmortem screenshot write failed: %s", exc)
        screenshot_path = None

return PostmortemTrace(
    ...
    screenshot_path=screenshot_path,  # was always-None placeholder

```

New helper `_atomic_write_screenshot(application_id, ts, png_bytes)` writes to `<data_dir>/data/postmortems/<app_id>/<ts>/screenshot.png` via `tempfile.NamedTemporaryFile(dir=parent, delete=False)` + `os.replace`. Returns relative path `postmortems/<app_id>/<ts>/screenshot.png` — same convention as the existing `trace.json` + `analysis.md` artifacts.

PNG is **NOT** redacted at the postmortem layer — that's the adapter's responsibility (Workday SSN fields should be navigated past, not screenshotted). The adapter can elect not to populate `raw["screenshot_b64"]` if the failure is on a sensitive page; the contract is "best-effort visual context, never raw PII." Documented in ATS_ADAPTERS.md § E.

Path-traversal guard already in place at the GET retrieval route (`src/api/applications.py`); strict regex on `ts` + `Path.resolve()` + `relative_to(data_root)` containment. Screenshot serving inherits the same guard — extending the existing `GET /api/v1/applications/{id}/postmortem/{ts}` envelope to include `screenshot_url` (a relative API URL `/api/v1/applications/{id}/postmortem/{ts}/screenshot.png`) is the per-adapter PR's job, not this scaffold. This plan only writes the file; the retrieval surface arrives with the first real adapter.

### D.2 — Browser strategy

### D.5 — Manual review queue (auto-approve threshold)

### D.7 — Generic adapter scope (unknown boards)
