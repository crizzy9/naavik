# 29 · `0.2.0.06` — Crawl4AI setup + generic scraper base

## Goal

Land the **scraper substrate** that all six site scrapers (`0.2.0.07`: LinkedIn / Workday / Greenhouse / Lever / Ashby / Indeed) will inherit from. Three artifacts:

1. `crawl4ai==0.8.6` added to `pyproject.toml` (the post-2026-03-24 security-hotfix release; replaces the long-stale "Replace Browserless" reference in ROADMAP row `0.2.0.06`).

3. `src/services/scraper_service.py` — `run_scraper(scraper)` orchestrates one scraper invocation: opens a `JobScrapeRun` row at `RUNNING`, iterates `scraper.scrape() → AsyncIterator[RawJob]`, calls `job_service.upsert_job(...)` per yield, tracks counters, finalizes the run at `SUCCESS / PARTIAL / FAILED / TIMED_OUT`.

The plan is `Type: design`. On approval the proposal content graduates into the canonical `docs/design/SCRAPER_BASE.md` — the single doc the `0.2.0.07`-era site scrapers, `0.2.0.10` scheduler, and `0.2.0.13` rate-limit work all read from. ### D.1 — `ScraperBase` interface shape

Three options for the abstract surface every site scraper inherits.

**Option matrix.**

| Option | A — `abc.ABC` abstract base class (recommended) | B — `typing.Protocol` (structural) | C — Dataclass config + free-function scrapers |
| --- | --- | --- | --- |
| Capability | Explicit `@abstractmethod` enforcement; inheritance hierarchy; `isinstance()` checks work; matches existing `src/llm/base.py` LLM provider pattern. | Looser coupling; duck-typed; works with mocks-without-inheritance; harder to enforce subclass contract at construction time. | Functional style; each scraper is `async def scrape_linkedin(config: LinkedInConfig) → AsyncIterator[RawJob]`; no class hierarchy; no shared state. |
| Cost | ~80 LOC `base.py` (abstract class + ConfigSchema + helper methods). | ~50 LOC `base.py` (Protocol class + runtime_checkable decorator). | ~30 LOC `base.py` (no base; just dataclass `ScraperConfig`); each site is a function. |
| Risk — drift between scrapers | LOW — abstract methods force contract; mypy + ruff catch missing impls. | MEDIUM — duck typing accepts partial impls; subtle bugs at runtime. | HIGH — no shared structure; each site free-styles error handling / rate limits / retry. |
| Risk — over-engineering | LOW — pattern matches `src/llm/base.py:LLMProvider` (already merged + tested w/ 3 impls). | LOW — Protocol is lightweight. | LOW — least code. |
| Maintenance | Adding a new site = subclass + impl `scrape()`. ~50 LOC per site. | Same as A in practice (impls still need full methods); harder code review. | Per-site: define dataclass + free-function. Each site stands alone; no inheritance scaffolding to maintain. |
| Lock-in | Sticky — once 6 scrapers inherit, replacing the ABC is mechanical refactor (search-replace). | Same. | Lowest — free functions are most flexible. |
| Test surface | `tests/test_scraper_base.py` validates ABC + tests SampleScraper subclass against contract. | Same pattern with Protocol. | `tests/test_sample_scraper.py` only — no shared base to test. |
| Matches existing convention | ✅ — `src/llm/base.py:LLMProvider(ABC)` is the merged pattern (`src/llm/anthropic.py`, `src/llm/openai.py`, `src/llm/ollama.py` all inherit). | ⚠ — diverges from LLM layer's ABC pattern. | ❌ — diverges; also no shared instance state for things like `requests_made` counter. |

**Recommendation: Option A — `abc.ABC` abstract base class.**

Justification across three axes:

- **Convention parity.** `src/llm/base.py:LLMProvider(ABC)` is the existing merged pattern. Six scrapers reading the same idiom as the three LLM providers reduces cognitive load for contributors. Diverging here would be novelty for novelty's sake.
- **Drift prevention.** Six site scrapers will inherit. ABC's `@abstractmethod` enforcement catches "I forgot to implement `scrape()`" at module-import time, not at first invocation. Protocol's runtime-checkable variant catches at `isinstance()` but not at construction; free-function approach catches nothing structurally.
- **Shared state.** Per-scraper `requests_made` counter + `errors[]` buffer + `rate_limit_per_minute` config field live naturally as instance attributes on an ABC. Free-function approach forces all of that into a context dict that callers pass — harder ergonomics for both authors and reviewers.

**Trade-off accepted.** ABC adds ~30 LOC vs Protocol; that's the cost of being the same pattern as `LLMProvider`. No real-world cost.

### D.2 — `RawJob` field set (the boundary DTO)

The DTO that flows from scraper → service → `job_service.upsert_job`. Field set must:
- Cover everything `job_service.upsert_job(... raw=raw)` needs to land a `Job` row (the required keys per `JOB_MODEL.md § F.1`: `board`, `url`, `url_type`, `company`, `role`, `description`).
- Preserve enough source-shape data that `0.2.0.08` (AI extraction) can re-extract from `description_html` if structured fields drift.
- Permit `0.2.0.09` dedup to read the `(source, external_id)` tuple without re-fetching.

Two cuts of field shape — minimal vs verbose. **No real option matrix here**; the field set is determined by `JOB_MODEL.md` consumers. Lock the verbose form:

```python
# src/scraper/types.py

from datetime import datetime
from typing import Any
from pydantic import BaseModel, Field, ConfigDict

from models import JobSource, RemotePolicy, VisaRestriction, SeniorityLevel, ApplicationBoard


class RawJob(BaseModel):
    """Scraper-emitted job payload before AI extraction + dedup.

    Lives at the scraper ↔ service boundary. Scraper subclasses populate the
    fields they can fill from source; service layer maps to `Job` via
    `job_service.upsert_job(... raw=raw_job.model_dump(exclude_unset=True))`.

    AI extraction (`0.2.0.08`) takes over for the missing structured fields
    by re-parsing `description_html` and overwriting `RawJob`-supplied
    `remote_policy_hint` / `visa_restriction_hint` / `seniority_level_hint`
    with confident enum values.
    """

    model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)

    # ── Required: dedup keys + Job.upsert_job contract requirements ──────
    source: JobSource                       # which scraper produced this row
    external_id: str = Field(min_length=1)  # per-source stable identifier
    source_url: str = Field(min_length=1)   # canonical URL (used as Job.url)
    board: ApplicationBoard                 # ATS adapter routing (Job.board)
    url_type: str = "external"              # "ats" / "company_direct" / "rss" / "manual" / "external"

    # ── Required: user-visible Job fields the scraper can fill ───────────
    company_name: str = Field(min_length=1)
    position_title: str = Field(min_length=1)

    # ── Optional: structured fields the scraper may know; AI extraction
    #    refines or supplies if missing ──────────────────────────────────
    location_raw: str | None = None          # free-form "Remote / SF Bay / NYC"
    description_html: str | None = None      # raw scraped HTML; required for AI extraction step
    description_text: str | None = None      # stripped text; convenience; AI may re-derive

    # ── Hints — scrapers fill when source data is unambiguous; AI extraction
    #    overwrites if the hint is wrong or absent ──────────────────────
    posted_at_text: str | None = None        # raw "Posted 3 days ago" → `Job.posted_at_text`
    posted_at: datetime | None = None        # parsed datetime if scraper can compute → `Job.posted_at`
    salary_raw: str | None = None            # raw "$160k - $200k" → eventually parsed by AI
    remote_policy_hint: RemotePolicy | None = None
    visa_restriction_hint: VisaRestriction | None = None
    seniority_level_hint: SeniorityLevel | None = None

    # ── Source-specific extras: kept in JSONB for diagnostics + audit ────
    raw_meta: dict[str, Any] = Field(default_factory=dict)
```

**Field-by-field rationale + Job mapping:**

| RawJob field | Required? | Maps to `Job` field | Filled by scraper? | Refined by AI (`0.2.0.08`)? |
|---|---|---|---|---|
| `source` | YES | `Job.source` | YES — scraper subclass sets the class-level `source: JobSource` property | NO |
| `external_id` | YES | `Job.external_id` | YES — per-source stable id (LinkedIn `job_id`; Greenhouse `gh_jid`; Lever `posting_id`) | NO |
| `source_url` | YES | `Job.url` | YES — canonical URL from listing | NO |
| `board` | YES | `Job.board` | YES — scraper subclass sets the class-level `board: ApplicationBoard` property | NO |
| `url_type` | YES (defaults `"external"`) | `Job.url_type` | YES — per-scraper convention | NO |
| `company_name` | YES | `Job.company` | YES — from listing or detail HTML | YES — AI normalizes ("Anthropic, PBC" → "Anthropic") |
| `position_title` | YES | `Job.role` | YES — from listing | YES — AI normalizes ("Sr. SWE - Eng I" → "Senior Software Engineer") |
| `location_raw` | NO | (input to `Job.location`; AI parses) | YES if scraped | YES — AI maps to "City, State" / "Remote" |
| `description_html` | NO (but recommended) | `Job.description_html` | YES — from detail fetch | NO (preserved verbatim for re-extraction) |
| `description_text` | NO | (input to `Job.description`; AI normalizes) | YES if scraper can strip | YES |
| `posted_at_text` | NO | `Job.posted_at_text` | YES — diagnostics | NO (preserved) |
| `posted_at` | NO | `Job.posted_at` | OPTIONAL — only if scraper can parse cleanly | YES — AI normalizes from `posted_at_text` |
| `salary_raw` | NO | (input to `Job.salary_min` + `Job.salary_max`; AI parses) | YES if scraped | YES |
| `remote_policy_hint` | NO | `Job.remote_policy` | OPTIONAL — only when source is unambiguous (e.g. Greenhouse "Remote" tag) | YES — AI extracts from description if absent |
| `visa_restriction_hint` | NO | `Job.visa_restrictions` | OPTIONAL — rarely available pre-extraction | YES — AI infers from description |
| `seniority_level_hint` | NO | `Job.seniority_level` | OPTIONAL — derivable from title regex sometimes | YES — AI extracts from title + description |
| `raw_meta` | NO (defaults `{}`) | `Job.raw_meta` (merge) | YES — scraper-specific extras (e.g. `{"listing_page_url": "...", "rsshub_endpoint": "..."}`) | NO (preserved, merged) |

**Pydantic v2 `extra="forbid"` rationale.** Catches scraper authors who add a field that doesn't map to `Job` — they get a `ValidationError` at construction time. Forces an explicit add to `RawJob` (which forces an explicit `Job` field mapping) instead of silently passing through to `raw_meta`.

**`*_hint` naming.** Plan 27 § D.3 hardened `Job.remote_policy` etc. as typed enums. Scrapers that *think* they know the value (e.g. LinkedIn listing card has `"Remote · Hybrid · On-site"` tag) pass it through `RawJob.remote_policy_hint`; AI extraction overwrites if the JD body says different. The `_hint` suffix signals "advisory, AI may override" without polluting the `Job` field namespace.

### D.3 — `ScraperBase.scrape()` return type

Three options for how a scraper yields jobs.

**Option matrix.**

| Option | A — `AsyncIterator[RawJob]` (recommended) | B — `list[RawJob]` (batch return) | C — `AsyncIterator[ScrapeBatch]` (batched stream) |
| --- | --- | --- | --- |
| Capability | Stream per-job; service-layer consumer writes JobScrapeRun counters incrementally; downstream dedup processes per-job; partial-results survive an exception mid-stream. | Simplest signature; full result set materialized before service layer touches DB. | Stream batches of N jobs; service-layer flushes counters per batch. |
| Memory profile | Best — one RawJob in memory at a time. | Worst — all N jobs in memory simultaneously. For Greenhouse listing of ~150 jobs per company, all 150 in RAM. | Middle — N per batch. |
| Failure mode | Service layer can land partial results: 47 jobs landed, then exception on 48th → `JobScrapeRun.status = PARTIAL` with `listings_returned = 48`, `new_jobs = 47`, `errors = ["stage=detail-fetch url=... kind=timeout msg='...'"]`. | All-or-nothing: a single exception loses everything before it. Caller would have to wrap in try/except and rebuild the partial-list semantic by hand. | Same as A for partial results; coarser counter granularity. |
| Matches Crawl4AI native pattern | ✅ — `crawler.arun_many(..., config=CrawlerRunConfig(stream=True))` returns async generator; `async for result in ...` consumes per-result. Confirmed via `https://docs.crawl4ai.com/advanced/multi-url-crawling/`. | ❌ — fights the Crawl4AI grain; scraper would have to `[r async for r in ...]` to materialize. | ✅ — composable with Crawl4AI's per-batch dispatcher progress. |
| Service-layer ergonomics | `async for raw in scraper.scrape(): await job_service.upsert_job(...)` — clean. | `raws = await scraper.scrape(); for raw in raws: await job_service.upsert_job(...)` — also clean; one extra step. | `async for batch in scraper.scrape(): for raw in batch: await job_service.upsert_job(...)` — nested. |
| Testability | Easy — `[r async for r in scraper.scrape()]` materializes in test. | Easiest — list is list. | Same as A. |
| Scheduler-loop fit (`0.2.0.10`) | Best — APScheduler job emits time-budget-elapsed signals; streaming let scheduler abort mid-stream cleanly via `asyncio.CancelledError`. | Worst — batch must complete before scheduler can react. | Middle. |
| Lock-in if wrong | Refactor to A is mechanical; refactor away from A to B is also mechanical (collect into list). | Same. | Same. |

**Recommendation: Option A — `AsyncIterator[RawJob]`.**

Justification:

- **Matches Crawl4AI's native pattern.** Crawl4AI 0.8.x's `arun_many(..., config=CrawlerRunConfig(stream=True))` returns an async generator that yields one `CrawlResult` per URL completion. Our scraper wraps the streaming generator in our own streaming generator that maps `CrawlResult` → `RawJob`. No materialization in between. Pattern is "thin layer over the tool we're adopting".

- **Partial-results survive failures.** A LinkedIn scraper fetching 200 listings + 200 detail HTMLs that crashes on the 150th detail (Cloudflare 403, network hiccup, parse failure on one weird job posting) leaves 149 RawJobs already-yielded — the service layer has already upserted them. `JobScrapeRun.status = PARTIAL`, `listings_returned = 150`, `errors = [the 150th-job error]`. With Option B, that entire run loses 149 jobs. Per `docs/design/research/LINKEDIN_SCRAPING.md § 6 risk #2` (silent breakage), this graceful-degradation is structural.

- **Scheduler interrupt-friendly.** `0.2.0.10` (APScheduler periodic scraping) will have a per-job time budget. When the budget elapses, the scheduler raises `asyncio.CancelledError` mid-stream. With Option A, the generator's `finally` block fires, the service layer's `record_scrape_run(... status=TIMED_OUT, listings_returned=<partial>)` lands cleanly. With Option B, you can't interrupt mid-batch.

**Trade-off accepted.** Generators are slightly trickier to debug than lists (you can't `print(scraper.scrape())` and see all results). Mitigation: `tests/test_scraper_sample.py` materializes the sample scraper into a list and asserts on the full set. Production scrapers use streaming; tests use list materialization. Both patterns coexist cleanly.

**Concrete signature:**

```python
# src/scraper/base.py

from abc import ABC, abstractmethod
from collections.abc import AsyncIterator
from datetime import datetime, UTC
from pydantic import BaseModel, Field

from models import JobSource, ApplicationBoard
from scraper.types import RawJob


class ScrapeQuery(BaseModel):
    """Inputs to one scraper invocation. Per-scraper subclasses
    interpret as appropriate (LinkedIn: keywords + location;
    Greenhouse: company list; etc.)."""

    keywords: list[str] = Field(default_factory=list)
    location: str | None = None
    company_filter: list[str] | None = None
    max_listings: int = 200  # per-scraper cap; defaults conservative
    raw_meta: dict = Field(default_factory=dict)  # scraper-specific extras


class ScraperBase(ABC):
    """Abstract base for site scrapers.

    Subclasses declare `source` + `board` as class attributes and implement
    `scrape()` as an async generator yielding `RawJob` instances.

    Subclasses MAY override `rate_limit_per_minute` and
    `random_delay_seconds` to be more aggressive or conservative than the
    base defaults; the `0.2.0.13` rate-limiter task will surface these as
    `Settings` fields with per-source defaults.

    Subclasses should NOT override `__init__` unless they have provider-
    specific config; the base accepts an optional `Crawl4AIClient` for
    test injection.
    """

    # ── Class-level: declared by subclass ────────────────────────────
    source: JobSource           # which JobSource enum value this scraper emits
    board: ApplicationBoard     # which ATS adapter the resulting Jobs route to

    # ── Class-level: rate-limit hooks (D.6) ──────────────────────────
    rate_limit_per_minute: int = 30           # conservative default
    random_delay_seconds: tuple[float, float] = (1.0, 3.0)  # min, max

    def __init__(self, client: "Crawl4AIClient | None" = None) -> None:
        from scraper.crawl4ai_client import Crawl4AIClient
        self._client = client or Crawl4AIClient()

    @property
    def name(self) -> str:
        """Human-readable name for logs + JobScrapeRun.raw_meta."""
        return self.__class__.__name__

    @abstractmethod
    async def scrape(self, query: ScrapeQuery) -> AsyncIterator[RawJob]:
        """Yield RawJob instances as they are discovered.

        Subclass contract:
        - MUST yield only valid `RawJob` instances (Pydantic validates at construction).
        - SHOULD honor `query.max_listings` as an upper bound.
        - SHOULD catch per-listing errors, log to a buffer, and continue
          iterating (the service layer aggregates the buffer into
          JobScrapeRun.errors[]).
        - MUST raise on a total scraper failure (auth, network unrecoverable,
          target site down) so the service layer marks the run FAILED.

        Best-effort errors:
        - Per-listing parse failure → skip + log to `self._errors[]`,
          continue.
        - Rate-limit (HTTP 429) → exponential backoff via Crawl4AIClient,
          continue.
        - Total network/auth failure → raise (service layer catches at
          top level, marks JobScrapeRun.status = FAILED).
        """
        # Subclasses use `async def` + `yield`; ABC enforces presence via mypy.
        ...  # pragma: no cover
        if False:
            yield RawJob(...)  # type: ignore[unreachable]
```

The `if False: yield` shim is the canonical pattern for declaring an abstract async generator method in Python — needed so mypy treats the override as `AsyncIterator[RawJob]`, not as a coroutine returning a generator.

### D.4 — Crawl4AI integration shape (`Crawl4AIClient` wrapper)

Three options for how `ScraperBase` consumes Crawl4AI.

**Option matrix.**

| Option | A — Direct import in ScraperBase | B — `Crawl4AIClient` wrapper class (recommended) | C — Hexagonal `IBrowser` protocol |
| --- | --- | --- | --- |
| Capability | `ScraperBase.scrape()` imports `crawl4ai` directly; calls `AsyncWebCrawler` inline. | `Crawl4AIClient` wraps `AsyncWebCrawler` + `BrowserConfig` + `RateLimiter`; scraper subclasses call `await self._client.fetch_html(url)`. | Abstract `IBrowser` protocol; `Crawl4AIBrowser` + `PlaywrightBrowser` + `MockBrowser` implementations; scrapers depend on protocol. |
| Cost | ~0 extra LOC (just `import crawl4ai`). | ~120 LOC `crawl4ai_client.py` (constructor + 3 methods: `fetch_html(url)`, `fetch_many(urls) → AsyncIterator[CrawlResult]`, `close()`). | ~250 LOC (protocol + 2 impls + mock). |
| Testability | Hard — scraper tests must mock `crawl4ai.AsyncWebCrawler` directly; brittle to Crawl4AI internal changes. | Easy — scraper tests inject `Crawl4AIClient(mock=True)` or pass a `FakeClient` subclass. `tests/test_scraper_base.py` doesn't need to patch `crawl4ai` at all. | Easiest — protocol is mockable by trivial subclass; tests never touch real Crawl4AI. |
| Plays-well-with-Crawl4AI-upgrades | ❌ — every Crawl4AI breaking-change (0.8 → 0.9 etc) forces edits in every scraper subclass. | ✅ — Crawl4AI breaks land in `crawl4ai_client.py` only; scrapers unchanged. | ✅ — same as B, plus optional swap to non-Crawl4AI implementation. |
| Future Playwright fallback | Hard — scrapers tightly coupled to Crawl4AI; "+ Add by URL" generic scraper (`scraper/generic.py`, future `0.2.0.07` work per `BACKEND.md § J.2`) would need to import Playwright separately. | OK — second client class `PlaywrightClient` parallel to `Crawl4AIClient`; scraper subclass chooses. | Best — Playwright is just another `IBrowser` impl; same scraper code calls both. |
| Over-engineering risk | Low (least code). | Low. | MEDIUM — building hexagonal architecture before second implementation exists is premature abstraction; YAGNI. |
| Matches existing convention | ⚠ — `src/llm/anthropic.py` imports `anthropic` directly; one could argue scrapers should follow. | ✅ — `src/llm/anthropic.py` wraps the SDK in a class (`AnthropicProvider`); the wrapper is the test injection point. Same pattern. | ⚠ — diverges; no other Naavik subsystem is hexagonal. |

**Recommendation: Option B — `Crawl4AIClient` wrapper class.**

Justification:

- **Test injection point.** Plan 29's test suite (`tests/test_scraper_*.py`) needs to exercise scraper logic without spinning up Chromium. Wrapper class + dependency injection is the merged Naavik pattern (`AnthropicProvider` + `OpenAIProvider` + `OllamaProvider` all wrap their respective SDKs; service-layer tests inject mocks; e.g. `tests/test_llm.py:88` uses `MockProvider`). Same idiom.

- **Single upgrade surface.** Crawl4AI's 0.7 → 0.8 transition included rename of `proxy` → `proxy_config`. Six site scrapers in `0.2.0.07` would each need to patch that rename if they imported Crawl4AI directly. Wrapper class absorbs the breakage.

- **YAGNI on hexagonal.** Option C (Phase 6 polish target) is the right answer eventually, when there's a real second `IBrowser` impl (Playwright generic scraper, or a "headless-disabled" debug mode). Plan 29 doesn't need it. Adding 130 LOC of abstraction for a future feature is the textbook premature-abstraction failure mode.

**Trade-off accepted.** When Playwright fallback lands (target: `0.2.0.07` generic scraper + Phase 6 deep retrofit), we'll either (a) add a sibling `PlaywrightClient` class with the same surface as `Crawl4AIClient` and let scraper subclasses pick at construction, or (b) refactor to Option C. Cost of the refactor: search-replace ~5 method-call sites in six site scrapers. Acceptable cost vs over-building now.

**`Crawl4AIClient` shape:**

```python
# src/scraper/crawl4ai_client.py

import asyncio
import logging
import random
from collections.abc import AsyncIterator

from crawl4ai import AsyncWebCrawler, BrowserConfig, CacheMode, CrawlerRunConfig

log = logging.getLogger(__name__)


class Crawl4AIClient:
    """Testable wrapper around Crawl4AI's AsyncWebCrawler.

    Scrapers depend on this class (not Crawl4AI directly) so Crawl4AI
    upgrades land in one place and tests can inject fakes.

    The wrapper is a thin pass-through; production scrapers should use
    its `fetch_html()` / `stream_many()` methods rather than reaching
    through to the underlying `AsyncWebCrawler`.
    """

    def __init__(
        self,
        *,
        enable_stealth: bool = True,
        headless: bool = True,
        page_timeout_ms: int = 30_000,
        rate_limit_per_minute: int = 30,
        random_delay_seconds: tuple[float, float] = (1.0, 3.0),
    ) -> None:
        self._browser_config = BrowserConfig(
            enable_stealth=enable_stealth,
            headless=headless,
        )
        self._run_config = CrawlerRunConfig(
            cache_mode=CacheMode.BYPASS,
            page_timeout=page_timeout_ms,
        )
        self._rate_limit_per_minute = rate_limit_per_minute
        self._random_delay_seconds = random_delay_seconds
        self._last_request_at: float = 0.0

    async def fetch_html(self, url: str) -> str | None:
        """Fetch one URL, return HTML or None on failure."""
        await self._respect_rate_limit()
        async with AsyncWebCrawler(config=self._browser_config) as crawler:
            result = await crawler.arun(url=url, config=self._run_config)
            if not result.success:
                log.warning("crawl4ai fetch failed: url=%s err=%s", url, result.error_message)
                return None
            return result.html

    async def stream_many(self, urls: list[str]) -> AsyncIterator[tuple[str, str | None]]:
        """Fetch many URLs concurrently; yield (url, html-or-None) per result.

        Uses Crawl4AI's native streaming dispatcher; bounded by
        rate_limit_per_minute via the underlying MemoryAdaptiveDispatcher.
        """
        from crawl4ai import MemoryAdaptiveDispatcher

        streaming_config = self._run_config.model_copy(update={"stream": True})
        dispatcher = MemoryAdaptiveDispatcher(
            memory_threshold_percent=85.0,
            max_session_permit=max(1, self._rate_limit_per_minute // 6),
        )

        async with AsyncWebCrawler(config=self._browser_config) as crawler:
            async for result in await crawler.arun_many(
                urls=urls, config=streaming_config, dispatcher=dispatcher
            ):
                if result.success:
                    yield (result.url, result.html)
                else:
                    log.warning("crawl4ai stream-result failed: url=%s err=%s", result.url, result.error_message)
                    yield (result.url, None)

    async def _respect_rate_limit(self) -> None:
        """Sleep so requests/minute stays under the cap; add jitter."""
        now = asyncio.get_event_loop().time()
        min_interval = 60.0 / max(1, self._rate_limit_per_minute)
        elapsed = now - self._last_request_at
        if elapsed < min_interval:
            await asyncio.sleep(min_interval - elapsed)
        jitter = random.uniform(*self._random_delay_seconds)
        await asyncio.sleep(jitter)
        self._last_request_at = asyncio.get_event_loop().time()
```

**`enable_stealth=True` rationale.** Confirmed via `https://docs.crawl4ai.com/advanced/undetected-browser/` (WebFetch 2026-05-19): `BrowserConfig(enable_stealth=True)` patches `navigator.webdriver`, modifies browser fingerprints, emulates realistic plugin behavior. Per `docs/design/research/LINKEDIN_SCRAPING.md § 6 risk #3` (Cloudflare/WAF challenge), stealth is the first-line defense across all sources. `UndetectedAdapter` is a separate, more advanced feature that we won't engage in `0.2.0.06` — defer to `0.2.0.13` (rate limiting + anti-detection) if measured 403-rate exceeds threshold.

### D.7 — Error handling pattern

Two error tiers, propagated cleanly to `JobScrapeRun`:

**Tier 1: per-listing errors (recoverable; scrape continues).** The scraper subclass's `scrape()` catches per-URL parse failures, per-URL 429s, per-URL timeouts. It appends to `self._errors[]` and continues iterating. Format per `JOB_MODEL.md § D.2`: `"stage=<list|detail|extract> url=<...> kind=<rate_limit|captcha|timeout|parse_failure|other> msg=<...>"`. Per-listing errors do NOT raise.

```python
# Example in a future LinkedInScraper.scrape():
try:
    html = await self._client.fetch_html(detail_url)
except Crawl4AIRateLimitError as e:
    self._errors.append(f"stage=detail url={detail_url} kind=rate_limit msg={e}")
    continue  # skip this job; move to next
except Crawl4AITimeoutError as e:
    self._errors.append(f"stage=detail url={detail_url} kind=timeout msg={e}")
    continue
```

**Tier 2: scraper-fatal errors (raise to service layer).** Auth failure (LinkedIn rejects guest API), DNS failure, total network outage, scraper subclass bug. The `scrape()` generator raises; `scraper_service.run_scraper()` catches at top level, finalizes `JobScrapeRun.status = FAILED` with the exception in `errors[]`, re-raises to caller (scheduler) if appropriate.

```python
# scraper_service.run_scraper():
try:
    async for raw_job in scraper.scrape(query):
        ...
except Exception as e:  # noqa: BLE001 — top-level catch by design
    await job_service.record_scrape_run(
        session, ...,
        status=JobScrapeStatus.FAILED,
        errors=[f"stage=invocation kind=fatal msg={type(e).__name__}: {e!s}"],
    )
    raise  # propagate to scheduler so it can surface alert
```

**Partial vs success vs failed status determination (in `run_scraper`):**

| Outcome | `JobScrapeRun.status` |
|---|---|
| Generator completes; `len(scraper._errors) == 0` | `SUCCESS` |
| Generator completes; `len(scraper._errors) > 0`; ≥1 RawJob yielded | `PARTIAL` |
| Generator raises mid-stream; ≥1 RawJob already yielded | `PARTIAL` |
| Generator raises before any RawJob yielded | `FAILED` |
| `asyncio.CancelledError` (scheduler time budget) | `TIMED_OUT` |

`asyncio.CancelledError` handling per D.3 above: the generator's `finally` block fires, `run_scraper` catches `CancelledError` separately, finalizes `TIMED_OUT` with partial counters.

### D.10 — Service-layer integration (`scraper_service.py`)

New file `src/services/scraper_service.py` with one public function:

```python
# src/services/scraper_service.py

import asyncio
import logging
from datetime import UTC, datetime

from sqlmodel.ext.asyncio.session import AsyncSession

from models import JobScrapeRun, JobScrapeStatus
from scraper.base import ScrapeQuery, ScraperBase
from services import job_service

log = logging.getLogger(__name__)


async def run_scraper(
    session: AsyncSession,
    *,
    scraper: ScraperBase,
    user_id: int,
    query: ScrapeQuery | None = None,
    triggered_by: str = "manual",
) -> JobScrapeRun:
    """Run one scraper invocation; persist Jobs + JobScrapeRun.

    Lifecycle:
    1. Open JobScrapeRun row with status=RUNNING.
    2. Iterate scraper.scrape(query); for each RawJob, call upsert_job.
    3. On generator completion / exception / cancel, finalize the run.
    4. Return the JobScrapeRun row (for caller observability).

    Caller (scheduler, manual ops, test) sees a JobScrapeRun row
    regardless of outcome; status field distinguishes success / partial /
    failed / timed_out.

    Per `JOB_MODEL.md § F.4`, `record_scrape_run` is the helper that
    writes the table; this function orchestrates the lifecycle around it.
    """
    if query is None:
        query = ScrapeQuery()

    started_at = datetime.now(UTC)
    run = await job_service.record_scrape_run(
        session,
        user_id=user_id,
        source=scraper.source,
        status=JobScrapeStatus.RUNNING,
        triggered_by=triggered_by,
        started_at=started_at,
        raw_meta={"scraper_name": scraper.name, "query": query.model_dump()},
    )
    await session.flush()

    listings_returned = 0
    new_jobs = 0
    updated_jobs = 0
    errors: list[str] = []
    status = JobScrapeStatus.SUCCESS  # mutated below

    try:
        async for raw_job in scraper.scrape(query):
            listings_returned += 1
            try:
                _job, created = await job_service.upsert_job(
                    session,
                    user_id=user_id,
                    source=raw_job.source,
                    external_id=raw_job.external_id,
                    raw=raw_job.model_dump(exclude_unset=True),
                    scrape_run_id=run.id,
                )
                if created:
                    new_jobs += 1
                else:
                    updated_jobs += 1
            except Exception as e:  # noqa: BLE001 — per-listing tolerance
                errors.append(
                    f"stage=upsert url={raw_job.source_url} kind=upsert_failure msg={type(e).__name__}: {e!s}"
                )
                log.exception("upsert_job failed for %s", raw_job.source_url)

        # Inherit per-scraper errors collected during scrape().
        errors.extend(getattr(scraper, "_errors", []))

        if errors and listings_returned > 0:
            status = JobScrapeStatus.PARTIAL
        elif errors and listings_returned == 0:
            status = JobScrapeStatus.FAILED
        else:
            status = JobScrapeStatus.SUCCESS

    except asyncio.CancelledError:
        status = JobScrapeStatus.TIMED_OUT
        errors.append("stage=invocation kind=cancelled msg=asyncio.CancelledError")
        raise  # re-raise so scheduler can react
    except Exception as e:  # noqa: BLE001 — top-level scraper failure
        if listings_returned > 0:
            status = JobScrapeStatus.PARTIAL
        else:
            status = JobScrapeStatus.FAILED
        errors.append(f"stage=invocation kind=fatal msg={type(e).__name__}: {e!s}")
        log.exception("scraper %s failed", scraper.name)
    finally:
        finished_at = datetime.now(UTC)
        run.status = status
        run.finished_at = finished_at
        run.listings_returned = listings_returned
        run.new_jobs = new_jobs
        run.updated_jobs = updated_jobs
        run.errors = errors
        run.duration_ms = int((finished_at - started_at).total_seconds() * 1000)
        session.add(run)
        await session.flush()

    return run
```

**Notes on the orchestration:**

- **`record_scrape_run` is called once** to open the row (`status=RUNNING`); the `finally` block updates the same row in-place via `session.add(run)`. This is intentional: `JobScrapeRun` rows survive the run lifecycle as a single row, not append-only.
- **`session.flush()` after each phase**, never `session.commit()` — caller (cron job, test, manual ops) commits at the boundary. This is the merged Naavik pattern (per `tests/test_job_service.py` round-trips).
- **`scraper._errors`** is accessed via `getattr` to keep the contract loose; subclasses MAY maintain the list, but the orchestrator doesn't require it.
- **`asyncio.CancelledError` is re-raised** after marking the run TIMED_OUT — Python's structured concurrency demands it; scheduler upstream needs the signal.

### D.13 — Hint fields vs structured fields (one more boundary call)

`RawJob` carries `*_hint` enum fields (`remote_policy_hint`, `visa_restriction_hint`, `seniority_level_hint`). Two alternatives considered + rejected.

**Rejected: structured enum fields without `_hint` suffix.** Would mean `RawJob.remote_policy: RemotePolicy` direct. Problem: scraper subclasses that *guess* (LinkedIn listing card shows `"Remote · Hybrid · On-site"` and they pick one) overwrite AI extraction's later authoritative read of the JD body. Hint suffix preserves "scraper opinion vs AI ground truth" as separable.

**Rejected: free-form strings.** `RawJob.remote_policy_hint: str | None`. Would let scrapers say `"hybrid"` / `"Hybrid"` / `"3 days in office"` and force AI extraction to normalize. Typed enum hint catches at boundary (Pydantic validation rejects unknown values); enforces source-side normalization.

**Accepted: typed enum hints.** Same enum type as the corresponding `Job` field; nullable; semantically "scraper's best guess; AI may override". `0.2.0.08` (AI extraction) writes the final `Job.remote_policy` from the JD body; the hint is diagnostic-only after extraction lands.
