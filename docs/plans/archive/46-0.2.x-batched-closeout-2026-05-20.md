### Item 1 — Expand `test_no_direct_http_imports.py` lint (0.2.0.07b, #104)

**Rationale.** Filed by hacker on PR #102. The current `FORBIDDEN_MODULES = {"requests", "httpx", "urllib.request", "aiohttp"}` set-membership check misses sibling libraries and attribute-access forms: `from urllib import request`, `import http.client`, `import urllib3`, `import httpcore`, `import niquests`, `import aiohttp.client`. Convert to prefix-match + extend the forbidden set + AST walk both `ast.Import` and `ast.ImportFrom` for the `urllib.*` / `http.*` / `aiohttp.*` namespaces.

**Files.**

- `tests/test_no_direct_http_imports.py` — replace set-membership with prefix-match helper. Extend `FORBIDDEN_MODULES` to `{"requests", "httpx", "urllib", "urllib3", "http.client", "httpcore", "niquests", "aiohttp"}`. AST walk: for `ast.Import`, check `alias.name` against forbidden prefixes (e.g. `urllib.request` matches prefix `urllib`); for `ast.ImportFrom`, check `node.module` against the same. Whitelist `httpx_oauth` (if it exists in scraper layer, keep the existing whitelist; otherwise no-op).
- (No source changes — guard-only test edit.)

**LOC.** ~25 LOC test diff. **Tests.** 1 new positive test (each forbidden form is rejected: 8 parametrized cases). 1 negative test (`from typing import TYPE_CHECKING` style imports unaffected).

### Item 4 — Telegram parse_mode/escape fix for `_telegram_text_for_event` + `send_telegram` (0.2.0.12a, #117)

**Rationale.** Filed by hacker on PR #116. The wave-6 high-score notification path at `src/services/notifications.py:211` (`_telegram_text_for_event`) + `:242` (`send_telegram`) has the same Markdown-injection surface that `_send_telegram_scrape_run` had pre-fix (closed in PR #116 delta `c4d4154`). Scraper-controlled `role`/`company` fields can carry `*` / `_` / `[]()` and would render as Markdown formatting. Apply the identical mitigation: drop `parse_mode=Markdown` from the `send_telegram` body payload + drop `*...*` bolding from any header line in `_telegram_text_for_event`.

**Files.**

- `src/services/notifications.py:258` — remove `"parse_mode": "Markdown"` key from the body dict; final shape: `{"chat_id": chat, "text": text}`.
- `src/services/notifications.py:211–240` — scan `_telegram_text_for_event` body for `*<x>*` bolding (header / job-title / company emphasis); strip the `*` wrappers. Telegram auto-linkifies URLs without parse_mode (already noted in adjacent comment at line 428–430), so plain-text shape is safe.

**LOC.** ~2 LOC source diff (parse_mode line removal + bolding strip — exact line count depends on number of `*x*` instances in `_telegram_text_for_event`). **Tests.** 1 new test in the existing notifications test file: `send_telegram(event with role="Senior *Test* Engineer")` produces body payload without `parse_mode` key + literal `*` characters preserved in `text`. Mock httpx, assert request body shape.
