### Wave 1 — Security/route hardening (`src/ui/routes/tracking.py` + `src/services/application_service.py`)

**W1.1 — 0.4.5.10: `PUT /api/v1/applications/{id}/notes` Pydantic `max_length=2000` validator BEFORE body parse**
- Path: `src/ui/routes/tracking.py:355-404` (the `put_application_notes` handler + sibling `_NOTES_MAX_CHARS` const).
- Fix: Introduce Pydantic `NotesPayload(BaseModel)` with `notes: str = Field(min_length=0, max_length=2000)`. Replace the current manual `if len(text) > _NOTES_MAX_CHARS: raise` block with FastAPI body validation. Pydantic raises 422 at body-parse layer (BEFORE the route body sees the dict), eliminating the DoS amplification surface where a malicious 50MB body parsed before the cap fired.
- Form-encoded compat: existing handler accepts both `application/json` and form-encoded. Pydantic-as-body assumes JSON. Solution: keep dual-content-type support but wrap form-decode in `NotesPayload.model_validate({"notes": form["notes"]})` which still triggers `max_length=2000` validation at validator level (constant-time field check on the in-memory str — same protection, slight UX trade since form body still gets uploaded first).
- **Locked: prefer the JSON-body Pydantic path; keep form-encoded support but route it through `model_validate` so the validator fires consistently.**
- ~10 LOC + 1 new test (`test_notes_oversize_rejected_at_validator_layer`).

**W1.2 — 0.4.5.11: `_application_or_404` filters `deleted_at IS NULL`**
- Path: `src/ui/routes/tracking.py:130-135`.
- Fix: After `await application_service.get_application(session, application_id)`, add an explicit `a.deleted_at is not None` → `raise HTTPException(status_code=404)` check before the user_id boundary.
