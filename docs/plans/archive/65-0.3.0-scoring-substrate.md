# 65 · 0.3.0 — Scoring substrate

## A · Goal

Ship the hybrid layered scorer (tag overlap → semantic cosine → LLM-as-judge) that writes `Job.score` + `Job.score_explanation` + `Job.match_breakdown` for every job in every user's queue. Six ROADMAP rows (`0.3.0.01–06`) cover the visa-chip wiring, tag layer, profile embedding sibling table, semantic layer, LLM-judge layer w/ schema expansion, and the cron orchestrator. Cost-cap-aware: when `Settings.daily_llm_cost_cap_usd` is exhausted the orchestrator silently falls back to a layer-2-3 composite and surfaces a banner on Settings · LLM (the banner UI itself lands in `0.3.2.04`; this plan only persists the `judge_skipped=true` signal).

## B · Why

`ROADMAP § 0.3.0` (lines 351–368) is the critical-path unblocker for `0.4.0` Application Tracking & Auto-Apply — auto-apply gates on `Job.score >= Settings.auto_apply_score_threshold` (`BACKEND.md § O`). Until 0.3.0 lands, no job ever achieves a non-trivial score outside the deterministic visa filter, so the auto-apply queue stays empty by construction.

The research memo (`docs/design/research/0.3.0-intelligent-scoring-research.md`) locked seven strategic OQs:

- **OQ-1** — hybrid layered architecture (Option 4 in § C of the memo).
- **OQ-2** — LLM tier user-configurable via `Settings.llm_provider`; layer 4 skips when no provider is configured.
- **OQ-3** — LinkedIn MCP deferred to `0.5.0.12.1` (no scope addition here).
- **OQ-4** — 3-sub-release cut already applied to ROADMAP (`0.3.0` substrate · `0.3.1` resume + one-click · `0.3.2` UI polish).
- **OQ-5** — cost-cap fallback is silent + banner on Settings · LLM tab (banner is `0.3.2.04`, signal is persisted by this plan).
- **OQ-6** — profile embedding refresh on edit + nightly idempotent batch.
- **OQ-7** — Discover card shows 1–2 sentence overview + 3–5 gap bullets; full `/jobs/{id}/match` modal carries structured `{strengths, gaps, visa_note}`.

This plan converts those locks into a file-by-file implementation contract.

The 0.2.7 sweep deliberately staged the substrate this plan consumes: `JobEmbedding` + `embedding_service.embed_job` + `LLMProvider.embed` ABC + `tracked_call` + Settings.semantic_match_* fields + APScheduler nightly-batch pattern. Nothing material needs new infrastructure — this is the wire-up release.

## C · Tactical decisions locked by this plan

User locked the 7 strategic OQs pre-dispatch. The 11 tactical decisions below cover engineering choices the OQs did not address. Plan recommends one in each case; engineer follows without re-deciding.

### T1 — Cost-cap probe ordering

**Decision: per-job pre-flight probe, NOT per-batch.** Before layer 4 fires, the orchestrator awaits `llm_tracker.today_cost_usd(session, user_id=...)` + compares to `Settings.daily_llm_cost_cap_usd`. If `cap is not None AND today_cost + estimated_judge_cost > cap`, layer 4 skips for this job and the orchestrator records `judge_skipped=true`. The probe is per-job because the cron processes jobs in a loop within one transaction; per-batch probing would underestimate spend at the tail of a large batch (the cap could trip mid-batch and the loop wouldn't notice until next invocation).

**Cost of pre-flight call:** one indexed scalar SELECT per job (the same `today_cost_usd` query that Settings · LLM cards already run). Negligible at ~1k jobs/day.

**Estimated judge cost per job:** static constant `_ESTIMATED_JUDGE_COST_USD = 0.015` (Sonnet 4.6 @ ~5K input + 500 output tokens). Stored as a module-level constant in `services/scorer.py`; tightened post-launch from observed averages on `ApiUsage`. Conservative bound — better to skip one borderline job than overshoot the cap.

**Rationale rejected:** session-cached `cap_exhausted_at` flag (set once per orchestrator run). Rejected because cron runs 15min apart — a flag in the in-process orchestrator dies between runs and adds state for ~no gain; a DB-stored flag duplicates information already present in `ApiUsage` rollups.

### T2 — Per-tag weight defaults

**Decision: `Settings.score_per_dim_weights` defaults to `{}` (empty dict → all tags weighted 1.0).** Tag weights are operator-tunable but the baseline ships neutral. Per-tag weight resolution:

```python
def _tag_weight(tag: Tag, weights: dict[str, float]) -> float:
    return float(weights.get(tag.value, 1.0))
```

**Rationale:** the H1B/i-140 owner-profile (Shyam Padia) is the only seeded profile, but Naavik ships as self-host first — every new user's tag relevance differs. Letting the LLM judge implicitly weight via its own attention is more robust than baking owner-specific weights into the default. Operators who want to bias (e.g. "ai-ml weight = 1.5 for me") tune via Settings · LLM (UI wiring is `0.3.2.04` scope; the JSONB column ships here).

**Schema:** `dict[str, float]` keyed by the 9 Tag enum values. Pydantic validator (`PerDimWeights.model_validate(value)`) accepts only the 9 known keys, rejects unknown keys (security: prevents arbitrary JSONB pollution), clamps values to `[0.0, 3.0]` (caps over-weighting a single dimension).

**Reference file:** new `src/services/scorer/weights.py` (sibling to the existing `scorer.py` module — split is T11).

### T3 — Layer 1 tag-overlap score formula

**Decision: weighted overlap with profile-tag normalizer.**

```
job_tags     = set(Job.tags)           # populated by 0.2.0.08 extract_job
profile_tags = aggregated_profile_tags # union of Bullet.tags across user (set)
weights      = Settings.score_per_dim_weights or {tag: 1.0 for tag in TAG_VOCAB}

numerator    = Σ(weights[t]      for t in job_tags ∩ profile_tags)
denominator  = Σ(weights[t]      for t in job_tags)               # NOT union — we ask "how much of what the job wants does the profile cover?"
tag_score    = numerator / denominator if denominator > 0 else 0.0
```

**Rationale (recommended over plain Jaccard `|J ∩ P| / |J ∪ P|`):**

| Dimension | Weighted overlap (recommended) | Plain Jaccard |
|---|---|---|
| Symmetry | Asymmetric — asks "does profile cover what JD wants?" | Symmetric — penalizes profile breadth |
| Profile breadth penalty | None — extra profile tags don't lower score | High — a profile with 7 tags scoring an JD with 3 tags maxes at `3/7 = 0.43` even with full overlap |
| Operator tunability | Direct — weight up the tags they care about | Indirect — Jaccard ignores weights cleanly |
| Math fit for "is profile a good fit for this job" | Strong — that's the question we're asking | Weak — it's the wrong axis |

**Edge cases:**
- Job with zero tags (rare, only if `0.2.0.08 extract_job` failed) → `tag_score = 0.0`, layer 1 dispositions per T4 floor.
- Profile with zero tags (new user, no bullets tagged) → `tag_score = 0.0`, layer 1 dispositions per T4 floor.

**Reference file:** `_tag_overlap_score(job: Job, profile_tags: frozenset[str], weights: dict[str, float]) -> float` in `src/services/scorer/tag_layer.py`.

### T4 — Layer 1 floor + promotion to layer 2

**Decision: hardcoded floor `_TAG_FLOOR = 0.10`; no per-user override at v1.** Any `tag_score >= 0.10` promotes to layer 2 (semantic cosine). Below `0.10` the orchestrator persists `score = tag_score, judge_skipped = True, layers_run = ["tag"]` and short-circuits.

**Rationale (recommended over per-user `Settings.semantic_rerank_topk`):**

- The research memo's `0.50` LLM gate is per-job composite score; T4's floor is per-job tag-only score. They're different axes.
- The scoring cron processes per-user, per-job — there's no Top-K-by-tag-rank batch. Every job that passes the floor flows to layer 2. "Top-K" framing only applies if we batched jobs across a user and ranked them, which the cron does not.
- 0.10 is generous — Shyam's profile + a Workday DevOps JD with one matched tag (`devops`) clears 0.10 even with non-DevOps weights. We're filtering "clearly off-topic" jobs, not "borderline."

**Promotion to layer 3 (LLM judge)** is governed by a composite (tag + semantic) `>= _LLM_GATE` threshold — see T5.

**Reference file:** module-level constants `_TAG_FLOOR = 0.10` + `_LLM_GATE = 0.50` in `src/services/scorer/__init__.py`.

### T5 — Layer 2 → Layer 3 promotion threshold

**Decision: composite `0.4 × tag_score + 0.6 × semantic_score >= _LLM_GATE` (default `0.50`).** Weights `0.4/0.6` favor semantic over tag (semantic carries richer signal per § D.7 of research memo: 89% F1 vs ~60% precision for keyword-only).

**Below `_LLM_GATE`:**
- `score = composite`, `layers_run = ["tag", "semantic"]`, `judge_skipped = True` (with reason `"below_llm_gate"`).
- Orchestrator persists + moves on (no LLM call).

**Above `_LLM_GATE`:**
- Layer 4 fires (LLM-as-judge).
- `JobScore.score` from LLM overrides composite as the final persisted `Job.score`.

**Rationale (recommended over `Settings.llm_judge_topn`):**

- v1 doesn't batch — every job is independently scored. "Top-N" framing implies a sort across the user's job pool; the cron processes jobs as they're discovered.
- A threshold is more cost-predictable than a top-N: a user with 200 daily inbound jobs all above 0.50 composite would burn 200 LLM calls; a top-N=20 cap would silently drop 180. The threshold + cost cap (T1) is the right composability.
- Future work can add Top-N batching in `0.8.0.4X` if observed cost behavior demands it; v1's threshold doesn't preclude.

**Reference file:** module-level constants per T4.

### T6 — `JobScore` Pydantic schema (expanded)

**Decision:** extend the existing `JobScore` schema in `src/llm/prompts/score_job.py` to the following shape. Bounds + length caps prevent prompt-injection oversize-payload attacks (hacker-relevant — Pydantic `max_length` enforces).

```python
from typing import Literal
from pydantic import BaseModel, Field, field_validator
from models.enums import Tag

# Module-level constants visible to the orchestrator (T8).
MAX_GAPS = 5
MAX_SUGGESTED_BULLETS = 8
MAX_STRENGTHS = 5

class JobScore(BaseModel):
    score: float = Field(ge=0.0, le=1.0)
    explanation: str = Field(max_length=512)              # 1-2 sentences (OQ-7)
    matched_tags: list[Tag] = Field(default_factory=list, max_length=9)
    per_dimension: dict[str, float] = Field(default_factory=dict)
    strengths: list[str] = Field(default_factory=list, max_length=MAX_STRENGTHS)  # 0-5 short bullets
    gaps: list[str] = Field(default_factory=list, max_length=MAX_GAPS)            # 3-5 short bullets (OQ-7)
    suggested_bullets: list[int] = Field(default_factory=list, max_length=MAX_SUGGESTED_BULLETS)
    visa_concern: bool = False
    visa_note: str | None = Field(default=None, max_length=256)

    @field_validator("per_dimension")
    @classmethod
    def _validate_per_dim(cls, v: dict[str, float]) -> dict[str, float]:
        # Reject unknown tag keys (security: bound the JSONB shape).
        allowed = {t.value for t in Tag}
        out: dict[str, float] = {}
        for k, val in v.items():
            if k not in allowed:
                continue                          # silently drop unknown keys
            out[k] = max(0.0, min(1.0, float(val)))  # clamp to [0,1]
        return out

    @field_validator("gaps", "strengths")
    @classmethod
    def _strip_long_bullets(cls, v: list[str]) -> list[str]:
        return [s[:120] for s in v]              # cap bullet length 120 chars
```

**Rationale on each field:**

- `score` — already capped `[0,1]` in current skeleton.
- `explanation` — 512-char cap allows 1–2 sentences without runaway responses.
- `matched_tags` — typed as `list[Tag]` (already 9-vocab); max 9.
- `per_dimension` — `dict[str, float]` keyed by Tag enum values. Validator drops unknown keys + clamps values. This is what drives Discover's per-dim bars (`SCREENS.md § 7`).
- `strengths` — new field per OQ-7's "structured `{strengths, gaps, visa_note}` for full modal." Short bullets; max 5; capped 120 chars.
- `gaps` — already present; now max 5 (per OQ-7) + capped 120 chars per bullet.
- `suggested_bullets` — list of `Bullet.id` integers (max 8) the LLM thinks should be selected for this job. Orchestrator validates these IDs exist + belong to the right user (T9).
- `visa_concern` — already present; bool.
- `visa_note` — new short string explaining the visa concern (e.g. "JD says 'US citizens only'"). Surfaces in `/jobs/{id}/match` modal.

**`suggested_bullets` ID-existence validation** happens in the orchestrator post-LLM-call (`scorer.score_job_layered` filters non-existent IDs + IDs belonging to other users). This is belt-and-suspenders against LLM hallucination — the prompt instructs valid IDs, but a bad parse can't poison the persisted `match_breakdown`. Filed under T9 below.

**Reference file:** `src/llm/prompts/score_job.py` (in-place expansion; existing import sites continue working via the same class name).

### T7 — `Job.match_breakdown` canonical JSONB shape

**Decision:** the JSONB blob on `Job.match_breakdown` carries exactly the following shape (PG `JSONB` allows arbitrary structure, but the orchestrator writes only this — no extra keys; new keys require a plan).

```python
{
    "score": 0.86,                     # final score (== Job.score; redundant for read APIs)
    "per_dimension": {                 # max 9 keys from Tag enum
        "ai-ml": 0.95,
        "platform": 0.88,
        "leadership": 0.82,
        "visa": 0.70,
    },
    "matched_tags": ["ai-ml", "platform", "leadership"],
    "strengths": ["10+ years AI/ML in production", "Distributed-systems platform background"],
    "gaps": ["Kubernetes", "GCP"],
    "suggested_bullets": [3, 7, 12],   # Bullet.id; orchestrator-filtered
    "visa_concern": false,
    "visa_note": null,
    "layers_run": ["tag", "semantic", "llm_judge"],   # which layers fired
    "judge_skipped": false,
    "judge_skipped_reason": null,      # "below_llm_gate" | "cost_cap_exhausted" | "no_provider" | null
    "layer_4_provider": "anthropic",   # null if skipped
    "layer_4_model": "claude-sonnet-4-6", # null if skipped
    "scored_at": "2026-05-21T03:14:15Z",
    "tag_score": 0.78,                 # raw layer-1 score for debugging
    "semantic_score": 0.82,            # raw layer-2 score (null if skipped)
    "composite_pre_llm": 0.806,        # 0.4*tag + 0.6*semantic

```

**Rationale on the redundancies:**

- `score` is duplicated on the Job column for indexability + on the JSONB for self-contained debugging blobs.
- `tag_score` / `semantic_score` / `composite_pre_llm` allow operators (or future Score Analytics — `0.3.2.03`) to deconstruct "why did this job score 0.86" without rerunning the LLM. Storage: ~200 bytes per row uncompressed.
- `schema_version` (int, starts at 1) gives the orchestrator a forward-compat marker. Future shape changes either bump the version + write a migration (cron-driven backfill) or add nullable keys (no migration needed).

**Existing `Job.match_breakdown` callers** (`SCREENS.md § 7` reads `per_dimension`, `matched_tags`, `gaps`; § 8 reads same) work unchanged — the new keys are additive.

**Reference file:** `src/services/scorer/__init__.py` — `_serialize_breakdown(...)` helper.

### T8 — Score persistence semantics

**Decision:**

1. **`Job.score` write rule:** `score_job_layered` updates `Job.score = JobScore.score` (or composite when judge skipped). Always overwrites — no append/history (history is `0.3.2.03` deferred).
2. **`Job.score_explanation` write rule:** updated to `JobScore.explanation` (or layer-2-3 fallback prose string when judge skipped — orchestrator synthesizes `"Tag + semantic match composite ({composite:.2f}); LLM judge skipped: {reason}"`).
3. **`Job.match_breakdown` write rule:** full T7 JSONB overwrite (no merge).
4. **`Job.updated_at` write rule:** bumped to `datetime.now(UTC)` on every score write — consistent with all other Job mutations in `job_service.upsert_job`.
5. **AppEvent emission:** scoring does **NOT** emit an AppEvent (per `DATA_MODEL.md § C AppEvent`: events fire for Application-state transitions, not Job-state-internal scoring). The visa-zero-out case (layer 1) also does not emit — visa filter is deterministic + pre-application. If future analytics need score-change events, file as `0.3.3.NN`.
6. **Notifications:** the existing `notifications.notify_new_high_score_job` consumer (per `BACKEND.md § H.3`) fires from `scraper_service.run_scraper` post-score (Phase 3+). This plan does not add or change the notification trigger — but the `notify_threshold` Setting now has a real signal to gate on.

**Re-scoring policy:** see T10.

**Reference file:** `src/services/scorer/orchestrator.py:_persist_score`.

### T10 — Re-scoring trigger policy

**Decision:** v1 ships **three** re-scoring triggers — explicit, deterministic, no time-decay magic.

1. **Initial scoring** — `jobs.score_pending` cron (every 15min). Picks jobs where `Job.score = 0.0 AND deleted_at IS NULL AND visa_filter_not_zeroed`. Scores them. Critical-path.
2. **Profile-edit propagation** — on `POST /api/v1/profile/bullets/*` (any mutation) OR profile-headline edit, the orchestrator marks the user's existing jobs as `stale_score = True` (new boolean column? No — re-uses `Job.match_breakdown.scored_at` < `Profile.updated_at` lookup; see below). The nightly `score.recompute_stale` cron (03:30 UTC, **NEW in this plan**) re-scores jobs where `Profile.updated_at > scored_at`. Skips when profile is unchanged.
3. **Manual operator button** — `POST /api/v1/jobs/{id}/rescore` (route exists today returning 501; this plan wires it). UI in `0.3.2.NN` adds a button on the Discover card; for v1 it's curl/API only. The endpoint forces a full re-score regardless of stale signal.

**Re-scoring is NOT triggered by:**
- Time alone (e.g. "re-score every job once a month"). Deferred to `0.8.0.4X` if drift becomes observable.
- LLM provider change (changing `Settings.llm_provider`). Operator can hit `/rescore` manually for jobs they care about. Bulk re-score is `0.8.0.4X`.
- Cost-cap fallback resolution. Once tomorrow's cap resets, the same job gets re-scored on its natural cycle (manual button or `score.recompute_stale` if a profile edit also coincided).

**Why no `Job.stale_score` boolean:** adds a 7th index-or-column on a hot table for what's effectively a date comparison. The `Profile.updated_at > Job.match_breakdown->>'scored_at'::timestamptz` SQL works fine on the existing JSONB + `Profile.updated_at` index.

**Reference file:** new `src/services/scorer/orchestrator.py:score_unscored_jobs` + `src/services/scorer/orchestrator.py:rescore_stale_jobs`.

### D.2 · 0.3.0.02 — Tag-based matching layer

**Goal:** ship layer 1 of the layered scorer (T3 weighted-overlap formula). Pure-Python, deterministic, no LLM call.

**Files:**

- `src/services/scorer/tag_layer.py` (NEW, ~180 LOC):

```python
"""Layer 1 — tag overlap. Per plan 65 § T3 + § T4."""
from __future__ import annotations
from collections.abc import Iterable
from sqlmodel.ext.asyncio.session import AsyncSession
from sqlmodel import select
from models import Bullet, Experience, Job, Profile, Tag
from .weights import resolve_weights

async def aggregated_profile_tags(session: AsyncSession, *, profile: Profile) -> frozenset[str]:
    """Union of Bullet.tags across the profile's experiences. Cached per call."""
    # JOIN bullet → experience → profile, filter deleted_at IS NULL on both,
    # SELECT DISTINCT tags. Returns frozenset[str] (Tag enum values).
    stmt = (
        select(Bullet.tags)
        .join(Experience, Bullet.experience_id == Experience.id)
        .where(
            Experience.profile_id == profile.id,
            Bullet.deleted_at.is_(None),
            Experience.deleted_at.is_(None),
        )
    )
    out: set[str] = set()
    for row in (await session.exec(stmt)).all():
        for tag in (row or []):
            if tag in {t.value for t in Tag}:
                out.add(tag)
    return frozenset(out)

def _tag_overlap_score(
    job_tags: Iterable[str],
    profile_tags: frozenset[str],
    weights: dict[str, float],
) -> float:
    """Weighted overlap. Asymmetric — measures profile coverage of job's tags."""
    job_set = frozenset(job_tags or ())
    if not job_set:
        return 0.0
    numerator = sum(weights.get(t, 1.0) for t in (job_set & profile_tags))
    denominator = sum(weights.get(t, 1.0) for t in job_set)
    if denominator <= 0:
        return 0.0
    return min(1.0, numerator / denominator)
```

```python
"""Layer 2 — semantic cosine. Per plan 65 § C / § T5."""
from __future__ import annotations
from sqlmodel import select
from sqlmodel.ext.asyncio.session import AsyncSession
from models import Job, JobEmbedding, ProfileEmbedding

async def _semantic_score(
    session: AsyncSession,
    *,
    job: Job,
    profile_embedding: ProfileEmbedding | None,
) -> float | None:
    """Cosine similarity of job ↔ profile embeddings; None when either is missing.

    Returns sim in [0, 1] (1 = identical, 0 = orthogonal/opposite).
    Implementation: pgvector `<=>` cosine distance, converted via 1 - d/2.
    """
    if profile_embedding is None:
        return None
    job_emb = (
        await session.exec(
            select(JobEmbedding).where(JobEmbedding.job_id == job.id, JobEmbedding.user_id == job.user_id)
        )
    ).one_or_none()
    if job_emb is None:
        return None
    # Inline the cosine distance query — sibling tables, no Python-side cosine math.
    stmt = text(
        """
        SELECT 1.0 - (CAST(:p AS vector) <=> CAST(:j AS vector)) / 2.0 AS sim
        """
    )
    p_lit = "[" + ",".join(f"{v}" for v in profile_embedding.embedding) + "]"
    j_lit = "[" + ",".join(f"{v}" for v in job_emb.embedding) + "]"
    result = await session.exec(stmt.bindparams(p=p_lit, j=j_lit))
    val = result.one()
    return max(0.0, min(1.0, float(val[0] if isinstance(val, tuple) else val)))
```

**Rationale on the SQL roundtrip vs Python `numpy.dot`:** the embedding vectors are already in Postgres; pulling them to Python + cosine'ing in numpy round-trips 2 × 768 floats (~12KB) per scoring call. Letting Postgres compute the cosine via pgvector's operator keeps the math on the DB side + avoids the round trip. Net latency: ~5ms vs ~30ms for the Python path on a single job.

```python
"""Layer 4 — LLM-as-judge. Per plan 65 § D.5 + § T1 + § T6."""
from __future__ import annotations
import logging
from sqlmodel.ext.asyncio.session import AsyncSession
from llm import LLMProvider, LLMProviderError, get_provider
from llm.prompts.score_job import JobScore, PROMPT
from models import Bullet, Job, Profile, Settings, Tag
from services import llm_tracker

log = logging.getLogger(__name__)

_ESTIMATED_JUDGE_COST_USD = 0.015  # ~5K input + 500 output tokens at Sonnet 4.6 pricing

async def cost_cap_exhausted(
    session: AsyncSession, *, user_id: int, settings: Settings
) -> bool:
    """True iff a layer-4 call would exceed the daily cap."""
    cap = settings.daily_llm_cost_cap_usd
    if cap is None:
        return False
    today_spend = await llm_tracker.today_cost_usd(session, user_id=user_id)
    return (today_spend + _ESTIMATED_JUDGE_COST_USD) > cap

async def _llm_judge_score(
    session: AsyncSession,
    *,
    user_id: int,
    job: Job,
    profile: Profile,
    candidate_bullets: list[Bullet],   # top-K-by-tag-match; orchestrator passes
    tag_score: float,
    semantic_score: float | None,
    settings: Settings,
) -> tuple[JobScore | None, str | None]:
    """Call the LLM judge. Returns (JobScore, skip_reason).

    Returns (None, "no_provider") if no LLM provider is configured (OQ-2 graceful).
    Returns (None, "llm_failed") on LLMProviderError after retries (graceful degrade).
    """
    provider = get_provider(settings)
    if provider is None:
        return None, "no_provider"

    rendered = PROMPT.format(
        profile=_compose_profile_summary(profile),
        profile_tags=_render_profile_tags(profile, candidate_bullets),
        candidate_bullets=_render_bullets_with_ids(candidate_bullets),
        company=job.company or "",
        role=job.role or "",
        description=(job.description or "")[:4000],
        job_tags=", ".join(job.tags or []),
        skills=", ".join(job.skills_required or []),
        visa_restrictions=str(job.visa_restrictions),
        tag_score=tag_score,
        semantic_score=semantic_score if semantic_score is not None else 0.0,
        tag_vocabulary=", ".join(t.value for t in Tag),
    )
    try:
        result = await llm_tracker.tracked_call(
            session=session,
            user_id=user_id,
            provider=provider,
            method="structured",
            prompt_name="score_job",
            prompt=rendered,
            schema=JobScore,
        )
    except LLMProviderError as exc:
        log.warning("score_job LLM failed for job %s: %s", job.id, exc)
        return None, "llm_failed"

    score = JobScore.model_validate(result.value)
    return score, None

def _compose_profile_summary(profile: Profile) -> str:
    """One-block render of profile identity + summary for the prompt."""
    return "\n".join(
        x for x in (
            profile.full_name,
            profile.headline,
            profile.summary_short or profile.summary_full or "",
        ) if x
    )

def _render_profile_tags(profile: Profile, bullets: list[Bullet]) -> str:
    """Union of bullet tags across the candidate bullets passed to the prompt."""
    seen: set[str] = set()
    for b in bullets:
        for t in (b.tags or []):
            seen.add(t)
    return ", ".join(sorted(seen))

def _render_bullets_with_ids(bullets: list[Bullet]) -> str:
    """One bullet per line: `[id] text` (truncate to 200 chars)."""
    return "\n".join(f"[{b.id}] {(b.text or '')[:200]}" for b in bullets if b.id is not None)
```

**Note on bullet-selection seeding for `candidate_bullets`:** the orchestrator (D.6) selects the top-K bullets to pass to the LLM by tag-overlap with `job.tags`. K=12 default (constant in `__init__.py`). The LLM then selects up to 8 from those 12 via `suggested_bullets`. Two-stage narrowing keeps token cost predictable.

```python
from __future__ import annotations
import logging
from datetime import UTC, datetime
from sqlmodel import select
from sqlmodel.ext.asyncio.session import AsyncSession
from llm.prompts.score_job import JobScore
from models import Bullet, Experience, Job, Profile, ProfileEmbedding, Settings

from .visa import apply_visa_filter, needs_visa_zero_out
from .tag_layer import _tag_overlap_score, aggregated_profile_tags
from .semantic_layer import _semantic_score
from .llm_judge import _llm_judge_score, cost_cap_exhausted
from .weights import resolve_weights

log = logging.getLogger(__name__)

_TAG_FLOOR = 0.10
_LLM_GATE = 0.50
_TAG_WEIGHT = 0.4
_SEMANTIC_WEIGHT = 0.6
_K_CANDIDATE_BULLETS = 12
_BATCH_SIZE = 50

async def score_job_layered(
    session: AsyncSession,
    *,
    user_id: int,
    job: Job,
    profile: Profile,
    settings: Settings,
    source_trust_weight: float = 1.0,
) -> JobScore:
    """End-to-end layered scoring for one job. Persists Job.score + match_breakdown."""

    # ── Layer 1a — deterministic visa filter ──────────────────────────
    if needs_visa_zero_out(profile, job):
        score = JobScore(score=0.0, explanation=(
            "Visa filter: job requires US citizenship / green card; "
            "candidate needs sponsorship now."
        ), visa_concern=True, visa_note=str(job.visa_restrictions))
        await _persist(session, job=job, score=score, layers_run=["visa"],
                       judge_skipped=True, judge_skipped_reason="visa_zeroed",
                       tag_score=0.0, semantic_score=None,
                       composite_pre_llm=0.0, layer_4_provider=None, layer_4_model=None)
        return score

    # ── Layer 1b — tag overlap ────────────────────────────────────────
    profile_tags = await aggregated_profile_tags(session, profile=profile)
    weights = resolve_weights(settings)
    tag_score = _tag_overlap_score(job.tags or [], profile_tags, weights)
    if tag_score < _TAG_FLOOR:
        # Short-circuit below floor.
        composite = tag_score * source_trust_weight
        score = JobScore(score=composite, explanation=(
            f"Below tag floor — only {tag_score:.2f} of job's tags covered by profile."
        ))
        await _persist(session, job=job, score=score, layers_run=["tag"],
                       judge_skipped=True, judge_skipped_reason="below_tag_floor",
                       tag_score=tag_score, semantic_score=None,
                       composite_pre_llm=composite, layer_4_provider=None, layer_4_model=None)
        return score

    # ── Layer 2 — semantic cosine ─────────────────────────────────────
    profile_emb = (
        await session.exec(
            select(ProfileEmbedding).where(ProfileEmbedding.user_id == user_id)
        )
    ).one_or_none()
    semantic_score = await _semantic_score(session, job=job, profile_embedding=profile_emb)

    if semantic_score is None:
        # Embedding not available — composite = tag_score alone.
        composite = tag_score
        layers_run = ["tag"]
    else:
        composite = _TAG_WEIGHT * tag_score + _SEMANTIC_WEIGHT * semantic_score
        layers_run = ["tag", "semantic"]

    composite *= source_trust_weight

    if composite < _LLM_GATE:
        score = JobScore(score=composite, explanation=(
            f"Tag + semantic composite ({composite:.2f}) below LLM threshold; judge skipped."
        ))
        await _persist(session, job=job, score=score, layers_run=layers_run,
                       judge_skipped=True, judge_skipped_reason="below_llm_gate",
                       tag_score=tag_score, semantic_score=semantic_score,
                       composite_pre_llm=composite,
                       layer_4_provider=None, layer_4_model=None)
        return score

    # ── Layer 3 — LLM-as-judge (cost-cap probe per T1) ────────────────
    if await cost_cap_exhausted(session, user_id=user_id, settings=settings):
        score = JobScore(score=composite, explanation=(
            f"Tag + semantic composite ({composite:.2f}); LLM judge paused — daily cost cap reached."
        ))
        await _persist(session, job=job, score=score, layers_run=layers_run,
                       judge_skipped=True, judge_skipped_reason="cost_cap_exhausted",
                       tag_score=tag_score, semantic_score=semantic_score,
                       composite_pre_llm=composite,
                       layer_4_provider=None, layer_4_model=None)
        return score

        session, profile=profile, job=job, k=_K_CANDIDATE_BULLETS
    )
    judge_result, skip_reason = await _llm_judge_score(
        session, user_id=user_id, job=job, profile=profile,
        candidate_bullets=candidate_bullets,
        tag_score=tag_score, semantic_score=semantic_score, settings=settings,
    )
    if judge_result is None:
        # LLM failed or no provider — fall back to composite.
        score = JobScore(score=composite, explanation=(
            f"Tag + semantic composite ({composite:.2f}); LLM judge unavailable ({skip_reason})."
        ))
        await _persist(session, job=job, score=score, layers_run=layers_run,
                       judge_skipped=True, judge_skipped_reason=skip_reason or "llm_failed",
                       tag_score=tag_score, semantic_score=semantic_score,
                       composite_pre_llm=composite,
                       layer_4_provider=None, layer_4_model=None)
        return score

    # ── Validation: filter hallucinated suggested_bullets (T9) ────────
    if judge_result.suggested_bullets:
        valid_ids = await _filter_valid_bullet_ids(
            session, user_id=user_id, ids=judge_result.suggested_bullets
        )
        if len(valid_ids) < len(judge_result.suggested_bullets) / 2:
            log.warning("scorer judge hallucinated %d/%d bullet IDs for job %s",
                        len(judge_result.suggested_bullets) - len(valid_ids),
                        len(judge_result.suggested_bullets), job.id)
        judge_result = judge_result.model_copy(update={"suggested_bullets": valid_ids})

    final_score = apply_visa_filter(judge_result, profile, job)
    # source_trust_weight already applied to composite, but LLM score is its own axis.
```
