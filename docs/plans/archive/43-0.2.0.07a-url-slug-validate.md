# 43 · 0.2.0.07a — URL slug-validate (6 scrapers + url_guard helper)

## Goal

Close the two hacker MEDIUMs from PR #102 (Issue #103) by slug-validating every operator-supplied URL component (`tenant`, `site`, `company`) **before** template substitution in all 6 site scrapers, lifted to a single `scraper.url_guard._make_url(template, **slugs) -> str` chokepoint. The fix prevents confused-deputy outbound HTTP (Workday tenant-fragment trick: `tenant="evil.com#"` slips past `is_safe_destination`) and vendor-API path traversal (Lever `company` substitution at path position). Non-exploitable in current single-tenant self-host (attacker = operator), but a multi-tenant cloud blocker per hacker's verdict.

## Why

`is_safe_destination` runs **after** the URL has already been composed, so any user-controlled component that confuses `urlsplit.hostname` (Workday fragment trick) OR distorts the vendor path (Lever slash injection) is invisible to the post-composition guard. The fix shifts the contract one layer up: invalid component → URL is never composed in the first place, so the question of "did url_guard catch it?" doesn't arise. PR #102 review records the empirical bypass (`urlsplit("https://evil.com#.wd1.myworkdayjobs.com/External").hostname == "evil.com"`). ROADMAP row 0.2.0.07a captures the agreed fix shape: slug regex `^[a-zA-Z0-9][a-zA-Z0-9_-]*$`, lift to shared helper. The 6 scrapers already centralize URL composition through `_LIST_TEMPLATE` / `_DETAIL_TEMPLATE` / `_LIST_BASE` constants — single-chokepoint refactor lands cleanly without touching the parse/fetch loops.

## Proposal

One new helper + 6 surgical call-site edits + 1 new exception type + slug-validation tests. No new env var, on-disk path, CLI command, or operational surface. No DB migration. No alembic.

### D.1 New helper in `src/scraper/url_guard.py`

Add at end of file (after `is_safe_destination`):

```python
import re as _re

_SLUG_RE: _re.Pattern[str] = _re.compile(r"^[a-zA-Z0-9][a-zA-Z0-9_-]*$")
"""Slug shape for operator-supplied URL components.

Matches: lowercase + uppercase ASCII letters, digits, underscore, hyphen.
First character MUST be alphanumeric (no leading underscore / hyphen).
Length: 1..N (no upper bound; vendor practice keeps slugs <=64 chars; we don't
enforce that here — the regex's first-char constraint + character class is the
load-bearing rule).

Locked from ROADMAP row 0.2.0.07a per hacker PR #102 recommendation. Confirmed
to fit all 6 vendors empirically:

- Workday tenants: alphanumeric + hyphen (e.g. ``salesforce``, ``adobe``).
- Workday sites: alphanumeric + underscore (e.g. ``External``, ``Adobe_Careers``).
- Greenhouse / Lever / Ashby companies: alphanumeric + hyphen
  (e.g. ``rippling``, ``stripe``, ``shopify``).

Rejects all confusable shapes from PR #102 review:
``"evil.com#"`` (fragment), ``"evil.com?"`` (query), ``"evil.com&for=victim"``
(separator injection), ``"acme/../v0/users"`` (path traversal), ``""`` (empty),
``"a b"`` (whitespace), ``"\x00"`` (null), ``"-leading-hyphen"`` (leading dash),
``"https://x"`` (full URL stuffed as slug).
"""


class InvalidSlugError(ValueError):
    """Raised by ``_make_url`` when a slug-positional kwarg fails ``_SLUG_RE``.

    Subclass of ``ValueError`` so call sites that already catch ``ValueError``
    (or use bare ``except Exception``) compose without code change. The typed
    shape lets new callers distinguish slug-rejection from other URL-layer
    failures when needed.

    Carries ``slug_name`` (kwarg key — e.g. ``"tenant"``) and ``value``
    (the rejected string) as instance attributes for log redaction.
    """

    def __init__(self, slug_name: str, value: str) -> None:
        super().__init__(
            f"invalid_slug:{slug_name}={value!r}"
        )
        self.slug_name = slug_name
        self.value = value


def _make_url(template: str, **slugs: str) -> str:
    """Format ``template`` with slug-validated kwargs.

    Each kwarg value is matched against ``_SLUG_RE`` BEFORE substitution.
    First failure raises ``InvalidSlugError(slug_name, value)``; callers
    catch + log + skip the listing without ever composing the URL.

    Trailing ``is_safe_destination`` call is the SECOND chokepoint:
    even with a clean slug, the composed URL may still resolve into an
    RFC1918 / IMDS host if the operator points a public CNAME at it.
    The two layers compose; the slug regex closes the composition-bug
    attack vector, ``is_safe_destination`` closes the DNS-resolution one.

    NOTE: this helper does NOT call ``is_safe_destination`` itself —
    callers do, immediately after, because the callers also need to log
    the URL-guard rejection with ``safe_url`` redaction (helper has no
    error-reporting surface). The single-chokepoint property is about
    slug validation; ``is_safe_destination`` stays a per-call decision
    so the existing per-stage error reporting in each scraper survives.
    """
    for name, value in slugs.items():
        if not isinstance(value, str) or not _SLUG_RE.match(value):
            raise InvalidSlugError(name, value if isinstance(value, str) else str(value))
    return template.format(**slugs)
```

#### D.1.1 Helper return + raise contract (option matrix)

| Option | Capability | Cost | Risk | Maintenance | Lock-in |
| --- | --- | --- | --- | --- | --- |
| Return `str \| None` (None on reject) | Caller must check + skip | 6 site call sites duplicate `if url is None: continue` boilerplate; redaction inconsistent | Boilerplate drift: a future site might forget the None-check (regression to today's posture) | New `*_companies` consumers can no-op without try/except | Low — easy to flip to raise later |
| Raise bare `ValueError("bad slug")` | Caller's broad `except` already catches | Cheap; matches existing `except Exception` (BLE001) tier-1 pattern | Conflates with other ValueErrors (e.g. `int()` parse errors); loses slug identity in logs | Future caller may want to distinguish — has to grep for the string | Low |
| **Raise typed `InvalidSlugError(ValueError)`** | Typed sentinel for `except InvalidSlugError:`; also matches existing `except ValueError:` / `except Exception:` blocks | One new class (~7 LOC); explicit kind line in error append | Negligible — pure additive | Future scrapers / migrations adopt the same shape | Low |

**Recommendation: typed `InvalidSlugError(ValueError)`.** Subclassing `ValueError` preserves zero-friction composition with the existing tier-1 broad-except pattern (every site already has `except Exception: # noqa: BLE001` blocks for tier-1 fetch failures). The typed shape lets the site's narrow `except InvalidSlugError` precede that broad block + emit a clean `kind=invalid_slug msg={name}=<redacted>` error to `JobScrapeRun.errors[]`, matching the existing `kind=invalid_tenant_spec` shape Workday already uses. Reversal is cheap (the class is a 7-LOC addition). Evidence: `scraper.redaction.safe_exc` is already wired into every site's error-append path; typed exceptions integrate trivially.

#### D.1.2 Where the helper raises (caller-side option matrix)

| Option | Capability | Cost | Risk | Maintenance | Lock-in |
| --- | --- | --- | --- | --- | --- |
| Helper-internal raise; caller catches | One call site per scraper wraps in try/except | Each site gains `try: list_url = _make_url(...) except InvalidSlugError as exc:` (~5 LOC including error append + continue) | Forgotten try/except in a future scraper bubbles to tier-1 broad-except + records the run as FAILED instead of recording the per-listing skip | Pattern matches existing `is_safe_destination` site-level handling | Low — encapsulated |
| **Helper raises; central wrapper in `_BaseSiteScraper`** | One `_compose_list_url(template, **slugs)` shim in `_base_site.py` that try/excepts internally and returns `str \| None`; sites call the shim, treat None as "skip + already-logged" | Sites' edits collapse to: `list_url = self._compose_list_url(self._LIST_TEMPLATE, company=company)` + `if list_url is None: continue` | Slightly hides the failure surface — but `_base_site.py:_maybe_enrich` already centralizes the same pattern for extraction errors | New scraper authors get the right shape by default; helper-only refactor | Low — sites still own the URL templates |

**Recommendation: helper-internal raise + central `_BaseSiteScraper._compose_url(template, **slugs)` wrapper.** Matches the `_maybe_enrich` precedent already in `_base_site.py:46-84` (the wrapper handles `safe_url` + `safe_exc` + `self._errors.append` once; sites just call). Future scrapers (Phase 5+ `+ Add by URL` dispatcher, post-multi-tenant flip) get the right shape by inheritance. Trade-off accepted: the failure path is one level removed from each call site — but the wrapper's error-append carries `stage=list|detail` + `kind=invalid_slug` + `msg=<slug-name>=<redacted-value>` exactly as the existing site-level `is_safe_destination` rejection does, so debugging surface stays identical.

### D.2 New wrapper in `src/scraper/sites/_base_site.py`

Add method on `_BaseSiteScraper`:

```python
from scraper.url_guard import InvalidSlugError, _make_url


class _BaseSiteScraper(ScraperBase):
    # ... existing _maybe_enrich ...

    def _compose_url(
        self,
        template: str,
        *,
        stage: str = "list",
        **slugs: str,
    ) -> str | None:
        """Slug-validate + format ``template`` with ``**slugs``.

        Returns the composed URL on success.

        On ``InvalidSlugError``, appends a tier-1 error to ``self._errors``
        (matching the existing ``is_safe_destination`` rejection shape) and
        returns ``None``. Caller must check ``if url is None: continue``.

        ``stage`` is the SCRAPER_BASE § H.1 stage marker ("list" or "detail").
        """
        try:
            return _make_url(template, **slugs)
        except InvalidSlugError as exc:
            # `safe_url` is for full URLs; for slug rejection we redact the
            # rejected value to <=64 chars + strip control chars via the
            # same `_strip_control_chars` path `safe_exc` uses.
            from scraper.redaction import _strip_control_chars  # type: ignore[attr-defined]

            redacted_value = _strip_control_chars(exc.value)[:64]
            self._errors.append(
                f"stage={stage} url=<unmade:{template[:80]}> "
                f"kind=invalid_slug msg={exc.slug_name}={redacted_value!r}"
            )
            return None
```

`_strip_control_chars` is already factored out of `safe_exc` per plan 32 / `0.2.0.06b`. Re-importing for log redaction matches the existing pattern.
