# 83 · 0.7.0.36 — Delete auto-seed dev user; force first-time signup

## Goal

Remove the auto-seeded `dev@naavik.local` user + `~/.naavik/dev-credentials`
artifact + `NAAVIK_DEV_PASSWORD` env-var + lifespan credential echo. After this
plan, first-time `nix run .#dev` boots an EMPTY database; the user lands on
`/login` (which already auto-promotes the "Sign up" link when the User table
is empty per plan 10c / `0.1.0.30`), creates an account, and onboards from
scratch.

## Why

Owner directive 2026-05-21 (after session-mid observation that the
dev-credentials file wasn't on disk despite `nix run .#dev` running):

> "we need to just force the user to create the account on first time
> instead of seeding a username and password"

Concrete pain points the current design causes:

1. **The dev-credentials file is gated on `not user_existed`** (`db/seed.py:287`).
   Once the dev User row is in the DB, the file is never regenerated on
   subsequent reseeds. Operators who wipe `.naavik/db/` get it back; everyone
   else doesn't. This is the bug the owner hit today.

2. **The pattern is dev-only theater.** Docker / NixOS / Cloud paths never
   write the file (debug=False short-circuit). Only `nix run .#dev` produces
   it. Every other self-hosted-app convention is "first user signs up" — Naavik
   diverges for no real benefit.

3. **The 3-gate condition adds load-bearing complexity** for an artifact most
   operators read once + then `rm` anyway. Three failure modes (file missing,
   file stale, file wiped) are documented in `/setup-help`, RUNBOOK § 2.12,
   README, CLAUDE.md.

4. **First-run-with-real-data isn't blocked** — the resume-upload onboarding
   flow is already in place (Phase 1 Wave 5). Signup → onboarding → profile
   populated. Production-realistic.

## Proposal

Single PR; 1 commit. Breaking change on `nix run .#dev` first-time UX; minor
test surgery; doc updates.

### D.1 Code deletions

#### `flake.nix` (~line 217)

Remove the entire `seed` process-compose step. Resulting orchestrator:
`db-init → db → migrate → app`. The `seed` step + its 60-line env-var-export
block goes away. `app` depends on `migrate` directly, not `seed`.

#### `src/db/seed.py`

Two paths considered:

| Option | Approach | Trade-off |
|---|---|---|
| **D.1.a** | Delete `seed.py` entirely; tests rewire to use `db/sample_data.py` accessors directly (already in-memory per plan 60) | Cleanest cut. ~14 test-file updates. |
| **D.1.b** | Keep `seed.py` as a manual operator tool but strip the User seed + dev-credentials write. Operator can run `uv run python -m db.seed --owner-email=X` post-signup to backfill demo fixtures into their account. | Preserves demo-data option but adds a config path. Out-of-scope for this plan. |

**LOCKED: D.1.a.** Delete `seed.py`. If demo fixtures become valuable again,
a future plan can add a post-signup "Load demo data" button as a Settings UI
surface (consistent with the post-vault sunset pattern).

Concretely deleted: `src/db/seed.py`, `tests/test_seed.py`, every
`from db.seed import seed` callsite (test fixture re-wiring per D.2 below).

#### `src/main.py`

Delete `_echo_dev_credentials_after_start()` (~lines 79-108) + the WARN log
in lifespan (~lines 62-78) that fires when `dev_credentials_present=False`.
Replace with a single INFO line on first boot:

```python
log.info("dev server up at http://localhost:8000 — visit /signup to create your account")
```

#### `src/services/first_run.py`

36-65 (the "no NAAVIK_DEBUG AND user(s) seeded AND no dev-credentials" 3-
condition gate — moot once the artifact is gone).

#### `src/ui/routes/auth.py` + `_login.html`
