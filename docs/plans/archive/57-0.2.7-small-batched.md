### Item 2 — Onboarding offline retry buffer (0.2.7.13, LOW)

**Rationale.** Filed via INTERACTIONS.md § H.3 ("Phase 1.x optional; not blocking MVP") — queue retries in a small client-side buffer on `htmx:sendError` and replay on `online` event. Today the onboarding form (step 3 review, `src/ui/templates/pages/_onboarding_step_review.html`) posts to `/api/v1/profile/from-extraction` via HTMX (`hx-post` at line 48); per-field autosave at `src/ui/templates/pages/profile_edit.html` uses the same HTMX wiring. Offline = `htmx:sendError` fires + the swap silently no-ops. User loses unsaved edits if they navigate away.

Buffer in IndexedDB (not localStorage — autosave payloads can include large bullets/answers; 5MB localStorage cap is close to the realistic upper bound, IndexedDB has effectively unbounded quota subject to browser policy). Retry on `online` event AND on next page-load-after-reconnect (covers tab-closed-before-reconnect). Max 5 retries per request with exponential backoff (1s / 2s / 4s / 8s / 16s, then drop). Surfaces a toast on final drop using the existing OOB toast pattern.

**Scope.** Onboarding screen (`/onboarding/*`) only for this row. Profile editor + Settings tabs share the same HTMX autosave pattern but are out-of-scope; once the IndexedDB queue module exists, applying it to profile-edit is a follow-up (file as `0.2.7.13a` if needed). Plan 56 / `0.2.7.21` already noted "could fold with 0.2.7.05" precedent for cosmetic deferral.

**Files.**

- `src/ui/static/offline_queue.js` — new file. ~80 LOC. Exports an IIFE that:
  1. On load: opens IndexedDB database `naavik_offline_queue` (object store `pending`, keyPath `id`, autoIncrement).
  2. Listens for `htmx:sendError` events. Filters to mutating requests (`hx-post` / `hx-put` / `hx-patch` / `hx-delete`) whose path starts with `/api/v1/profile` OR `/api/v1/onboarding`. Captures request method, URL, headers (including X-CSRF-Token if present), body, target element id, retry-count (0). Writes to `pending` store.
  3. On `online` event AND on `DOMContentLoaded` (when `navigator.onLine === true`): reads all rows from `pending`, fires them via `fetch()` with `Content-Type` matching original. On 2xx: deletes the row. On non-2xx OR network error: increments retry-count, re-stores with exponential-backoff delay (setTimeout schedule). On retry-count === 5: deletes row, dispatches `naavik:offline-queue-drop` event carrying the original URL + payload so the page can surface a toast via the existing OOB pattern.
  4. Idempotency guard: `window._naavikOfflineQueueLoaded` (mirrors `base.js` pattern at `src/ui/static/base.js:14-23`) so HTMX `hx-boost` swaps don't re-attach listeners.
  5. The script is gated to `/onboarding/*` pages by checking `window.location.pathname.startsWith('/onboarding')` at the top — keeps the IndexedDB open cost off other pages until the follow-up extends it.

- `src/ui/templates/components/auth_shell.html` (or whichever shell `onboarding.html` extends — verify; `pages/onboarding.html:1` shows `{% extends "components/auth_shell.html" %}`) — add `<script src="{{ url_for('static', path='/offline_queue.js') }}" defer></script>` AFTER the existing base.js script tag, gated by `{% if request.url.path.startswith('/onboarding') %}` if the shell is shared. Verify by reading `auth_shell.html` first; if the shell unconditionally loads base.js, gate the new script via the if-block.

- `tests/test_onboarding_offline_queue.py` — new file. ~50 LOC. Three Playwright tests using the project's existing Playwright surface (engineer can verify the pattern from `tests/test_settings_observability_dashboards.py` or similar; if no Playwright tests exist for onboarding, fall back to unit-testing the JS module via `pytest-playwright` headless OR a `playwright/sync_api` `page.add_script_tag` approach):
  1. `test_offline_queue_stores_failed_submit` — load `/onboarding/3`, simulate `navigator.onLine = false` via Playwright's `page.context.set_offline(True)`, trigger an autosave field-blur, assert IndexedDB `pending` store has 1 row.
  2. `test_offline_queue_replays_on_online` — same setup, then `page.context.set_offline(False)`, trigger `window.dispatchEvent(new Event('online'))`, assert the request fires (via `page.expect_request`) and IndexedDB row is deleted.
  3. `test_offline_queue_drops_after_5_retries` — mock the endpoint to return 500 five times, assert the row is removed and a `naavik:offline-queue-drop` event fired.

  If Playwright is too heavy for the engineer's plumbing, fall back to unit tests via a minimal jsdom-flavored harness OR explicitly defer all three tests to a Playwright follow-up row (`0.2.7.13b`) and ship just the JS module + a one-line README mention. Engineer chooses based on existing Playwright wiring; deviations log captures the choice.

**LOC.** ~80 LOC JS + ~5 LOC HTML + ~50 LOC tests (or ~10 LOC deferral comment). **Risk.** MEDIUM — IndexedDB API is async/callback-heavy; subtle bugs around transaction lifetime + `onerror` handlers are common. Mitigations: (a) keep the module ~80 LOC by avoiding wrappers; use raw `indexedDB.open` + `IDBTransaction` directly per MDN. (b) The idempotency guard prevents double-listener attachment under `hx-boost`. (c) Path gate (`startsWith('/onboarding')`) keeps the IndexedDB open cost off other pages so a regression in the module can't poison Profile / Settings traffic. (d) Manual QA: nix run .#dev, navigate to /onboarding, devtools Network tab "Offline" toggle, edit a field, assert no console error + IndexedDB inspector shows the row, then toggle back online and assert the row clears.

### Item 3 — Portfolio API versioning (0.2.7.15, LOW)

Future schema changes (renamed fields, added/removed fields, EEO/visa policy changes) need a versioning surface so the portfolio site can pin to a known shape. Add `?version=v1` literal-string query param now; default to `v1` if absent; reject unknown values with 400. Reserves `v2` for the next iteration without breaking existing crypticsoul.dev fetches.

**Decision locked** (per dispatch context): literal-string version param (not numeric `v=1` integer — string is more idiomatic for API versioning, matches `/api/v1/` URL-segment convention). **Files.**

The handler body doesn't branch on `version` today — the Literal acts as a validation gate + reserves the surface. Add a one-line comment: `# version=v1 is the only shape today; v2 will branch the payload-build step at line 92.` Update the docstring summary to note the version param.
