### D.1 — Scheme allowlist: `pydantic.HttpUrl` on `Crawl4AIClient.fetch_html(url)`

**Hacker finding (MEDIUM).** `Crawl4AIClient.fetch_html` currently accepts any `str` and passes verbatim to `AsyncWebCrawler.arun(url=url, ...)`. Crawl4AI does not enforce a scheme allowlist at its boundary. A malicious or buggy scraper subclass — or an attacker-controlled value flowing through `ScrapeQuery.company_filter` or `keywords` into a URL composer in `0.2.0.07` — could submit `file:///etc/passwd` (LFI) or `gopher://internal-host:6379/...` (SSRF) and have Chromium dereference it.

**Locked: use `pydantic.HttpUrl` for both the parameter type AND the validation point.**

```python
# src/scraper/crawl4ai_client.py — fetch_html signature change
from pydantic import HttpUrl, TypeAdapter

_HTTP_URL_ADAPTER: TypeAdapter[HttpUrl] = TypeAdapter(HttpUrl)

async def fetch_html(self, url: str) -> str | None:
    try:
        validated = _HTTP_URL_ADAPTER.validate_python(url)
    except ValidationError as exc:
        log.warning("crawl4ai fetch rejected: url=%s reason=%s", _safe_url(url), _safe_exc(exc))
        return None
    await self._respect_rate_limit()
    async with AsyncWebCrawler(config=self._browser_config) as crawler:
        result = await crawler.arun(url=str(validated), config=self._run_config)
    ...
```

`pydantic.HttpUrl` accepts `http` and `https` only (verified against pydantic.dev/docs/validation/latest/api/pydantic/networks/ — pre-built type with `allowed_schemes=['http', 'https']` baked in). Rejects `file://`, `ftp://`, `gopher://`, `data://`, malformed strings, and missing schemes.

**Why both http + https (not pure https):** Greenhouse / Lever / Ashby boards are HTTPS in production, but localhost test fixtures and dev orchestrator usage land at `http://localhost:8000/...` plenty. Restricting to pure https would force every test that mocks a fake board URL through a custom URL type — over-engineering for the threat model (the threat is non-HTTP schemes that hit chromium-internal resolvers, not http-vs-https TLS).

**Option matrix.**

| Option | A — `pydantic.HttpUrl` via `TypeAdapter` (chosen) | B — `Annotated[Url, UrlConstraints(allowed_schemes=['https'])]` (pure-https) | C — manual `urlparse` + `scheme in {"http","https"}` check |
|---|---|---|---|
| Capability | Pre-built; covers http + https + IDN + length cap + format checks | Same but pure-https only | Crude string check; misses IDN / format / `javascript:` edge cases |
| Cost | ~5 LOC at module top + signature unchanged externally | ~8 LOC (need `Annotated` import + custom type alias) | ~5 LOC inline |
| Risk — security | LOW — pydantic well-tested | LOW — pydantic well-tested | MEDIUM — `urlparse("file:///etc/passwd").scheme == "file"` works, but no IDN normalization |
| Maintenance | Standard pydantic v2 idiom | Same | Hand-rolled validation drifts from pydantic conventions |
| Test surface | Single TypeAdapter raises ValidationError on hostile schemes | Same | Need to enumerate every hostile scheme by hand |
| Recommendation | ✅ chosen — pydantic-native, covers more than the immediate threat | Rejected — http-only restriction breaks localhost dev | Rejected — reinvents pydantic's URL validator |

**Trade-off accepted:** the wrapper still calls `AsyncWebCrawler.arun(url=str(validated), ...)` — i.e. we re-stringify after validation, because Crawl4AI 0.8.6's `arun(url=...)` parameter is typed `str`, not `HttpUrl`. Stringification is round-trip-safe for `HttpUrl` (`str(HttpUrl("https://x.com/y")) == "https://x.com/y"`).

### D.2 — Redaction surface: new module `src/scraper/redaction.py`

**Hacker finding (MEDIUM).** `JobScrapeRun.errors[]` is `list[str]` persisted to a Postgres `ARRAY(String)` column (`src/models/job_scrape_run.py:65-68`). `scraper_service.run_scraper` writes strings like:

```
stage=upsert url={raw_job.source_url} kind=upsert_failure msg={type(exc).__name__}: {exc!s}
stage=invocation kind=fatal msg={type(exc).__name__}: {exc!s}
```

`source_url` is uncapped; `{exc!s}` invokes the exception's `__str__` which often dumps the full SQL row, full stack repr, or the request body. Today the operator UI doesn't exist; once `0.2.0.11` (Discover UI) ships and the future `/api/v1/scrape-runs` endpoint lands, anyone with operator-token read access reads these strings. URL query-strings carry tokens; exception messages carry secrets.

**Locked: new module `src/scraper/redaction.py` with two pure functions.** Used by `scraper_service.py` (3 callsites) AND `crawl4ai_client.py` (3 callsites: `log.warning` in `fetch_html` failure path + 2 in `stream_many`).

**Option matrix (where the helpers live).**

| Option | A — new module `src/scraper/redaction.py` (chosen) | B — inline in `src/services/scraper_service.py` | C — `@staticmethod` on `JobScrapeRun` model |
|---|---|---|---|
| Capability | Pure functions; importable from both `scraper/crawl4ai_client.py` AND `services/scraper_service.py` | Functions accessible to scraper_service only; crawl4ai_client must import upward across `services/` boundary | Lives on the SQLModel that owns the column |
| Cost | New file (~20 LOC + module docstring) | No new file; ~10 LOC inline | No new file; ~10 LOC on the model |
| Risk — layering violation | LOW — `scraper/` is below `services/` in the dep graph | HIGH — `src/scraper/` cannot import `src/services/` (it would create a cycle: `services/scraper_service.py` already imports `from scraper.base import ScraperBase`) | MEDIUM — bloats the SQLModel with non-persistence concerns |
| Risk — drift | LOW — both writer paths import the same two functions | MEDIUM — `crawl4ai_client.py` would re-implement them, drift over time | LOW |
| Test surface | `tests/test_scraper_redaction.py` — pure-function tests, fast, no fixtures | Tests bundled into `test_scraper_service.py` (already 11KB) | Tests bundled into a future `test_job_scrape_run.py` |
| Reusability for future scrapers | Yes — `0.2.0.07` subclasses import as needed when building their own error strings | No — subclasses would have to reach into `services/` | Awkward — would need to import the model just for the static method |
| Recommendation | ✅ chosen — clean layering, testable in isolation, reused by both writer paths | Rejected — forces a `services → scraper` import inversion | Rejected — couples redaction policy to the persistence model |

**Module shape (skeleton signature — engineer writes the body):**

```python
# src/scraper/redaction.py
"""Log/error-string redaction helpers used by the scraper layer.

Both `scraper_service.run_scraper` (writes `JobScrapeRun.errors[]`) and
`crawl4ai_client.{fetch_html, stream_many}` (writes `log.warning`) route URL
+ exception material through `_safe_url` + `_safe_exc` before persisting or
logging. Per `docs/design/SCRAPER_BASE.md § H.4` (added 0.2.0.06a).
"""

from __future__ import annotations

from urllib.parse import urlsplit, urlunsplit

_MAX_EXC_MSG_LEN = 200


def safe_url(url: str | None) -> str:
    """Strip query string + fragment; preserve scheme + host + path.

    Tokens live in query strings (`?token=...&apply_now=true`); job IDs
    live in path (`/jobs/12345`) and are the value of the log. Returns
    `"<no-url>"` for None / empty / unparseable input.
    """


def safe_exc(exc: BaseException) -> str:
    """Format `<ClassName>: <truncated-msg>` capped at 200 chars total payload.

    Drops `__traceback__`, `args` tuple, `__cause__`. Class name preserved
    intact so operator grep stays useful; message slice prevents secret-leak
    from `f"{exc!s}"` dumps of SQL rows / request bodies / 4xx HTML pages.
    """
```

### D.3 — `safe_url` strip rule: query + fragment only

Two slices to consider stripping from a logged URL:

| Component | Strip? | Why |
|---|---|---|
| scheme (`https`) | NO | Diagnostic value; non-secret; useful when SSRF blocker fires |
| host (`linkedin.com`) | NO | Diagnostic value; non-secret; useful for "which scraper failed" |
| path (`/jobs/12345/`) | NO | The path **is** the value — job IDs encode there for LinkedIn / Greenhouse / Lever / Ashby. Stripping the path makes the log unusable for forensics |
| query string (`?token=abc&applied=1`) | **YES** | Tokens + session IDs + apply-now triggers live here. LinkedIn `?_l=en_US&trk=...` carries fingerprinting cookies. Always strip |
| fragment (`#applicant-info`) | **YES** | Rarely useful; sometimes carries OAuth tokens in `#access_token=...` redirects. Always strip |

The rule is **structural** (split → drop two components → recombine) not a regex blacklist; no pattern can leak through. `urllib.parse.urlsplit` + `urlunsplit` is the canonical Python stdlib idiom — already-imported tax-free.

**Edge cases:**
- `None` / `""` → return literal `"<no-url>"` (never raise — these helpers run inside exception handlers; raising hides the original error).
- Unparseable garbage (`"not a url"`) → `urlsplit` returns `(scheme='', netloc='', path='not a url', ...)`; we return the path slot (so the log still shows what the offending input looked like) but no scheme prefix.
- `urlsplit` doesn't raise on hostile input — stdlib is robust here.

### D.4 — `safe_exc` rule: class + message slice

Locked: `f"{type(exc).__name__}: {str(exc)[:200]}"`.

| Component | Keep? | Why |
|---|---|---|
| Class name (`TimeoutError`, `Crawl4AIRateLimitError`, `IntegrityError`) | YES | Primary diagnostic axis — grep-friendly; LOW info leak (class names are public API) |
| Message (first 200 chars) | YES, capped | Truncation prevents `IntegrityError: (psycopg.errors.UniqueViolation) duplicate key value violates unique constraint "ix_job_user_source_extid" DETAIL: Key (user_id, source, external_id)=(1, 'linkedin', '12345') already exists. [SQL: INSERT INTO job ...]` from dumping the row in full |
| `.args` tuple | NO | Often contains the row dump verbatim |
| `__traceback__` | NO | Not a string concern — no caller writes `str(exc.__traceback__)` today, but the helper closing the door is cheap insurance |
| `__cause__` chain | NO | Same |

**200 chars** is the budget. Median tracebacks fit; pathological cases truncate. If 0.2.0.07 surfaces a class of exception where 200 chars consistently truncates useful payload, the limit lifts in a follow-up — log a knowledge entry rather than guess now.

**Tradeoff accepted:** intentionally NOT calling `repr(exc)` because some exception classes implement `__repr__` to dump full internal state (asyncpg `Record`, sqlmodel `Job`). `str(exc)` defers to `__str__` which is the operator-readable summary.

### D.5 — `max_listings` cap: `le=10_000`

```python
# src/scraper/types.py
class ScrapeQuery(BaseModel):
    ...
    max_listings: int = Field(default=200, ge=1, le=10_000)
```

LinkedIn typical: ~1K listings per query (25/page × 40 pages). Greenhouse / Lever / Ashby: ~hundreds per company. 10K is 10× headroom for the largest realistic scrape. 100K would let a runaway cron consume hours of Chromium time + leak DB writes. 1K would clip realistic LinkedIn use. **10K is the right ceiling.**

`ge=1` lower bound prevents `max_listings=0` (silent no-op) and negative values.
