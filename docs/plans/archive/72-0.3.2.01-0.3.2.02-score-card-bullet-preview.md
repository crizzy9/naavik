# 72 · 0.3.2.01 + 0.3.2.02 · Score card + bullet selection preview UI polish

## Goal

Ship the two highest-impact 0.3.2 visual polish surfaces in one PR (they share substrate + designer subdispatch):
- **0.3.2.01 — Score card component + per-dim bar component**: refine `score_card.html` (NEW container partial) + `match_breakdown.html` (existing) + `score_circle.html` (existing) per the Discover + `/jobs/{id}` mockup contract. Surfaces the "why" + "what's missing" + "what was generated" overlay per 0.3.2 goal.
- **0.3.2.02 — Bullet selection preview UI**: Discover · review & apply (SCREENS.md § 8) gets a color-coded shipped-vs-dropped bullet list w/ inline rationale. Implements the per-bullet "selected because X / dropped because Y" affordance.

`Type: design` because both surfaces refine the visual contract; mockups graduate into `docs/design/SCREENS.md` § 7 + § 8 updates + `docs/design/COMPONENTS.md` if any new partials.

## Why

Per ROADMAP § 0.3.2:
> **Goal:** Every UI surface that consumes `match_breakdown` or `score` honors the mockup contract; user sees "why" + "what's missing" + "what was generated."

Current state:
- `score_circle.html` ships (0-100 number in a colored ring, 4-tier color thresholds). Used by `swipe_card.html`.
- `match_breakdown.html` ships per-dim bars (tag → 0.0-1.0 with 4-tier color). Used by `swipe_card.html` + `apply_topbar.html`.
- The "why" / "what's missing" / "what was generated" overlay is MISSING. `Job.match_breakdown` JSONB carries `{strengths, gaps, visa_note, suggested_bullets, ...}` (18-key schema per plan 65); the UI doesn't render them.
- Discover · review & apply (`pages/discover_review.html` + `pages/_discover_review_workspace.html`) renders tailored bullet selection but doesn't surface the rationale (the LLM judge's bullet-selection reasoning from `JobScore.suggested_bullets`).

Owner directive (master plan 68 § Context): plans 72/73/74 are the polish layer that lands AFTER plan 69 (data flow). Plan 72 is highest-impact (2 rows merged).
