# 44 · 0.2.0.11b — CSRF on `/api/v1/discover` save/skip/auto-submit

## Goal

Close the MEDIUM hacker finding from PR #112 by adding `Depends(require_csrf)` to the three swipe-mutation endpoints — `post_skip` (`src/ui/routes/discover.py:96`), `post_save` (`:109`), `post_auto_submit` (`:123`) — mirroring the existing canonical `post_change_password` pattern at `src/api/auth.py:283-291`. The HTMX base layer already injects the `X-CSRF-Token` header (`src/ui/templates/base.html:28`) so honest UI callers stay unaffected; this fix shuts the cross-origin POST surface that the 0.2.0.11 wiring of `_job_detail_body.html` Save/Skip buttons widened.

## Why

ROADMAP row `0.2.0.11b` (line 202) filed via PR #112 hacker review (Issue #114). Plan 36 (`0.2.0.11`) wired `_job_detail_body.html:160,168` Save/Skip POSTs into existing endpoints that pre-dated CSRF (the fake-session-substrate kept them effectively private). With the Job detail page now serving HTML to any authenticated browser, the lack of `require_csrf` lets a malicious cross-origin form forge swipes against a logged-in user. The fix is mechanical — one `_csrf: None = Depends(require_csrf)` parameter per endpoint — but it tightens a real, browser-exposed mutation surface. Part (b) of the ROADMAP row (migrate `db.sample_data` → `job_service.list_jobs` with `user_id` boundary) is gated on fake-session retirement and is **deferred** (§ Out of scope below). `docs/design/JOB_UI.md § E.4` (just graduated PR #134) explicitly forward-points to this plan: "The `0.2.0.11b` row tightens these endpoints with `Depends(require_csrf)`."

## Proposal

### D.1 — Add `Depends(require_csrf)` to three endpoints

File: `src/ui/routes/discover.py`

Import the dep at module top alongside existing imports:

```python
from api.auth import require_csrf
```

Then add `_csrf: None = Depends(require_csrf)` to each of the three handler signatures. The parameter ordering follows the existing canonical exemplar at `src/api/auth.py:290` (CSRF dep declared after the auth + session deps); FastAPI evaluates all `Depends(...)` resolutions and short-circuits on the first `HTTPException`, so logical ordering matters only for readability.

```python
# src/ui/routes/discover.py:95-105 (post_skip)
@router.post("/api/v1/discover/{job_id}/skip", response_class=HTMLResponse, name="discover_skip")
async def post_skip(
    request: Request,
    job_id: int,
    fail: Annotated[str | None, Query()] = None,
    _user: User | None = Depends(require_authed_session),
    _csrf: None = Depends(require_csrf),
):
    ...

# src/ui/routes/discover.py:108-115 (post_save)
@router.post("/api/v1/discover/{job_id}/save", response_class=HTMLResponse, name="discover_save")
async def post_save(
    request: Request,
    job_id: int,
    _user: User | None = Depends(require_authed_session),
    _csrf: None = Depends(require_csrf),
):
    ...

# src/ui/routes/discover.py:118-131 (post_auto_submit)
@router.post("/api/v1/applications/{job_id}/auto-submit", response_class=HTMLResponse, name="discover_auto_submit")
async def post_auto_submit(
    request: Request,
    job_id: int,
    _user: User | None = Depends(require_authed_session),
    _csrf: None = Depends(require_csrf),
):
    ...
```

Three signature edits. Zero behavior change for honest UI callers (HTMX already sends the header via `base.html:28`).

### D.2 — Update existing tests broken by the new gate

Three pre-existing tests POST to these endpoints **without** matching CSRF cookie + header, which means they'll get 403 from the new gate. Update each to set the matching pair:

**File: `tests/test_stub_endpoints.py:206-229`**

Three failing tests (`test_discover_skip_returns_swipe_card`, `test_discover_skip_fail`, `test_discover_save_returns_swipe_card`, `test_auto_submit_creates_draft`). Add a small helper at file top + thread `cookies=` + `headers=` into each `client.post(...)` call. Use the same `cookies={"naavik_csrf": tok}, headers={"X-CSRF-Token": tok}` shape that `test_auth.py:415-420` uses.

**File: `tests/test_auth_gate.py:144-150, 199-204`**

Two callsites: `test_ui_route_discover_save_403_when_flagged` (line 145) + the `test_fake_session_caller_unaffected_across_groups` discover probe (line 200). Add matching CSRF cookie + header to both POSTs so the gate under test (auth flagged-user check / fake-session pass-through) is reached, not short-circuited by CSRF 403.

The `test_unauthenticated_caller_gets_401_across_groups` sweep (line 248+) does not POST to the discover endpoints, so it stays untouched.

### D.3 — Add new CSRF-gate tests (mirror `change-password` pattern)

File: `tests/test_discover_csrf.py` (new). One reject + one accept per endpoint, exactly mirroring `test_auth.py:342-426`. Use the same `app.dependency_overrides[get_current_user]` + `app.dependency_overrides[require_authed_session]` pattern to bypass auth so each test exercises the CSRF dep in isolation. Six tests total (3 reject + 3 accept). Reject case asserts `403` + `"CSRF" in r.text`. Accept case asserts `r.status_code != 403` (success short-circuits at the sample_data layer; we don't need to assert the full 200 swipe response — only that CSRF is not the rejection cause).
