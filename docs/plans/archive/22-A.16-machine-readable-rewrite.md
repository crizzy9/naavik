# 22 · A.16 — Machine-readable wording rewrite of agent-system files

## Goal

Rewrite the four `.claude/` instruction-file groups — `agents/*.md` (6), `skills/*/SKILL.md` (~34), `commands/*.md` (15), `hooks/*` prose comments (1 file with prose) — into a denser, machine-first style so the per-dispatch context cost drops by 30–50%. Strip prose padding (articles, "please", conversational hedges, redundant elaboration), promote bullets + tables + file:line refs over paragraphs, keep imperative voice, preserve every load-bearing structural element (skill `description` TRIGGER phrases, frontmatter YAML, operating-loop step numbers, the 9 PLAYBOOK categories, anti-pattern + FORBIDDEN sections, trace event grammar, examples that illustrate edge cases). One PR, one squash commit. Also folds in **A.17a (#67)**: widen `scripts/agent-memory.sh:119` `ALIASES_RE` from `^[a-z0-9 .,/_-]*$` to `^[a-zA-Z0-9 .,/_#-]*$` + one positive test for uppercase + `#` admit (existing seeded knowledge entries fail re-record otherwise).

## Why

These files load on **every** subagent dispatch + skill auto-invocation. Measured baseline: **49.4k words ≈ 88k tokens** across the four groups; a `/build` cycle today re-ingests most of that 3–5× (manager dispatch → architect dispatch → engineer dispatch → hacker dispatch → devops dispatch, each pulling its own agent prompt + 3–5 auto-triggered skills). Compression that preserves semantics is pure win — fewer tokens for the same understanding, larger residual budget for the actual task, smaller blast radius when a future change widens the corpus. User directive 2026-05-17: *"make sure our wording everywhere other than docs is machine readable… minimizes tokens while conveying the same information more efficiently in a way that you can understand it best. in the end it's all about you."* Doc files (AGENTS.md, ROADMAP.md, CLAUDE.md, README.md, DESIGN.md, `docs/**`) stay prose-readable — the human is the primary reader there.

### Compression strategy catalog

| # | Strategy | DO apply to | DO NOT apply to | Example |
|---|---|---|---|---|
| 1 | **Drop articles** (the/a/an) where unambiguous. | All file groups. | Skill `description:` TRIGGER phrases (auto-loader matches substrings); frontmatter YAML field names. | "Read the file" → "Read file"; "The script is the sole writer" → "Script is sole writer". |
| 2 | **Bullets > paragraphs** when content enumerates. | Agents/skills/commands. | Identity-invariant paragraphs (manager's `# Identity invariant`, architect's `# Reasoning depth`) — those are single load-bearing sentences. | "First, do X. Second, do Y. Third, do Z." → "1. X / 2. Y / 3. Z". |
| 3 | **Imperative voice**, drop "please/kindly/you should/you must". | All file groups. | FORBIDDEN sections (keep "MUST NOT" / "DO NOT" — they're enforcement, not politeness). | "Please always invoke the skill first" → "Invoke skill first". |
| 4 | **Tables for enumerated lists** when columns repeat. | Agents (intent decoding, anti-patterns); skills (worked-examples comparisons). | Single-column lists ≤ 5 items (overhead exceeds savings). | "X applies when A, B, C. Y applies when D, E, F. Z applies when G, H, I." → 3-row table. |
| 5 | **File:line refs over prose pointers.** | All file groups. | First mention of a file in a SKILL body (need full context). | "the function at line 119 of scripts/agent-memory.sh" → "scripts/agent-memory.sh:119". |
| 6 | **Drop redundant elaboration** ("This is critical because…", "Why this exists" preambles when already stated). | Agents/skills. | Rationale that names a specific historical regression (e.g. `aa2f6a0` workflow miss, PR #46/#47 duplicates) — those preserve institutional memory and ARE load-bearing. | "This is non-negotiable; it codifies AGENTS.md § Single-doc-tracking." (if § already cited 3 lines above) → drop. Keep the § cite once. |
| 7 | **Collapse repeated headings** within one file. | Skills with overlapping sections. | Frontmatter; `## When to invoke` / `## When NOT to invoke` (load-bearing skill grammar). | "## Step 1 — Scan / ## Step 2 — Reject / ## Step 3 — Document" → "## Steps" with `1. / 2. / 3.` numbered list. |
| 8 | **Code-block over prose** for shell incantations + grep patterns. | Skills with shell examples. | Commentary that explains WHY a flag exists. | "Run grep with the -nE flags against the changed files, like this: grep -nE …" → fenced code block alone. |
| 9 | **Cross-ref consolidation** — replace 5 file-path mentions with one `Canonical references` section. | Skills + agent prompts. | Mentions within examples (they document the example, not the agent). | (per-skill — see hacker-pr-security-checklist baseline for the pattern). |

**Key transformations** (apply each in order):

- **Preserve verbatim**: `---` frontmatter block including the full `description:` line (TRIGGER phrases — auto-loader matches them; truncating could disable the skill); every `## When to invoke` heading + bullet list (also auto-loader heuristic); every `## When NOT to invoke` + `## Forbidden during invocation` heading + content; every shell/code block (the literal incantations).
- **Compress aggressively**: Opening prose paragraph ("X is on a hard sunset track" → bullet under `## Why`); multi-paragraph `## Step N` sections → single `## Steps` heading with `1./2./3.` numbered list; redundant "This is critical because…" + "Why this exists" → drop once already justified in description; `## Canonical references` lists → 1-line bullets with `file.md:section` refs only (no inline reasoning).
- **Per-skill audit**: open file → count baseline words → identify the 1–2 largest paragraphs → rewrite → re-count. If reduction < 30%, identify why and either compress further or accept (some skills, e.g. naavik-vault-sunset-guard, are paragraph-thick by design).
