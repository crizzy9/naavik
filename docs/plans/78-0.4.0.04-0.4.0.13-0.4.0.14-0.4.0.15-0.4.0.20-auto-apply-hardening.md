# 78 · 0.4.0.04 + 13 + 14 + 15 + 20 — Auto-apply hardening cluster

## Goal

Five auto-apply quality improvements shipped together:

- **0.4.0.04 refinement (M3+M4):** belt-and-suspenders score-threshold
  gate in `process_auto_apply_queue` + consumption of
  `Settings.auto_apply_adapter_confidence_threshold` (previously
  shipped but unused; was filed as `0.8.0.17`).
- **0.4.0.13:** per-board daily caps via JSONB on Settings.
- **0.4.0.14:** explicit pause/resume — per-job toggle on Discover +
  global "drain queue to SAVED" button when auto-apply flips OFF.
- **0.4.0.15:** sponsorship-friendly visa chip on Discover cards.
- **0.4.0.20:** auto-apply dry-run mode for threshold tuning.

## Why

The auto-apply substrate works end-to-end but has 5 gaps surfaced in
`docs/design/research/0.4.0-AUDIT.md § C`:

1. **M3 — Score-threshold gate:** cron doesn't re-check
   `Job.score >= Settings.auto_apply_score_threshold` before dispatch.
   Threshold gating only happens upstream at right-swipe time.
   Race: Job re-scored later by `score.recompute_stale` cron with
   lower score — DRAFT already queued — submits anyway.
2. **M4 — Adapter-confidence threshold:** Settings column exists
   (`auto_apply_adapter_confidence_threshold = 0.7`) but
   `submit_draft` never compares to `SubmissionResult.confidence`.
3. **Per-board rate limit:** Auto-apply daily cap is global per user.
   Submitting 50 to LinkedIn in 1 hour → account ban risk.
4. **Pause/resume:** Operator can disable globally but queued DRAFTs
   stay queued. Per-job opt-out doesn't exist.
5. **Dry-run:** No safe way to trial threshold tuning without real
   submissions.

Plus **0.4.0.15 visa chip** surfaces existing `Job.visa_restrictions`
data on Discover so an H1B operator can quick-skim feed for
H1B-compatible jobs (no behavioral change; pure UX).

## Proposal

Single PR; 5 commits (one per gap). New Alembic migration 0017
(additive). New env vars: NONE. New CLI commands: NONE. New
on-disk paths: NONE.

### D.1 Commit 1 — M3 score-threshold belt-and-suspenders

`src/services/application_service.process_auto_apply_queue` —
extend the per-row gate (~line 715) to check:

```python
if job.score is None or job.score < s.auto_apply_score_threshold:
    log.info(
        "auto-apply skipped %s: score %s below threshold %s",
        application.id, job.score, s.auto_apply_score_threshold,
    )
    # Pull out of queue — re-queue when score recomputes above threshold.
    job.queue_state = JobQueueState.SAVED
    job.updated_at = datetime.now(UTC)
    session.add(job)
    continue
```

Mirrors existing per-failure-class queue-flip pattern. ~10 LOC + 2
tests.

### D.2 Commit 2 — M4 adapter-confidence threshold consumption

`src/services/ats/base.py` — verify `SubmissionResult` has
`confidence: float = 1.0` (it does per plan 63). HTTP adapters
already always emit 1.0; Generic adapter emits LLM-form-fill
confidence.

`src/services/application_service.submit_draft` — after dispatch
succeeds, BEFORE flipping `application.status = APPLIED`:

```python
if result.confidence < user_settings.auto_apply_adapter_confidence_threshold:
    # Revert to DRAFT + record as failure
    await _record_failure(
        session, application,
        kind="low_confidence",
        message=f"adapter confidence {result.confidence:.2f} < threshold {user_settings.auto_apply_adapter_confidence_threshold:.2f}",
        raw={"confidence": result.confidence, **(result.raw or {})},
        settings=user_settings,
    )
    return application  # Stays DRAFT
```

~15 LOC + 4 tests (HTTP adapter passes, low-confidence Generic
rejected, threshold tuning via Settings, postmortem path populated).

**`src/services/application_service.process_auto_apply_queue`:** add
per-board running counter; check before dispatch:

```python
per_board_today: dict[tuple[int, str], int] = {}

async def _per_board_today(uid: int, board: str) -> int:
    key = (uid, board)
    if key in per_board_today:
        return per_board_today[key]
    today_start = datetime.combine(datetime.now(UTC).date(), datetime.min.time(), tzinfo=UTC)
    c = (await session.exec(
        select(func.count(Application.id)).where(
            Application.user_id == uid,
            Application.board == ApplicationBoard(board),
            Application.applied_at >= today_start,
        )
    )).one()
    if isinstance(c, tuple): c = c[0]
    per_board_today[key] = int(c or 0)
    return per_board_today[key]
```

When `Settings.auto_apply_per_board_daily_caps[board.value]` is set,
check and skip with `cap_class="per_board"` tag.

### D.4 Commit 4 — Pause/resume (0.4.0.14)

**Per-job:** new HTMX action on Discover card —
`POST /_fragments/discover/{job_id}/pause-auto-apply` flips

Confirmation modal. ~20 LOC + 3 tests.

### D.5 Commit 5 — Dry-run mode (0.4.0.20)

**Settings:**

```python
auto_apply_dry_run: bool = Field(default=False)
```

(included in Alembic 0017)

**`process_auto_apply_queue`:** when `s.auto_apply_dry_run is True`,
short-circuit BEFORE `submit_draft`:

```python
if s.auto_apply_dry_run:
    artifacts = dict(application.submission_artifacts or {})
    artifacts["dry_run_at"] = datetime.now(UTC).isoformat()
    application.submission_artifacts = artifacts
    application.updated_at = datetime.now(UTC)
    session.add(application)
    await _emit_event(
        session, user_id=application.user_id,
        application_id=application.id,
        kind=AppEventKind.AUTO_APPLY_DRY_RUN,
        payload={"score": job.score, "board": job.board.value},
    )
    out.processed += 1
    continue
```

**New `AppEventKind` value:** `AUTO_APPLY_DRY_RUN` — add to
`src/models/enums.py`.

**UI:** Toggle on `_settings_auto_apply.html` between enabled +
threshold. ~10 LOC + 4 tests.

### Risk + mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| M4 confidence threshold breaks HTTP adapters (Greenhouse/Lever/Ashby) which always emit 1.0 | NONE | NONE | 1.0 ≥ any threshold; behaviorally a no-op |
| Per-board cap JSONB column collides with future per-tenant settings refactor | LOW | LOW | Documented in plan; multi-tenant refactor moves ALL Settings cols |

| Per-board cap check adds 7 SELECTs per cron run | LOW | LOW | Cap lookup is per-user-per-board; cache in dict for cron lifetime |
