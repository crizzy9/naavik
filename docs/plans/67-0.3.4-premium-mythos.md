# 67 · 0.3.4 — PREMIUM-tier Claude-mythos generation

## A · Goal

Ship the PREMIUM-tier resume + cover letter generation layer that builds **on top of** the just-landed 0.3.1 FREE substrate (PR #167). PREMIUM is opt-in via Settings · Generation tab and adds five Claude-mythos machinery components: (1) adversarial Claude-as-detector loop with hybrid Originality.ai spot-check at convergence (`0.3.4.01`), (2) 3-agent voting council for bullet selection with Borda count merge (`0.3.4.02`), (3) multi-persona recruiter critique council post-draft (`0.3.4.03`), (4) tool-loop orchestrator coordinating 5 validators until convergence (`0.3.4.04`), (5) ATS parser ensemble cross-checking 3 OS parsers (`0.3.4.05`). All wired together via a tier="premium" branch in the existing `bundle_generator.generate_bundle` with a Settings UI surface for opt-in + cost projection + audit-trail viewer (`0.3.4.06`). 6 ROADMAP rows; ~1700 LOC across services + templates + 1 alembic migration; single PR. Cost: ~$0.40-1.20 per bundle (vs ~$0.06-0.22 FREE); user converts on high-stakes jobs (score > 0.85). Plan content graduates into existing `docs/design/RESUME_GENERATION.md` § Q (expanded from stub) + new § R cost projection + new § S PREMIUM audit-trail schema extensions.

## B · Why

`ROADMAP § 0.3.4` (lines 393-408) is the application-quality lever for jobs the user cares enough about to spend 10× the FREE cost. Cited research (`docs/design/research/0.3.1-resume-generation-sota.md` § A.1, § C.4, § D.7, § G.3-§ G.9) establishes that the **Claude-specific techniques** — heterogeneous-persona voting councils, adversarial detector loops, tool-orchestrated refinement — measurably outperform single-shot LLM generation at the cost of 5-10× more LLM tokens. The FREE tier ships SOTA-baseline quality (voice grounding + constitution + ATS-friendly Typst + adaptive cover letter + ethics pre-flight); PREMIUM stacks tactical Claude force-multipliers on top.

The 6 rows have all 10 OQs LOCKED per ROADMAP `Locked decisions` line (2026-05-21 user lock-in post-synthesized memo): OQ-2 council N=3 (heterogeneous personas, batch API), OQ-3 tool-loop cap N=3 (budget-aware early exit), OQ-4 hybrid Claude-as-detector + Originality.ai spot-check, OQ-6 TIER-2 evasion all opt-in. The remaining engineering shape — file boundaries, dispatch path through `generate_bundle`, audit-trail schema extensions, alembic migration — is the design space this plan locks.

**Why now:** 0.3.1 shipped 2026-05-21 (PR #167); the FREE substrate is on `main`, the one-click endpoint exists, and `Application.generation_trace` JSONB column is present + carrying the 17-key trace shape. The natural next user motion is: "this job is a unicorn — give me the premium pipeline." That motion currently dead-ends (the Settings · Generation toggle ships flat in 0.3.1 with no PREMIUM branch behind it). 0.3.4 closes the loop. 0.4.0 (auto-apply) does **not** gate on 0.3.4 — auto-apply runs FREE-tier; PREMIUM is per-app user-driven on the Discover · review screen — so 0.3.4 sits in its own quadrant: independently shippable, additive, no downstream gating.

### C.1 · `0.3.4.01` — Adversarial Claude-as-detector loop + Originality.ai spot-check

**New files:**

- `src/services/detector_loop.py` (~300 LOC)
- `src/llm/providers/originality.py` (~100 LOC)
- `src/llm/prompts/detect_ai_likelihood.py` (~80 LOC) — Pydantic schema `DetectorReport(ai_confidence: float, flagged_phrases: list[str], rationale: str)`
- `src/llm/prompts/refine_to_human.py` (~60 LOC) — schema `RefinedText(rewritten: str, changes: list[str])`

**Modified files:**

- `src/models/settings.py` — add `originality_api_key: str | None = Field(default=None, max_length=200)`
- `migrations/versions/0019_premium_mythos_settings.py` (NEW) — additive nullable text column + `generation_tier`

**Mechanics.** `services.detector_loop:run_detector_loop(text: str, *, max_iters: int = 3, user_id: int, session) -> DetectorReport`:

1. Iteration 0: Claude-as-detector prompt (`detect_ai_likelihood.py`) scores `ai_confidence` 0-1 + identifies flagged phrases. Wrap call via `services.llm_tracker.tracked_call(prompt_name="detect_ai_likelihood")`.
2. If `ai_confidence <= 0.25` OR `iter == max_iters` → terminate.
3. Otherwise: call `refine_to_human.py` with the flagged phrases. Replace those phrases in the output. Loop to step 1 with `iter += 1`.
4. At terminate: if `Settings.originality_api_key` present AND `iter > 0` (we did refine), spot-check via `originality.score_text(final_text)` → real-detector ground truth; record `originality_score` in returned report. If no API key OR `iter == 0`, `originality_score = None`.
5. Return `DetectorReport` carrying per-iter history (`iterations: list[{iter_n, confidence, refinements, prompt_tokens, output_tokens, cost_usd}]`) plus final `originality_score` (nullable).

`src.llm.providers.originality:OriginalityProvider`:

- **NOT** a `LLMProvider(ABC)` subclass — different shape (single `score_text` method, not chat-style).
- `async def score_text(text: str) -> float | None` — POSTs to `https://api.originality.ai/api/v1/scan/ai` with `Authorization: Bearer <api_key>` (loaded from `Settings.originality_api_key` field at call site, not env).
- Wraps the HTTP call through `tracked_call` with `prompt_name="originality_ai_scan"` and `provider="originality_ai"` so cost ledger captures the $0.01/scan typical charge. The `tracked_call` shim already supports non-Anthropic providers via the `provider=` kwarg (used by `ollama` today).
- Returns `None` gracefully on (a) no API key, (b) HTTP error, (c) non-200 response. Detector loop records `originality_score=None` in trace.

**Why this shape:** the Claude-as-detector inner loop is cheap (~$0.005/check at Sonnet 4.6) and avoids the 3rd-party API key requirement when users haven't configured one. The Originality.ai spot-check at convergence provides ground-truth validation — Claude self-critique risks model-self-cooperation per § G.9 OQ-4 footnote. Hybrid honors the locked OQ-4 decision.

**Test fixtures (~80 LOC test file):**

- Synthetic AI-tell text → detector reports `ai_confidence >= 0.85`.
- Human-corpus text (lifted from seeded `Bullet.text`) → detector reports `ai_confidence <= 0.20`.
- Detector loop converges within 3 iterations for low-AI input (single iter).
- Detector loop terminates at cap for adversarial input (3 iters, returns last attempt).
- `OriginalityProvider.score_text(...)` mocked via `httpx_mock`; graceful `None` on missing key.

### C.2 · `0.3.4.02` — 3-agent voting council for bullet selection (Borda count + batch API)

**New files:**

- `src/services/council.py` (~250 LOC)
- `src/llm/prompts/council_personas.py` (~120 LOC) — three prompt builders + shared `CouncilVote` schema:

  ```python
  class CouncilVote(BaseModel):
      persona: Literal["pragmatic_recruiter", "hiring_manager", "cultural_fit"]
      ranked_bullet_ids: list[int]  # ordered best→worst, length must equal candidate set
      rationale: str
  ```

**Modified files:**

- `src/llm/anthropic.py` — extend `AnthropicProvider` with `async def batch(self, requests: list[BatchRequest]) -> list[BatchResponse]` method that wraps `client.messages.batches.create(...)`. Polls until status=`ended` (typical ~30s-2min) with `asyncio.sleep` backoff. Returns ordered list of results matched by `custom_id`. Cost-discount 50% per batch API contract. ~60 LOC addition.

**Mechanics.** `services.council:vote_on_bullet_selection(candidate_bullets: list[Bullet], job: Job, profile: Profile, *, settings: Settings, session) -> SelectedBullets`:

1. Build 3 prompt requests using `council_personas.build_<persona>_prompt(candidates, job, profile)`. Each prompt asks for `CouncilVote` schema. All 3 share the same system message (constitution preamble + voice corpus, T2 cache hits).
2. Submit via `AnthropicProvider.batch(requests=[...])` — 3 parallel calls, 50% cost discount.
3. Borda merge: each persona's `ranked_bullet_ids` → bullets get N - rank_in_each_persona points (N = candidate set size); sum across personas; top-K = final selection (K = 8 default, matches existing `select_bullets` count).
4. Wrap each persona call via `tracked_call(prompt_name=f"council_{persona}", provider="anthropic_batch")` so cost surfaces in ledger. The batch API returns per-request usage; iterate and emit one `ApiUsage` row per persona.
5. Return `SelectedBullets(selected_ids: list[int], persona_rankings: dict[persona, list[int]], borda_scores: dict[bullet_id, int])`.

**Personas (see § G.3 of research):**

- **Pragmatic recruiter:** "Pick the 8 bullets that read as the strongest match to the JD's required skills. Prioritize quantification + alignment + ATS keyword coverage." Strong skim-test bias.
- **Hiring manager:** "Pick the 8 bullets that showcase the candidate's most transferable + senior-level impact. Prioritize ownership + scope + leadership + specific tech-stack signal." Depth bias.
- **Cultural-fit assessor:** "Pick the 8 bullets that align to the company's culture signals (work style, values, scale). Prioritize collaboration + impact + growth + curiosity." Soft-signal bias.

**Latency budget.** Anthropic batch API typical latency ~30s-2min vs sync ~3-5s. For the PREMIUM tier the user is waiting on the bundle render path (UI shows progress bar); 60-90s end-to-end fits the PREMIUM expectation. Synchronous fallback (3 sequential calls at 1× cost) when batch API returns 503 or polling exceeds 5min timeout.

**Test fixtures (~70 LOC):**

- 12 candidate bullets → Borda count tie-broken deterministically (lower bullet_id wins ties).
- All 3 personas rank `[1, 2, 3]` → consensus selects `[1, 2, 3]`.
- Personas disagree heavily → Borda still returns top-K with highest aggregate.
- Batch API mocked via `_FakeAnthropicClient` returning canned `MessageBatch.responses` shape.

### C.3 · `0.3.4.03` — Multi-persona recruiter critique council

**New files:**

- `src/services/critique_council.py` (~250 LOC)
- `src/llm/prompts/critique_personas.py` (~140 LOC) — three prompt builders + `CritiqueVote` schema:

  ```python
  class CritiqueVote(BaseModel):
      persona: Literal["faang_l5_l6_hm", "startup_founder", "fortune_500_hr"]
      strengths: list[str]            # ≤5 entries; one-line each
      concerns: list[str]             # ≤5 entries; one-line each
      recommendation: Literal["ship", "revise", "reject"]
      specific_changes: list[str]     # ≤3 entries; concrete edits requested if revise
  ```

**Mechanics.** `services.critique_council:critique_bundle(resume_text: str, cover_letter_text: str, headline: str, job: Job, *, settings, session) -> CritiqueReport`:

1. Build 3 prompts via `critique_personas.build_<persona>_prompt(resume_text, cover_letter_text, headline, job)`. Each persona reads the rendered resume + cover letter text + JD; returns `CritiqueVote`.
2. Batch via `AnthropicProvider.batch` (reuses C.2 infrastructure).
3. Aggregate:
   - **Consensus concerns**: items appearing in ≥ 2/3 persona `concerns` lists (string-similarity 0.6 via `difflib.SequenceMatcher.ratio()`) → surface to user as high-confidence feedback.
   - **Disagreement items**: items appearing in only 1 persona → surface as informational.
   - **Recommendation tally**: count `ship` vs `revise` vs `reject` across personas. Majority `revise` (≥ 2/3) → trigger one regeneration pass (loops the bullet selection + cover-letter generation stages with the consensus_concerns embedded into the constitution preamble's `extra_constraints` slot).
4. Cap regeneration at 1 pass per bundle (cost discipline — no infinite revise loop).
5. Return `CritiqueReport(persona_votes, consensus_concerns, disagreement_items, recommendation_tally, regeneration_triggered)`.

**Personas (see § G.4 of research):**

- **FAANG L5/L6 hiring manager:** 6-second skim + technical depth check. Flags: seniority clarity, signature-achievement-in-headline, scale-of-impact, sponsorship-status-readable.
- **Series A/B startup founder:** ownership + range + scrappiness. Flags: generalist signal, ownership clarity, recent ship velocity.
- **Fortune-500 HR-screener (Workday-using):** parse fidelity + keyword density + visa visibility. Flags: top-30% keyword presence, sponsorship clarity, standard headers.

**Test fixtures (~60 LOC):**

- 3 personas all flag `weak_quantification` → consensus surfaces with score 1.0.
- 1 persona flags, 2 don't → disagreement (informational only).
- 2/3 vote `revise` → regeneration triggered exactly once.
- 3/3 vote `ship` → no regeneration; consensus emits empty list.

### C.4 · `0.3.4.04` — Tool-loop orchestrator

**New files:**

- `src/services/tool_loop.py` (~400 LOC)
- `src/llm/prompts/orchestrate_refinement.py` (~80 LOC) — orchestrator prompt template + tool definitions

**Mechanics.** `services.tool_loop:run_tool_loop(resume: GeneratedDocument, cover_letter: GeneratedDocument, job: Job, *, max_iters: int = 3, settings, session) -> ToolLoopReport`:

1. Register 5 tools per § G.6 with the Anthropic Messages API `tools=[...]` parameter:

   | Tool name | Implementation delegate | Returns |
   |---|---|---|
   | `ats_parse_test` | `services.ats_parser_fidelity.validate_parse_fidelity(pdf_path)` | `ParseScoreReport` (existing) |
   | `detector_test` | `services.detector_loop.run_detector_loop(text)` (C.1) | `DetectorReport` |
   | `recruiter_skim_score` | NEW `services.recruiter_skim.score(text)` — Claude-as-recruiter simulating 6-sec skim; returns `SkimScore(score: int, top_signals: list[str], missing_signals: list[str])`. ~80 LOC inline in `tool_loop.py`. |
   | `keyword_coverage_check` | `services.keyword_coverage.compute_coverage(must_haves, text)` (existing) | `CoverageReport` |
   | `defensibility_check` | NEW closure that joins selected bullet IDs against actual `Bullet` rows; verifies provenance per § G.7. ~30 LOC inline. |

2. Initial message: orchestrate_refinement prompt with rendered resume + cover letter + JD; system message includes constitution preamble. Claude decides which tools to call.
3. Loop: receive `tool_use` blocks, dispatch to delegates, send back `tool_result` blocks. Claude iterates between tool calls (adaptive thinking auto-enabled on Sonnet 4.6 / Opus 4.7 — **NO** `interleaved-thinking-2025-05-14` beta header needed for current models; per research clarification).
4. Terminate conditions (whichever first):
   - Claude emits final `text` block declaring "ship" → exit.
   - `iter == max_iters` (3) → exit with current best.
   - Daily cost cap exhausted (`document_generator.is_cost_capped`) → exit early with `degraded_mode=True`.
5. Return `ToolLoopReport(iterations: list[{iter_n, tool_calls, results, decision, cost_usd}], final_decision: Literal["ship", "ship_with_caveats", "exhausted"])`.

**Why no beta header.** Per research clarification (context7 lookup 2026-05-21), Sonnet 4.6 and Opus 4.7 auto-enable interleaved thinking via adaptive-thinking; the `interleaved-thinking-2025-05-14` beta header is required only for older Claude 4 models (4.0, 4.1, 4.5). Plan ships without the header; engineer adds `extra_headers={"anthropic-beta": "interleaved-thinking-2025-05-14"}` ONLY when `Settings.llm_model` resolves to `claude-sonnet-4-5-*` or earlier (config-driven; the existing model-routing logic already discriminates). Saves the cognitive load of a forever-deprecated header for the common path.

**Cost projection.** Per § G.6: ~$0.04-0.10 per iteration × ≤3 iters = $0.12-0.30 worst case. Combined with the orchestrator's own thinking tokens.

**Test fixtures (~100 LOC):**

- Single-tool happy path: Claude calls `ats_parse_test`, gets score 0.95, emits "ship" → exit iter 0.
- Multi-tool refinement: parse-fidelity 0.6 first iter → Claude requests bullet rewrite → iter 1 parse-fidelity 0.85 → ship.
- Iteration cap: Claude keeps requesting refinement → cap at 3 → exit with `final_decision="exhausted"`.
- Budget early exit: cost cap mock returns True mid-loop → exit immediately with `degraded_mode=True`.

**New files:**

**Modified files:**

**Mechanics.** `services.ats_parser_ensemble:ensemble_score(pdf_path: Path) -> EnsembleReport`:

1. Run pdfplumber path (existing `ats_parser_fidelity.validate_parse_fidelity`) → `ParseScoreReport`. Always runs.
2. If `pyresparser` importable: run it on the same PDF; convert output to comparable 8-field schema (`name / email / phone / first_exp_title / first_exp_company / first_exp_start_date / education / skills_section_present`). Score = `fields_extracted / 8`.
3. If `node` on PATH AND `scripts/openresume_parser.js` exists: `subprocess.run(["node", "scripts/openresume_parser.js"], input=pdf_bytes, capture_output=True, timeout=10)`. Parse JSON. Score = `fields_extracted / 8`. Timeout → `score=None`; subprocess error → `score=None`.
4. Aggregate: `ensemble_score = mean([s for s in (pdfplumber, pyresparser, openresume) if s is not None])`. At minimum, pdfplumber always runs → ensemble degenerates to pdfplumber when optionals absent.
5. Return `EnsembleReport(pdfplumber_score, pyresparser_score, openresume_score, aggregate_score, parsers_used: list[str])`.

**Architect locks (option matrix in § E.3): shell-out to Node subprocess for OpenResume** (vs full TypeScript→Python port). Node already on path via `nodejs_20` in the dev shell; production Docker image already has Node available (alpine npm install line); maintenance cost low (60-LOC JS shim mirrors the upstream `parse-resume-from-pdf.ts` entry point). Full Python port would be ~600 LOC + ongoing sync with upstream. Subprocess is ship-it-and-forget; Python port is a maintenance commitment we don't need for what is fundamentally a cross-check signal.

**Test fixtures (~70 LOC):**

- All 3 parsers report 0.9 → ensemble 0.9.
- pyresparser unavailable (import fails) → ensemble = mean(pdfplumber, openresume).
- All optionals unavailable → ensemble = pdfplumber score (graceful).
- Node subprocess timeout (10s) → openresume_score=None; ensemble continues.

## D · Tactical decisions locked (T1-T16)

All 10 OQs are LOCKED per ROADMAP. The 16 tactical decisions below cover engineering choices ROADMAP did not address.

### T1 — Detector loop architecture (`0.3.4.01`)

**Decision: Claude-as-detector inner loop + Originality.ai single spot-check at convergence.** Per OQ-4 lock. Detector prompt asks Claude to score `ai_confidence 0-1` + identify specific flagged phrases (not just an overall score — actionable signal for the refine step). Refine prompt rewrites only the flagged phrases (not the whole text — preserves voice grounding from constitution). Cap at 3 iters per OQ-3. Originality.ai called ONCE at convergence (not per-iter) — minimizes 3rd-party cost while still providing ground-truth verification.

**Why not Originality.ai per-iter?** Cost spirals; per-iter detection check is the inner loop's job; final ground truth is what matters.

### T2 — Originality.ai integration shape

**Decision: `src/llm/providers/originality.py` outside the `LLMProvider(ABC)` hierarchy; tracked via `tracked_call(provider="originality_ai")`.** Originality.ai's API surface (single text-in / score-out) doesn't fit the `LLMProvider` abstraction (chat completions / structured outputs / streaming). A dedicated module keeps the contract honest. The `tracked_call` shim already accepts arbitrary `provider=` strings (used by `ollama`); reuse the same path so cost ledger stays unified.

**API key sourcing.** `Settings.originality_api_key` DB column (new in alembic 0019), NOT env var. When key is absent, detector loop runs without ground-truth check (audit trail records `originality_score=None`).

### T3 — Council vote merge: Borda count (`0.3.4.02`)

**Decision: Borda count over majority vote.** Each persona's `ranked_bullet_ids` is a full ordering of the candidate set. Borda awards `N - rank` points (N = candidate count); sum across personas; top-K (K=8) win. **Ties broken by lower bullet_id** (deterministic).

**Why not majority?** Majority vote requires a tie-breaker rule when personas disagree (common case for non-trivial bullet sets). Borda naturally aggregates partial agreement: a bullet ranked #1 by 2 personas and #5 by 1 persona scores higher than a bullet ranked #1 by 1 persona and unranked by 2 others. Better signal for ordinal preferences.

### T4 — Critique council aggregation (`0.3.4.03`)

**Decision: string-similarity matching (`difflib.SequenceMatcher.ratio() >= 0.6`) for consensus detection.** Two personas saying "lacks quantification" vs "needs more numbers" should aggregate to the same consensus item. Exact-match aggregation would miss this. Threshold 0.6 calibrated against research synthesis (§ G.4).

**Regeneration trigger.** Majority `revise` (≥ 2/3) → run ONE regeneration pass with `consensus_concerns` embedded into constitution preamble's `extra_constraints` slot. Cap at 1 pass — no infinite revise loop. If regen still gets majority `revise`, the bundle ships with the warning surfaced to user; the trace records `regeneration_triggered=True` + `regeneration_outcome="still_concerns"`.

### T5 — Tool-loop orchestration: NO beta header for Sonnet 4.6 / Opus 4.7 (`0.3.4.04`)

## E · Option matrices for non-trivial decisions

### E.1 — Tier-dispatch placement (extend `generate_bundle` vs new wrapper module)

| Option | Capability | Cost | Risk | Maintenance | Lock-in |
|---|---|---|---|---|---|
| **(A) Extend `generate_bundle` with `tier=` kwarg + inline branch** | Same callers, one function | LOW (one branch added) | LOW (backward-compat via default) | LOW (one file) | MED (function grows) |
| **(B) New `generate_bundle_premium` module + Settings-driven dispatcher in routes** | Clear separation | MED (new file + dispatcher) | MED (route-layer dispatch easy to miss; tests for routes only) | MED (two files; tier-dispatch can drift) | LOW |
| **(C) Class-based `BundleGenerator` w/ tier-strategy pattern** | Most extensible | HIGH (~100 LOC refactor) | MED (refactors a stable function) | LOW long-term | HIGH (locked into class hierarchy) |

**Recommendation: (A)** — minimum-risk, backward-compat-safe, single PR scope. The branch is small (one `if tier == "premium":`); future complexity (more tiers, A/B testing) can refactor to (C) when justified.

### E.2 — Council parallelism (batch API vs concurrent asyncio.gather vs sequential)

| Option | Capability | Cost | Risk | Maintenance | Lock-in |
|---|---|---|---|---|---|
| **(A) Anthropic batch API** | 50% cost discount | LOW per-call | MED (~30s-2min latency; polling required) | LOW (1 method on provider) | LOW |
| **(B) `asyncio.gather(call1, call2, call3)`** | Fastest latency (~3-5s) | 1× cost (no discount) | LOW | LOW | LOW |
| **(C) Sequential** | Simplest | 1× cost | LOW | LOW | LOW (slowest UX) |

**Recommendation: (A) with sync (B) fallback.** Batch is the locked default per the ROADMAP row description; the 50% discount on 3 calls × 3 council × 3 critique × 3 tool-loop personas = $0.18 saved per PREMIUM bundle (meaningful at scale). Latency 60-90s fits the PREMIUM UX expectation (user clicked "PREMIUM" — implicit "I'll wait"). Fallback to (B) when `batches.create` returns 503 OR polling exceeds 5min timeout. (C) only as emergency last-ditch.

### E.3 — OpenResume integration: Node subprocess vs Python port

| Option | Capability | Cost | Risk | Maintenance | Lock-in |
|---|---|---|---|---|---|
| **(A) Node subprocess (`scripts/openresume_parser.js`)** | Stays in sync with upstream; minimal LOC | LOW (60 LOC shim + node_modules) | MED (subprocess timing, error handling) | LOW (defer to upstream) | LOW |
| **(B) Full TypeScript→Python port** | No runtime deps | HIGH (~600 LOC port) | HIGH (bug-for-bug parity with upstream) | HIGH (forever-sync burden) | HIGH |
| **(C) Skip OpenResume entirely; pdfplumber + pyresparser only** | Simplest | LOW | MED (lose one parser signal) | LOWEST | LOW |

**Recommendation: (A) Node subprocess.** Node already needed for `nix run .#dev` post-0.2.7.x typst tooling; production Docker image already has Node. 60-LOC shim is cheap to maintain; bug-for-bug parity is OpenResume's problem, not Naavik's. The cross-check signal IS valuable (different parsers fail differently — ensemble catches them all). (B) is over-engineering. (C) loses signal we want.

### E.4 — Detector loop refine strategy

| Option | Capability | Cost | Risk | Maintenance | Lock-in |
|---|---|---|---|---|---|
| **(A) Phrase-targeted refine (only flagged phrases rewritten)** | Preserves voice grounding | LOW (~$0.005/refine) | LOW | LOW | LOW |
| **(B) Full-text regenerate per iter** | Maximum AI-tell escape | HIGH (~$0.015/iter) | HIGH (loses voice grounding) | MED | LOW |
| **(C) Sentence-targeted refine (whole sentence containing flagged phrase)** | Middle ground | MED | LOW | LOW | LOW |

**Recommendation: (A) Phrase-targeted refine.** The constitution preamble + voice grounding work BECAUSE the LLM saw the candidate's actual writing in the system message. Full regenerate (B) discards that context iteratively, defeating the FREE-tier substrate. Phrase-targeted edits preserve the voice; (C) is acceptable but (A) is tighter signal.

### E.5 — Audit-trail viewer rendering

| Option | Capability | Cost | Risk | Maintenance | Lock-in |
|---|---|---|---|---|---|
| **(A) Server-rendered HTML fragments (HTMX)** | Idiomatic for Naavik | LOW | LOW | LOW | LOW |
| **(B) Client-side render of JSONB blob (Alpine.js or vanilla JS)** | Fast tab-switch | LOW | MED (~50 LOC JS) | MED (more state to track) | MED (drifts from HTMX convention) |
| **(C) JSON download + external viewer** | Simplest | LOW | LOW (poor UX) | LOW | LOW (no UI surface) |

**Recommendation: (A).** Matches Naavik's HTMX-first convention; AGENTS.md § Frontend (HTMX) explicitly says "Alpine.js only if needed for complex client-side state." Audit-trail viewer is read-only render of JSONB — perfect HTMX fragment swap.
