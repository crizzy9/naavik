# 80 · 0.4.0.09 — Bulk actions on /tracking list

## Goal

Add bulk-action toolbar to the Tracking list view (SCREENS.md § 9
spec: "Sortable columns; bulk actions on selected rows (move stage,
archive, export to CSV)"). Today operators can only act on one
Application at a time.

## Why

`docs/design/research/0.4.0-AUDIT.md § C` lists this as 0.4.0.09
(MEDIUM). 3 actions ship:

- **Move stage** — bulk-update `Application.status` (forward
  transitions only; backwards needs MANUAL_OVERRIDE).
- **Archive** — bulk discard (status=CLOSED, closed_reason=user_archived).
- **Export CSV** — download selected applications as a CSV file.

SCREENS.md spec is partial-built — list view already renders
checkboxes per row (`_tracking_list.html`); no toolbar surfaces them.

## Proposal

Single PR; 3 commits.

### D.1 Commit 1 — service layer

`src/services/application_service.py` — three new bulk functions:

```python
async def bulk_update_status(
    session: AsyncSession,
    *,
    user_id: int,
    application_ids: list[int],
    new_status: ApplicationStatus,
    closed_reason: ClosedReason | None = None,
) -> tuple[int, list[int]]:
    """Bulk-update status. Returns (success_count, failed_ids).

    Forward transitions only — backwards transitions go via
    `update_status` (MANUAL_OVERRIDE event). Failed IDs include
    cross-user IDOR violations (silently ignored) + applications in
    states that can't transition forward to new_status.
    """
    success = 0
    failed: list[int] = []
    for app_id in application_ids:
        application = await get_application(session, app_id)
        if application is None or application.user_id != user_id:
            failed.append(app_id)
            continue
        try:
            await update_status(
                session, app_id, new_status, closed_reason=closed_reason
            )
            success += 1
        except (IllegalStateTransition, ValidationError):
            failed.append(app_id)
    return success, failed


async def bulk_archive(
    session: AsyncSession,
    *,
    user_id: int,
    application_ids: list[int],
) -> tuple[int, list[int]]:
    """Bulk archive (status=CLOSED, closed_reason=user_archived,
    deleted_at=utcnow). Returns (success_count, failed_ids)."""
    # Calls update_status with closed_reason=USER_ARCHIVED.
    return await bulk_update_status(
        session, user_id=user_id, application_ids=application_ids,
        new_status=ApplicationStatus.CLOSED,
        closed_reason=ClosedReason.USER_ARCHIVED,  # new enum value
    )


async def list_for_export(
    session: AsyncSession,
    *,
    user_id: int,
    application_ids: list[int],
) -> list[dict]:
    """Fetch + denormalize for CSV export. Honors user_id boundary."""
    stmt = select(Application).where(
        Application.user_id == user_id,
        Application.id.in_(application_ids),
        Application.deleted_at.is_(None),
    )
    rows = (await session.exec(stmt)).all()
    return [
        {
            "company": a.company,
            "role": a.role,
            "team": a.team or "",
            "location": a.location or "",
            "status": a.status.value,
            "applied_at": a.applied_at.isoformat() if a.applied_at else "",
            "salary_min": a.salary_min or "",
            "salary_max": a.salary_max or "",
            "board": a.board.value if a.board else "",
            "external_url": a.external_url or "",
        }
        for a in rows
    ]
```

**Enum addition:** `src/models/enums.py` — extend `ClosedReason`

```js
// Bulk-selection helpers for /tracking list view
function trackingBulkSelectionChange() {
  const checks = document.querySelectorAll('[data-tracking-row-select]:checked');
  const bar = document.getElementById('tracking-bulk-action-bar');
  if (!bar) return;
  bar.hidden = checks.length === 0;
  bar.querySelector('[data-bulk-count]').textContent = checks.length + ' selected';
}

function bulkExportCsv() {
  const checks = document.querySelectorAll('[data-tracking-row-select]:checked');
  const ids = Array.from(checks).map(c => c.value);
  if (!ids.length) return;
  const qs = ids.map(id => 'application_ids=' + id).join('&');
  window.location.href = '/api/v1/applications/export.csv?' + qs;
}
```

### Risk + mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Bulk-update with 100s of IDs blows out session.flush + transaction time | LOW | LOW | Cap at 50 IDs per request; UI documents the cap |
| `application_ids` form field collides with existing tracking list state | LOW | LOW | Form field name `application_ids` is bulk-action-specific |
| `USER_ARCHIVED` enum addition conflicts with PostgreSQL pre-PG16 (can't drop enum values) | NONE | NONE | Only adding a value; never removing existing |
| Mass-archive with no confirmation modal → accidental data loss | MED | MED | `hx-confirm` + JS confirm dialog; "Are you sure?" prominent |
| IDOR via crafted `application_ids` (includes another user's IDs) | LOW | LOW | Service iterates per-ID + checks `user_id`; cross-user silently fails |
