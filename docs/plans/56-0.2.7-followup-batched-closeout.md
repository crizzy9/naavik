### Item 5 — Postmortem `_redact()` walks VALUES not just KEYS (0.2.7.18, MEDIUM)

**Rationale.** Filed via PR #152 hacker review (MED-1). `src/services/ats_postmortem.py:_redact` (lines 66-78) walks dict KEYS via `_SECRET_KEY_RE` (line 35) but `response_body_excerpt` is a raw string (line 104-110) — ATS error bodies can echo back the auth headers used in the failed request (rare but observed in some ATS adapter logs). Bearer / JWT / Set-Cookie / Authorization patterns in the string body bypass `_redact` entirely and land verbatim in `trace.json` + get fed into the LLM prompt at `ats_postmortem.PROMPT`. Need a value-shape regex pass BEFORE the 32KB truncate (line 108).

**Files.**

- `src/services/ats_postmortem.py` — add a `_VALUE_PATTERN_REDACTIONS` list at module level after `_SECRET_KEY_RE` (line 35):

  ```python
  # Value-shape patterns that match auth material echoed back in scraper-controlled
  # response bodies (ATS error pages sometimes mirror the request's auth header).
  # Replace the matched span with [REDACTED] BEFORE the response body excerpt is
  # persisted to trace.json or fed to the LLM postmortem prompt.
  _VALUE_PATTERN_REDACTIONS = [
      # Bearer / JWT — case-insensitive header form + bare JWT shape
      re.compile(r"(?i)\b(bearer|jwt)\s+[A-Za-z0-9._\-+/=]{20,}"),
      # JWT (3-segment base64url) — match bare even when no "bearer" prefix
      re.compile(r"\beyJ[A-Za-z0-9_\-]+\.[A-Za-z0-9_\-]+\.[A-Za-z0-9_\-]+"),
      # Set-Cookie / Cookie / Authorization header value (everything after the colon)
      re.compile(r"(?im)^(Set-Cookie|Cookie|Authorization):\s*.+$"),
      # OAuth refresh / access token URL params
      re.compile(r"(?i)(access_token|refresh_token|id_token)=[A-Za-z0-9._\-+/=]{20,}"),
  ]


  def _redact_value_patterns(text: str) -> str:
      """Apply value-shape regex redactions to a raw string.

      Complements `_redact()` (which only walks dict keys). Used on
      `response_body_excerpt` before truncate + persist + LLM-prompt feed.
      """
      out = text
      for pat in _VALUE_PATTERN_REDACTIONS:
          out = pat.sub(_REDACTED, out)
      return out
  ```

  Then in `_build_trace` (line 81-110), apply `_redact_value_patterns` to the body BEFORE the truncate slice. Concrete patch on lines 104-110:

  ```python
  if body is None:
      response_body_excerpt = None
  elif isinstance(body, str):
      response_body_excerpt = _redact_value_patterns(body)[:_RESPONSE_BODY_CAP]
  else:
      response_body_excerpt = _redact_value_patterns(json.dumps(body, default=str))[:_RESPONSE_BODY_CAP]
  ```

- `tests/test_ats_postmortem.py` — add 4 tests in a new `class TestRedactValuePatterns:` block:
  1. `test_redacts_bearer_header` — input `"Authorization failed: Bearer eyJabc...verylong"`; assert output contains `[REDACTED]` + no `eyJabc`.
  2. `test_redacts_bare_jwt` — input `"token=eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxMjM0NSJ9.SflKxw..."`; assert `[REDACTED]` present.
  3. `test_redacts_set_cookie_header` — input `"failed: Set-Cookie: session=abc123; Path=/"`; assert `session=abc123` absent.
  4. `test_redacts_oauth_token_url_param` — input `"redirect: ?access_token=ya29.abc...defABC&state=xyz"`; assert `access_token=ya29` absent.
  5. (Bonus, no extra test) — verify existing `tests/test_ats_postmortem.py` cases that DON'T include auth material still match the captured trace shape (no regressions from over-aggressive redaction).

**LOC.** ~30 LOC src + ~50 LOC tests. **Risk.** MED — regex over-match could redact legitimate non-secret content (e.g. a long base64-encoded image URL matches the access_token pattern). Engineer keeps the patterns conservative (`\b` word boundaries, length-min 20 chars). One test case explicitly: `"signature=abc"` (short) MUST NOT redact. Engineer also documents in the file's module docstring that `_redact_value_patterns` is "best-effort defense in depth, not a comprehensive secrets scrubber" — the canonical defense is the ATS adapter never including auth material in `raw["text"]` in the first place.
