## Background — the two MEDIUMs verbatim (PR #102 hacker review)

```
MEDIUM Finding #1 — src/scraper/sites/workday.py:125-132
_parse_tenant_spec accepts attacker-controlled host segments past url_guard's
permissive netloc check. workday_companies is user-controllable via
PUT /api/v1/settings/sources. An authenticated user can supply
workday_companies=["evil.com#"]. The composed URL becomes
https://evil.com#.wd1.myworkdayjobs.com/External; urlsplit sees host evil.com,
is_safe_destination resolves DNS for evil.com (a public IP, allowed), the URL
passes. The browser then drops the fragment and fetches https://evil.com/.
Net result: scraper performs HTTP requests against attacker-chosen public
domains. Confirmed empirically:
  urlsplit("https://evil.com#.wd1.myworkdayjobs.com/External").hostname == "evil.com"

MEDIUM Finding #2 — src/scraper/sites/{greenhouse.py:64, lever.py:57, ashby.py:56}
Only the fully-composed URL is checked; user-controlled URL components
(query.company_filter) are not validated before template substitution.
Lever's URL inlines {company} in the path:
  https://api.lever.co/v0/postings/{company}?mode=json
A slash injection like company="acme/../../v0/users/{id}" smuggles a
path-traversal at the API layer. urlsplit hostname stays api.lever.co so
url_guard is happy, but the actual API endpoint hit is attacker-chosen.

Fix: Validate every {company}/{tenant} value before substitution against
_SLUG_RE = re.compile(r"^[a-zA-Z0-9][a-zA-Z0-9_-]*$"); entries that fail get
logged + skipped (kind=invalid_slug). Cleaner shape: a _make_url(template, **slugs)
helper in scraper.url_guard that asserts each kwarg matches _SLUG_RE, formats,
then callers pass through is_safe_destination — single chokepoint instead of 6
sites each remembering to validate.

Non-exploitable in current single-tenant self-host (attacker is the user);
MUST fix BEFORE multi-tenant cloud flip.
```
