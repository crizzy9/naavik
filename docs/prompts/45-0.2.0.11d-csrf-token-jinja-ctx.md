## Why this matters

Production HTMX is degraded today across two surfaces: `/discover` Save/Skip/Auto-submit (new in PR #138) and `/auth/change-password` (latent since plan 18). The security boundary IS correct — `require_csrf` rejects mismatched / empty tokens by design. The defect is purely upstream: no code reads the cookie back into the template context, so the rendered `X-CSRF-Token` is always `""`. Engineer's job here is to wire that one thread, in one file, idiomatically.

The architect locked Option A from a 3-option matrix because Starlette's `context_processors` is the documented mechanism for exactly this pattern; B (per-handler `Depends`) means touching 40 callsites + creating a perpetual drift trap; C (`TemplateResponse` wrapper) means non-idiomatic Starlette-internal coupling. A wins on every axis.
