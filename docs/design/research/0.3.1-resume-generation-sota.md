## A · Executive summary + reconciliation summary

The current `0.3.1` ledger has 4 rows that read as "bullet selection + bullet trim + page-count loop + one-click endpoint" — a thin wrapper around `select_bullets.py` + `trim_bullet.py` + the existing Typst compile loop. Both source memos independently concluded that framing badly under-scopes the user's actual ask: **a tailored PDF that (a) survives parsing across 9 ATS systems with > 85% field-extraction fidelity, (b) evades the 5 major AI-detector classifiers without crossing into fraud, (c) lands the candidate's name in the recruiter's 6-second-skim "potential hire" attention zone, and (d) uses Claude's specific capabilities (1M context, prompt caching, extended thinking, tool use, multi-agent voting) as a tactical force-multiplier past off-the-shelf LLM generation.**

In 2026, where 76% of applications are AI-detected ([WasItAIGenerated 2026 study](https://www.wasitaigenerated.com/research/ai-detection-hiring-recruitment)) and 49% of hiring managers auto-reject suspected AI-generated material ([Resume.io](https://resume.io/blog/resume-rejections)), the 4-row sketch is meaningfully insufficient.

### A.1 Three critical decisions (synthesized)

1. **Adopt the 2-tier FREE/PREMIUM architecture (§ H Stage 1-9).** FREE-mode is SOTA-only: constitution preamble extracted from corpus + 1 generation pass + ATS-friendly Typst template (`onepage_ats.typ`) + page-count retry-drop loop + ethics pre-flight. ~$0.06-0.12 per application at Sonnet 4.6 with prompt caching. PREMIUM-mode layers the Claude-mythos stack on top: 3-agent council for bullet selection (§ G.3), adversarial generator-critic loop for AI-detection burstiness injection (§ G.5), multi-persona recruiter critique council for the final draft (§ G.4), tool-loop orchestrator running ATS-parse-test + detector-test + recruiter-skim-score + defensibility-check until convergence (§ G.6). ~$0.40-1.20 per application. **Default is FREE; user toggles PREMIUM in Settings · Generation tab OR per-app for jobs scoring > 0.85.** This split honors the daily cost cap, gives users predictable cost per app, and concentrates Claude-mythos spend where it converts.

2. **Adopt PDF/A-1b + ATS-friendly Typst variant + voice-grounded constitution as the FREE baseline.** PDF/A-1b is the documented best-fit for ATS readability (≥85% parse scores per [ResumeAdapter 2026](https://www.resumeadapter.com/blog/ats-resume-formatting-rules-2026)). The new `onepage_ats.typ` template strips the current single-column grid to even more parser-friendly form (no columns, no boxes, plain `•` bullets, MM/YYYY dates, ligatures-disabled Helvetica). Voice grounding from corpus + constitution-preamble (§ G.1 + § G.2) is the *biggest single lever* for AI-detection evasion because it grounds bullets in the candidate's own past writing, making them inherently human-burstiness compliant.

3. **Reject TIER-3 (black-hat) techniques as default; surface them with explicit opt-in + blacklist-risk warning.** White-text keyword stuffing, zero-width unicode injection, homoglyph substitution, hidden-metadata keyword spam all cross into deception territory. Per [airesume.guru blacklist study](https://airesume.guru/blog/hidden-keywords-white-text-on-resumes-the-myth-that-gets-you-blacklisted), modern ATS reads these AND many recruiter networks share blacklists across companies. They can mass-blacklist the candidate. **Naavik never recommends these; we surface them in Settings · Advanced with a blacklist-risk warning + require explicit opt-in.** No exceptions.

### B.2 Universal rules (apply to all 9)

These combine the cross-system lessons — getting these right pushes parse fidelity from ~70% (creative templates) to ~95% (ATS-friendly):

1. **Single-column layout.** No tables, no text boxes, no columns. Taleo silently fragments; Workday interleaves; iCIMS may flag for manual retype. [Jobscan 2026](https://www.jobscan.co/blog/resume-tables-columns-ats/) — 23% of ATS parse failures are formatting-driven.
2. **Standard section headings.** `EXPERIENCE` (not "Career Journey"), `EDUCATION` (not "Academic Background"), `SKILLS` (not "Capabilities"), `PROJECTS` (not "Things I've Built"). Taleo's exact-match-only is the strictest case.
3. **MM/YYYY or "Month YYYY" dates.** "Jan 2024 — Present" parses across all 9. Avoid "January '24" / "Q1 2024" / "2024 (ongoing)".
4. **Plain bullet markers.** `•` (U+2022) or `-` only. Avoid Unicode arrows (→), checkmarks (✓), decorative dots, emoji — iCIMS flags, Taleo fragments.
5. **No header/footer content.** Workday + most parsers ignore PDF header/footer XML nodes. Contact info must be in the body, top-of-page.
6. **Web-safe fonts.** Helvetica / Arial / Calibri / Times New Roman / Georgia. Current `onepage.typ` already uses `Helvetica, Arial, Liberation Sans` — keep.
7. **PDF/A-1b output.** ≥85% parse scores on most ATS checkers per [ResumeAdapter 2026](https://www.resumeadapter.com/blog/ats-resume-formatting-rules-2026). Typst output is already text-based PDF; verify it qualifies as PDF/A-1b via the `--pdf-standard a-1b` flag.
8. **No fancy ligatures, no kerning quirks.** Some PDF parsers tokenize ligature glyphs (`fi`, `fl`) as separate characters or as PUA Unicode that Taleo can't recover. Typst `text(ligatures: false)` directive on `onepage_ats.typ`.
9. **Contact info in canonical pattern.** Name on first line (bold, 14pt). Email + phone + location on second line. LinkedIn / GitHub / portfolio URL on third line. Current `onepage.typ` already does this — keep.
10. **No PII beyond canonical fields.** No date-of-birth, marital status, photo, nationality — some ATS flag for review.

### B.3 PDF format choice — PDF/A-1b vs PDF/A-2b vs raw PDF vs DOCX

The two source memos disagreed on PDF/A variant. **Synthesized choice: PDF/A-1b.** Rationale:

- v1 argued for PDF/A-2b (basis: PDF 1.7, the version used by virtually all modern ATS).
- mythos argued for PDF/A-1b (basis: PDF 1.4, documented ≥85% parse scores per ResumeAdapter 2026 — the actual real-world parse-fidelity threshold most ATS checkers cite).
- **The decisive factor:** parse fidelity is what we measure, and PDF/A-1b is what the parse-fidelity benchmarks cite. PDF/A-2b is the "archival default" but parsers don't care about archival features. PDF/A-1b is the more conservative + better-documented choice.

Typst supports all PDF/A variants via `--pdf-standard a-1b` / `a-2b` / `a-3b` / `a-4` / `a-1a` flags ([Typst PDF docs](https://typst.app/docs/reference/pdf/)). Ship PDF/A-1b in `onepage_ats.typ`.

**DOCX as fallback** for Taleo-/SuccessFactors-heavy job universes — out of scope for `0.3.1` (Typst → DOCX is non-trivial). File as `0.3.4.NN` or `0.8.0.NN` deferred row. Re-visit if real-world ATS-failure telemetry justifies it.

Cross-ATS allowlist (every name appears in ≥ 3 ATS docs):

- **`Education`** (universal).

### B.5 Bullet markers — what survives PDF→text extraction

Cross-ATS safe list:

- **`•`** (U+2022 BULLET) — universal. Typst's `bullet_line` macro already uses this. Pass.
- **`-`** (ASCII hyphen-minus U+002D) — universal. Safe.
- **`*`** (ASCII asterisk U+002A) — universal but renders as `*` (less polish).

Reject: `★ ➤ ▸ ✓ ◆ ●` (iCIMS flags as bullet normalization; Taleo skips line; Workday garbage). `o` (concatenates into adjacent text). En-dash `–` or em-dash `—` as bullet (readers don't expect; some ATS skip).

**`onepage_ats.typ` recommendation: explicit `•` only; no fallback chain.**

### B.6 Date formats — what parses reliably

Cross-ATS safe:

- **`Jan 2024 – Present`** — universal. Current `onepage.typ` uses `%b %Y` → `Jan 2024`. Pass.
- **`01/2024 – Present`** — universal but slightly less recruiter-friendly.
- **`January 2024 – December 2023`** — full names; safer on Taleo + JazzHR.

Reject: year-only (`2024 – Present`; Workday + Lever can't compute years-of-experience). `Current` / `Ongoing` / `Now` (some ATS reject; `Present` is universal). Inconsistent formats within one resume.

Owner profile is **Shyam Padia, 8+ years (5.5+ at Intuit)** — solidly in the "2-page is acceptable" zone per all 2026 sources. But `onepage.typ` enforces 1-page (with overflow retry-drop). **Stay 1-page for `0.3.1`**:

## C · AI-detection evasion — TIER-1 / TIER-2 / TIER-3 + ethics framing

### C.1 Ethics framing (read FIRST)

**Naavik never lies about credentials.** The AI is *tailoring* what the user actually did into the language the JD speaks. Anti-detection is about getting **human-with-AI-assist past false-positive screening**, NOT pretending no AI was used.

**Key context:**

- **Stanford Liang et al. 2023:** 61.3% false-positive rate on non-native-English TOEFL essays vs near-zero on native-English. Academic + medical writing flagged 2-4× more than creative writing. **AI detectors are unreliable enough that lossy human-written cover letters get false-flagged anyway.**
- **2026 industry consensus** (WasItAIGenerated + Gem + AI Career Lab): the meaningful distinction is **AI-assisted writing of accurate information** (legitimate; ATS vendors like Oracle invite candidates to use AI) vs **AI-fabricated credentials** (fraud; 18 USC §1001 felony; FCRA implications; permanent blacklist).
- **65% of Fortune 500 companies** use AI-content detection (humanizerai.com). **62% of resumes flagged are rejected** (resumegeni.com). **33.5% of hiring managers say they can spot AI-generated content in <20 seconds** (gem.com).
- **No major ATS itself runs AI-content detection** (Workday/Greenhouse/iCIMS/SSF use AI for *matching*, not for *who wrote it*). But integrators (Originality.ai, Copyleaks via Workday Marketplace, Turnitin Workforce edition) wire detection in via webhook.
- **Detection-rate climb:** H1 2024 = 53%; H1 2026 = 76%; H1 2027 projected = 85-90%. The opening for honest tools: detection spectrum spans "100% AI-from-blank-prompt" (easily caught) to "human-written with AI optimization" (nearly undetectable). The key variable is **how much content comes from real career data vs AI invention**. Naavik's substrate is built for the latter — every bullet derives from a user-owned `Bullet` row.

**Naavik's stance:** TIER-1 default-on (legitimate optimization; voice-grounding + AI-tell removal). TIER-2 opt-in with cost-cap awareness. TIER-3 surfaced + warned + NOT default. The user owns the choice.

### C.2 Detector landscape (what AI detectors actually measure)

Cross-source (GPTZero / Originality.ai blog / Copyleaks / academic):

| Detector | Primary signal | Secondary signals | Architecture | 2026 false-positive rate | API access |
|---|---|---|---|---|---|
| **GPTZero** | Perplexity + burstiness | Sentence-length variance + lexical diversity + word-rarity + Paraphraser Shield trained on 12+ humanizer tools | Deep classifier trained on 600M+ documents | 9.2% on non-AI text | Yes ($14.99/mo+) |
| **Originality.ai** | Proprietary multi-feature ensemble (perplexity + n-gram + style fingerprint + watermark detection) | Self-reported 99%+ on GPT-3.5; drops to 31.7% on GPT-5 per their own Chicago Booth 2026 benchmark | Closed proprietary | 2.1% | Yes ($179/mo Enterprise; $30 PAYG 30k words = ~$0.001/cover-letter) |
| **Copyleaks** | Proprietary multi-feature (perplexity + deep-learning + semantic fingerprinting) | Closed | Closed | 5.8% | Yes (commercial) |
| **Turnitin (workforce edition)** | Sentence-level entropy + semantic coherence (v4 in 2026) | Fine-tuned on student-essay corpus; may not generalize well to job-app text | Proprietary | 4% (claimed; academics dispute) | Yes (enterprise-only) |
| **Winston AI** | Perplexity + burstiness + stylometric cues | Similar to GPTZero | Proprietary | ~10% | Yes |

**Key insight:** the underlying signal across all of them is **perplexity (how predictable each word is) + burstiness (sentence-length and complexity variance) + style-fingerprint**. Defeat those three and you defeat ~90% of detection signal.

### C.3 TIER-1: Legitimate optimization (default-on; ship in `0.3.1` FREE-tier)

These are the techniques the academic literature + practitioner consensus agree are "good writing" — not "evasion."

#### T1-A. Voice grounding from user's writing samples

Per [arXiv 2509.14543](https://arxiv.org/abs/2509.14543) (Bao et al. 2025) + [arXiv 2604.24444 Post-Editing LLM Text](https://arxiv.org/abs/2604.24444) + [arXiv 2604.26460 Theory-Grounded Evaluation](https://arxiv.org/abs/2604.26460):

- LLMs plateau at 4-5 demonstrations for style imitation (sample efficiency).
- Style imitation works well on structured formats (cover letters fit this); plateaus on informal blogs.
- **This is the single most powerful evasion technique because it's not evasion — it's truth.** The output matches the user's natural sentence-length distribution and idiomatic phrases.

**Implementation:** add a 2-5 sample block sourced from:

- `Profile.summary_full` (paragraph the user wrote)
- `Profile.summary_short` (one-liner the user wrote)
- All `ProfileAnswer.answer` rows (shipped 0.2.7.14) — user's prior screener responses (~20-100 × ~300 chars = ~10K chars)
- `Bullet.text` of the highest-tagged-relevance bullets (a writer's experience descriptions are voice-revealing)
- (optional) Past cover letter sections (when we eventually have multi-app history)
- (optional) User-uploaded "writing sample" via new `Settings.ai_writing_voice_samples: str` textarea (~500-2000 chars)

Prompt pattern (extends `draft_cover_letter.py`):

```python
PROMPT = """Draft a cover letter for this candidate × job pair.

THE CANDIDATE'S OWN VOICE — Use these samples to ground style:
{user_writing_samples}  # 2-5 paragraphs the user wrote

Match the user's sentence-length variance (avg sentence length: {avg_sentence_length:.1f} chars; std dev: {std_sentence_length:.1f}).
Match the user's reading-ease (Flesch: {flesch_reading_ease:.1f}).

Avoid AI-tell vocabulary and structures:
- Do NOT use: "delve", "leverage", "robust", "intricate", "in conclusion", "furthermore", "moreover", "stark", "navigating", "underscore", "harness the power".
- Do NOT use em-dashes ( — ); use commas, periods, or rephrase.
- Do NOT open paragraphs with "I am excited" / "I am writing to express" / "It is with great enthusiasm".
- AVOID balanced clauses ("X is critical, and Y is equally critical").
- VARY sentence length; don't write three medium sentences in a row.

CANDIDATE PROFILE:
{profile}

JOB:
{job}

TONE: {tone}
..."""
```

**~200 LOC** added to `draft_cover_letter.py` (style-feature extractor + sample selection) + ~100 LOC in `services/voice_grounding.py` (compute Flesch score + sentence stats via `textstat` library — MIT-licensed).

#### T1-B. AI-tell vocabulary blocklist + em-dash removal

Curated list to forbid in prompt + post-process strip:

- `delve`, `delves`, `delving` — top em-dash equivalent for vocabulary ([Hacker News 45045897](https://news.ycombinator.com/item?id=45045897), [Em-dash effect LinkedIn](https://www.linkedin.com/pulse/em-dash-effect-ai-fingerprints-cvs-resumes-john-parkinson-bnulf))
- `leverage`, `leveraging`, `leveraged`
- `robust`, `seamless`, `crucial`, `pivotal`, `intricate`, `comprehensive`, `multifaceted`
- `landscape` (as in "the evolving landscape of...")
- `navigate`, `navigating`
- `tapestry` (AI generative-art tic)
- `dive deep into`, `it's important to note that`, `it goes without saying`, `in today's fast-paced world`
- Em-dash ` — ` (replaced with `, ` or `. ` or removed)

Post-process: regex-scan LLM output; if any blocked token found, re-prompt with "rewrite without using these words" OR pass through a small post-edit transform that swaps for synonyms.

**~50 LOC** in `services/ai_tell_blocklist.py`. ~30 entries + post-process regex.

#### T1-C. Burstiness + perplexity injection — natural variance

Per [DIPPER paper arXiv 2303.13408](https://arxiv.org/abs/2303.13408) (Krishna et al. NeurIPS 2023) + [arXiv 2506.07001 Adversarial Paraphrasing](https://arxiv.org/abs/2506.07001):

- AI tends to uniform sentence length.
- Human writing has high variance (some 8-word sentences, some 28-word, in the same paragraph).
- Injecting variance is the simplest effective evasion technique.

**Implementation: prompt instruction-level injection** (NOT post-process rewriting — too lossy):

- Tell the LLM: "Write 1 short sentence (8-12 words), then 1 long sentence (22-35 words), then 1 medium sentence (15-20 words). Repeat with varied order in each paragraph."
- Validate: post-generation, compute std-dev of sentence lengths. If < 6 chars (uniform), regenerate with "the previous draft was too uniform; vary length more."

**~80 LOC** in `services/burstiness_check.py`.

#### T1-D. Perplexity matching — lexically uncommon-but-natural word choice

Too-low perplexity = AI tell. Inject lexically rare-but-natural words from the user's own vocabulary (extracted from voice-grounding samples):

- Extract user's top-100 unique non-stopword tokens from their writing.
- Tell the LLM: "Bias word choice toward this user-specific vocabulary list when natural: {vocab_list}".

Meaningfully different from "inject random rare words" — we match the user's actual vocabulary. Stays within voice.

**~60 LOC** in `services/voice_grounding.py` (TF-IDF extractor against generic corpus; identify what's distinctive about the user's writing).

#### T1-E. Quantification

**40% callback uplift on quantified resumes.** [Jobscan study cited in Resume.io](https://resume.io/blog/quantify-your-resume-bullets). 34% of hiring managers pass over resumes with few/no measurable results. Naavik's existing `trim_bullet.py` says "Preserve every number, every verb, the most concrete result." ✓ Keep. Bake "every claim with a number when one exists in source" into constitution.

#### T1-F. Defensible reduction not invention

AI trims the user's existing long-form bullet to a tighter version. The semantic content was the user's; AI just compresses. AI-detectors trained on "AI invented this" patterns miss "AI summarized this" patterns at a lower rate. Enforced via citation-grounded generation (§ G.7).

### C.4 TIER-2: Gray-area but defensible (opt-in toggle in Settings; informed-consent dialog)

#### T2-A. Detector-roundtrip validation (run output through Originality.ai API; regenerate if flagged)

Per Originality.ai pricing: $30 PAYG = 30k words = ~$0.001/cover-letter for AI-detection check. Negligible cost.

- If output > 0.30 AI-likelihood probability, regenerate with stronger style anchoring (e.g., paste 2 more user samples).
- Hard cap: 3 retries before giving up (avoid infinite loop).

**Trade-off (TIER-2 because gray-area):**

- Pro: catches detector-positive output before submission.
- Con: detector returns false-positives on 2.1-9.2% of human-written text already (Stanford); regenerating *might* introduce new tells.
- Con: $0.001 per check × N retries adds to daily cap.
- Con: implies "we're playing the detection arms race" — some users will find this distasteful.

**Recommendation:** Ship as **Setting toggle (off by default)** — "Run AI-detection check before save (uses Originality.ai API)". When on, attach `ai_detection_score` to `GeneratedDocument.bullet_selection` JSONB for auditability. Cost surfaces in the daily cost cap.

**~120 LOC** in `services/ai_detection_check.py` + new `Setting.ai_detection_check_enabled` + new env var `ORIGINALITY_AI_API_KEY` (per AGENTS.md vault-sunset pattern; `.env.example` slot).

#### T2-B. 2-pass paraphrase via secondary LLM (DIPPER-style)

Per [arXiv 2506.07001](https://arxiv.org/abs/2506.07001): adversarial paraphrasing drops detection 87.88% on average. BUT — "mostly a slight degradation in text quality." For a cover letter, slight degradation = loss of professionalism. Defer to `0.3.3` catch-all as a possible enhancement.

#### T2-C. Mix-in human seed — 30-50% verbatim user-written sentences

Take the user's `Profile.summary_full` + their best-tagged bullets — verbatim — and weave them through the cover letter. The detector struggles when 50% of the text is provably user-written (because it IS). **Ship as partial-implementation in the cover-letter draft prompt** — instruct the LLM to "incorporate verbatim phrases from the candidate's profile when natural; prefer the candidate's own words over rephrasing them." Don't add a separate detection-evasion module; bake into voice-grounding (T1-A).

#### T2-D. Adversarial generator-critic loop (Claude-as-detector + refine)

The Claude-mythos technique: Claude-as-detector scores each draft; refines if flag-confidence > threshold (0.25); max 3 iterations. Inner loop is cheap (~$0.005/check); outer convergence is bounded. **Recommend PREMIUM-tier opt-in (`0.3.4.01`).**

### C.5 TIER-3: Black-hat / blacklist-risk (SURFACE + WARN + NEVER DEFAULT)

#### T3-A. Invisible-text keyword injection (white-on-white; zero-width characters; homoglyph substitution; metadata-only keyword injection)

**Status: BLACKLIST RISK; possibly resume-fraud-adjacent.**

- Some companies maintain internal blacklists of candidates who used deceptive practices; **these blacklists are shared across companies in the same recruiter network** per [airesume.guru](https://airesume.guru/blog/hidden-keywords-white-text-on-resumes-the-myth-that-gets-you-blacklisted).

#### T3-B. Adversarial paraphrasing (DIPPER-style; multi-round detector-guided rewriting)

**Status: Detectable as 2-pass artifact; possibly inflates the cost cap.** Drops detection 87.88% (powerful) — but text quality degrades meaningfully. Requires running output through TWO LLM passes per generation. For a cover letter where the user must own the words, this is borderline fraud-adjacent. Defer to user research.

#### T3-C. PDF metadata keyword spam

#### T3-D. Inflated job titles or fabricated credentials

## D · Recruiter pre-screen optimization (the "potential hire" flag)

### D.1 The 6-second skim — what's actually true

| Study | N | Median scan time |
|---|---|---|
| Ladders Inc. 2012 (original eye-tracking) | 30 recruiters × 10 weeks | **6.0 seconds** |
| Ladders Inc. 2018 update | Larger sample, same methodology | **7.4 seconds** |
| InterviewPal 2025 | 4,289 reviews × 312 recruiters (US/UK/SEA) | **11.2 seconds** |

Pattern: scan time has **increased**, not decreased, with the rise of ATS auto-screening (recruiters spend more time per resume that survives the ATS filter, because there are fewer of them to look at).

**Naavik design implication:** target the 6-11 second skim window, not the 6-second one. Optimize for "what gets read in the first 8 seconds."

### D.2 The 6 eye-tracking fixation points (Ladders 2018 + ResumeHeatMap 2026)

In order of attention (heat-map clusters):

1. **Name** — center-top, ~1.0 sec
2. **Most-recent job title + company** — top-left below name, ~1.5 sec ("who are they working at now?")
3. **Most-recent dates** — right-aligned, ~0.5 sec ("for how long?")
4. **Education institution** — bottom-left, ~0.5 sec (school name is heuristic for "good")
5. **Previous job title + company + dates** — second Experience entry, ~1.5 sec (trajectory signal)
6. **Skills list** if visually distinct — quick keyword scan against JD

**80% of 6-second attention** lands on these 6 fixation points. The remaining 20% scatters across skills + bullets-of-experience-#1.

[Source: A4CV eye-tracking 2026](https://a4cv.app/blog/six-second-resume-scan-eye-tracking-reveals-what-recruiters-see/): F-pattern scan; 80% of viewing time in top third of page 1; bottom 30% often completely ignored in initial skim.

**Current `onepage.typ` (verified):** name in 14pt bold center; headline immediately below; Experience block — title + company on one line, location + dates on same line; Education at bottom. **Pass on structure; tune the content.**

### D.3 Name + title + headline (the recruiter-pre-screen lever)

**Current `onepage.typ` emits:**

```
{full_name}
{headline}
{email} · {phone} · {location}
{linkedin} · {github} · {portfolio_url}
```

**Extend `headline` to a JD-tailored 1-line pitch** ([Title] | [Years/Credential] | [Signature Achievement]), not a static profile field:

```
Senior ML/AI Engineer · 8+ years · ML platform + LLM systems · Open to ML/AI roles · H1B requires sponsorship
```

SOTA pattern (zety, Resume Optimizer Pro, novoresume converge):

- **Job title** (matching the JD's target title where ethical) — 10.6× interview signal per [jobshinobi](https://www.jobshinobi.com/blog/jobscan-resume-scanner-how-it-works).
- **Years of experience** (numeric; recruiter pattern-matches to seniority requirement).
- **Specialty / domain** (1-2 phrases the JD specifically calls for).
- **Sponsorship signal** (only when relevant — `H1B requires sponsorship` if visa concern; `Work-authorized in US` if not). Saves the recruiter a click; gets the candidate filtered IN (or OUT) cleanly.

**Naavik implementation:** new prompt `tailor_headline.py` (LLM call gated on `JobScore.score >= 0.50`):

- Input: `Profile.headline` + `Profile.summary_full` + `Job.role` + `Job.role_family` + `Job.description` + `Profile.work_authorization`
- Output: `TailoredHeadline{headline: str (max 100 chars), keywords_emphasized: list[str]}`
- Validates: each ` · `-separated chunk ≤ 30 chars; total ≤ 100 chars (one-line constraint).

**~80 LOC** in `services/recruiter_optimization.py` + `llm/prompts/tailor_headline.py`.

Cross-source (jobshinobi.com + resumeoptimizerpro + uppl.ai + theinterviewguys + [Jobscan State of Job Search 2025](https://www.jobscan.co/blog/what-jobscan-match-rate-should-i-aim-for/)):

- Personalized greeting: 50% more positive responses (TopResume; SHRM 42%; JobScan 42%).
- 72% of hiring managers prefer personalized greetings (Indeed).
- 87% notice when candidates find the right name (SHRM 2026).

**Ship a SOTA cover letter pipeline (`0.3.1.05`):**

Replace current 4-section template ({intro, body, why_company, close}) with a SOTA 3-paragraph + signature structure:

- **§1 The Hook (2-3 sentences):** Open with a specific JD-pain-point reference + 1-line achievement-story matching that pain. NOT "I am writing to apply for..." — start with the company's challenge.

- **§3 The Close (2 sentences):** Specific ask — "I'd love 20 minutes to discuss how my X work on Y might fit your Z initiative" — NOT "I look forward to hearing from you."

## G · Claude-mythos-tier techniques (the FREE/PREMIUM differentiator)

The 12 techniques the user explicitly asked for — techniques that lean on Claude's specific capabilities (multi-agent, 1M context, extended thinking, structured outputs, tool use, prompt caching) as a tactical substrate. Each is paired with its cost multiplier so the user can lock-in FREE vs PREMIUM.

### G.1 Long-context profile grounding (Claude's 1M context window)

**The technique:** every Stage 1-5 LLM call gets the user's entire writing corpus injected into the system message as voice anchor. Cached via [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) (90% off on cache reads, $0.30/MTok).

**The corpus inputs:**

- All `Bullet.text` rows for the user (~50-100 bullets × ~200 chars = ~12K chars)
- `Profile.summary_full` + `Profile.summary_short`
- All `ProfileAnswer.answer` rows (shipped 0.2.7.14) — user's prior screener responses (~20-100 × ~300 chars = ~10K chars)
- Past cover letter sections (when we eventually have multi-app history)
- Onboarding intake responses (Profile · open-text fields)
- Optional: a single user-uploaded "writing sample" (~500-2000 chars)

**Total corpus:** ~25-50K tokens. At Claude Opus 4.7 / Sonnet 4.6 input rates ($5 / $3 per MTok respectively), one fresh load is $0.075 (Opus) or $0.045 (Sonnet) per call. **With prompt caching enabled (cache_read $0.30/MTok), second-and-subsequent calls cost ~$0.008 per call.** For multi-stage generation (5-9 stages per app), cache amortization is huge.

**System message preamble (the "voice anchor"):**

```
Below is the candidate's complete corpus of authored writing. Match this voice exactly when generating any output. Key voice signatures:
- Sentence-length distribution: [histogram extracted from corpus]
- Idiomatic phrases: [extracted from corpus]
- Vocabulary: [vocab-fingerprint extracted from corpus]
- Tendencies: [pattern extracted, e.g. "leads with verb 70% of time, with number 50%"]

CORPUS:
[full bullets + past answers + cover letter sections]

CONSTITUTION:
[see § G.2]

TASK:
[stage-specific user message]
```

**Cost projection (5 stages per app, Sonnet 4.6, caching enabled):**

- Stage 1 cache write: $0.045 (cache_write 1.25× base, ~24K input tokens)
- Stages 2-5 cache reads: 4 × $0.008 = $0.032
- Output tokens per stage (~500 tokens × 5 stages × $0.015/Ktok): $0.038
- **Total: ~$0.115 per app for voice-grounded generation** (vs ~$0.045 / $0.06 without caching).

**Recommended for FREE-tier** — voice grounding is the single highest-ROI technique because it kills AI-detection at the source. Cache hit rate determines cost; with 5-stage pipeline + 5-minute cache TTL, all 5 calls hit the cache.

### G.2 Constitutional AI generation

**The technique:** every Claude call's system message includes a "constitution" — a structured set of constraints and persona-definitions that bound output behavior. Inspired by [Anthropic's own 80-page Claude Constitution (Jan 2026)](https://natesnewsletter.substack.com/p/what-anthropics-new-constitution).

**Naavik's per-user constitution structure (YAML; cached in `Settings.generation_constitution` JSONB):**

```yaml
identity:
  i_am: Shyam Padia
  role: Senior Software Engineer at Intuit (Personalization/Marketing Tech)
  experience: 8+ years, 5.5+ at Intuit US
  education: MS CS Northeastern, BE CE Mumbai
  visa: H1B with i-140 pending — REQUIRES SPONSORSHIP

voice:
  sentence_length_distribution: {short: 35%, medium: 50%, long: 15%}
  preferred_idioms: ["built", "shipped", "led", "designed", "scaled"]
  avoided_phrases: ["delve", "tapestry", "in conclusion", "leverage", "elevate", "robust",
                    "spearhead", "in today's fast-paced", "moreover", "furthermore"]
  preferred_punctuation: "commas for clauses; em-dashes ONLY for parenthetical asides (rare)"
  number_preference: "every claim with a number, when a number exists in source"

honesty_constraints:
  no_fabrication: "Every claim must trace to a Bullet/Profile field. Never invent."
  no_inflated_titles: "Use job titles as recorded in the Profile; do not embellish."
  defensibility: "If the candidate is asked about any claim in interview, they can defend it."

style_constraints:
  bullet_format: "Verb-first 50% of time. Number-first 30% of time. Subject-first 20%."
  bullet_length: "Single line, 60-130 chars. Vary."
  parallel_clause_habit: "Avoid LLM's parallel-clause habit; mix structures."

forbidden:
  - em_dash_inside_sentence
  - the_blacklist_of_AI_tell_phrases (see voice.avoided_phrases)
```

The constitution sits at SYSTEM message in every Claude call. The user message is the stage-specific task.

**Cost impact:** ~1-2K tokens added to system message. Cached via prompt caching. Marginal.

**Refinement loop:** extract constitution from user's existing writing samples **once per user** (background job, run when Profile is created or significantly edited). Cache in `Settings.generation_constitution` JSONB and re-use across all 0.3.1 generations. Update incrementally when new corpus arrives.

**Recommended for FREE-tier.**

### G.3 Self-consistency sampling (N-vote council) — bullet selection

**The technique:** for high-stakes decisions (which 8 bullets, which JD pain points), generate N variants (temperature ~0.7-0.9) and have Claude-as-judge pick the best.

**Two variants:**

| Variant | N | Cost multiplier | Quality gain |
|---|---|---|---|
| **Self-consistency (1 prompt, N samples)** | 3-5 | ~3-5× | Catches obvious bad samples |
| **Multi-agent council (N different personas, voting)** | 3-7 | ~3-7× | Distinct perspectives; better quality |

**Naavik's premium-tier choice: 3-agent council with distinct personas.** Per [LLM Council paper arXiv 2604.02923](https://arxiv.org/pdf/2604.02923), heterogeneous personas (different roles, not different models) beat same-model multi-instance.

**The 3 council members for bullet selection (Stage 2):**

- **Persona A — Pragmatic recruiter:** "Pick the 8 bullets that read as the strongest match to the JD's required skills. Prioritize quantification + alignment."
- **Persona B — Hiring manager:** "Pick the 8 bullets that showcase the candidate's most transferable + senior-level impact. Prioritize ownership + scope + leadership."
- **Persona C — Cultural-fit assessor:** "Pick the 8 bullets that align to the company's culture signals (work style, values, scale). Prioritize fit + curiosity."

Each persona returns an ordered list of bullet IDs. Merge: borda count vote — each bullet scored = N - rank_in_each_persona; bullets ranked highly by all 3 win.

**Cost projection (per app):**

- 3 Claude calls × ~500 output tokens × Sonnet 4.6 ($3 in / $15 out)
- Voice grounding cached: ~$0.025 per call
- Total: ~$0.075 for bullet-selection vote (vs ~$0.025 for single-shot)

**Recommended for PREMIUM-tier; opt-in default.**

### G.4 Multi-persona recruiter critique council

**The technique:** after draft resume rendered (Stage 7), submit to N=3 Claude instances each embodying a distinct recruiter persona. Each returns specific feedback. Merge feedback → identify high-confidence issues (all 3 flag the same thing) and surface to user OR auto-refine.

**The 3 personas:**

| Persona | Goal | Output |
|---|---|---|
| **FAANG L5/L6 hiring manager** | 6-second skim simulation | Flags: name/role/years/seniority clarity, signature-achievement-in-headline check, scale-of-impact, sponsorship-status-readable |
| **Series A/B startup founder** | Same 6-second simulation, startup priorities | Flags: ownership clarity, range of experience, generalist signal, scrappiness |
| **Fortune-500 HR-screener (Workday-using)** | Parser fidelity + keyword match | Flags: JD-keyword density, sponsorship clarity, education + visa visibility |

**Cost projection (per app):** 3 calls × ~800 output tokens × Sonnet 4.6 = ~$0.04. Voice grounding cached.

**Recommended for PREMIUM-tier.**

### G.5 Extended thinking / chain-of-thought (Claude Opus 4.7 adaptive thinking)

**The technique:** Anthropic's extended-thinking API lets Claude run a long "scratchpad" reasoning phase before emitting final structured output. [Claude Opus 4.7 + Sonnet 4.6 use `thinking: {type: "adaptive"}`](https://platform.claude.com/docs/en/about-claude/models/whats-new-claude-4-7); older Claude 4 models use the explicit budget. The model dynamically decides how much to think.

For Naavik's bullet selection (Stage 2), the scratchpad prompt:

```
Reason about which 8 bullets from these 50 most-strongly align with this JD's specific pain points. Consider:
- Visa constraint (candidate needs sponsorship; JD must allow)
- Seniority signal (JD says "Senior"; candidate is 8 yrs)
- Recency (recent bullets > old ones)
- Quantification (numbers > qualitative)
- Recruiter pre-screen heuristics (top of resume = top-third skim zone)
- Defensibility (can the candidate defend in interview?)
Show your reasoning. Then return BulletSelection.
```

For cover letter (Stage 5), extended thinking surfaces pain-point identification + hook-paragraph candidates + defensibility check per claim.

**Cost projection:** thinking tokens billed at output rate. Adaptive thinking dynamically scales (~500-3000 thinking tokens per Stage 2 call). At Sonnet 4.6 output rate ($15/MTok), $0.0075 - $0.045 per stage.

**Recommended:** PREMIUM-tier for Stage 2 (bullet selection) and Stage 5 (cover letter). FREE-tier could skip thinking for cost.

**Interleaved thinking** ([beta header `interleaved-thinking-2025-05-14`](https://platform.claude.com/docs/en/build-with-claude/extended-thinking) for Claude 4 models other than 4.6+ which auto-enable) lets Claude think between tool calls. Critical for § G.6 tool-loop refinement.

### G.6 Tool-use orchestration (the refinement loop)

**The technique:** Claude orchestrates a tool loop where each tool returns a structured signal and Claude decides "ship" or "iterate."

**The 5 tools:**

| Tool | What it does | Returns | Stage where called |
|---|---|---|---|
| **`ats_parse_test(pdf_bytes)`** | Runs N open-source parsers (§ B.9) on the PDF | Per-parser field-match score + overall | After Stage 7 render |
| **`ai_detector_test(text)`** | Runs Claude-as-detector OR a real GPTZero/Originality.ai API roundtrip | Per-detector AI-flag confidence | After Stage 3 trim |
| **`recruiter_skim_score(text)`** | Claude-as-recruiter simulating 6-second skim | Score 0-100 + 3-bullet feedback | After Stage 7 |
| **`keyword_density_check(text, jd)`** | Computes JD-keyword coverage in top 30% | Per-keyword pass/fail | After Stage 3 |
| **`defensibility_check(bullet_text, profile)`** | Verifies bullet derives from `Bullet.id` (no invention) | Per-bullet provenance | Pre-Stage 7 |

Claude orchestrates: emit tailored draft → call all 5 tools → decide ship-or-iterate → if iterate, emit refined draft and repeat.

**Implementation via Anthropic's tool_use:** define the 5 tools as structured-output tools. Use `interleaved-thinking-2025-05-14` beta header so Claude reasons between tool calls ([Source: tool_use docs](https://docs.anthropic.com/en/docs/build-with-claude/tool-use)).

**Iteration cap:** 3 iterations max. Each iteration ~2-4 Claude calls (orchestrator + tools) → ~$0.04-0.10 per iteration. **Synthesized cap: 3 with budget-aware early exit (OQ-3).**

**Recommended for PREMIUM-tier.**

### G.7 Citation-grounded generation (the defensibility lever)

**The technique:** every output bullet carries provenance — the source `Bullet.id` it derived from + the specific JD signal (keyword / pain point) it addresses. Enforced via Pydantic structured output.

**The shape:**

```python
class TailoredBullet(BaseModel):
    source_bullet_id: int  # FK to Bullet.id, must exist for this user
    output_text: str  # the trimmed/rewritten bullet
    jd_signal_addressed: str  # which keyword/pain-point this addresses
    defense_note: str  # 1-line: "how would the candidate defend this?"
```

**Code enforcement:** `defensibility_check` tool (§ G.6) verifies `source_bullet_id` is a real `Bullet.id` for this user. If LLM hallucinated an ID, reject and re-prompt.

**User-facing surface:** Discover · review & apply screen shows each bullet alongside its citation: "← derived from your Intuit bullet #47, addresses 'distributed systems' keyword." User can click to see source bullet. **This is the trust feature** — Naavik isn't generating fictional achievements; it's selecting + compressing user's real ones, with audit trail.

**Side-note:** Anthropic structured outputs DO NOT work with the `citations` feature ([400 error](https://towardsdatascience.com/hands-on-with-anthropics-new-structured-output-capabilities/)). Use structured-output-only and roll our own citation field; don't use Anthropic's native citation feature.

**Cost impact:** marginal (~200 tokens per bullet for citation field).

**Recommended for FREE-tier (mandatory).** This is the honesty constraint.

### G.8 Multi-Claude council voting (Borda count consensus)

**The technique:** for high-stakes decisions, 3+ Claude instances each emit a candidate output; consensus computed via Borda count or majority vote. Inspired by [Council Mode arXiv 2604.02923](https://arxiv.org/pdf/2604.02923) — heterogeneous personas explicitly outperform same-prompt multi-instance.

**Already covered in § G.3 (bullet selection) and § G.4 (recruiter critique).** Mentioned here for completeness as a distinct pattern from § G.6 (adversarial generator-critic loop).

**Anthropic Batch API support:** Anthropic supports parallel calls via `messages.batches.create` ([Vertex AI batch predictions](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/partner-models/claude/batch)). **50% discount on batch API submissions.** For PREMIUM-tier 3-agent council, batch-API the 3 calls to cut cost in half. Synchronous mode adds latency (~2s vs 100ms); the user is waiting for the resume so latency budget is real.

**Recommended for PREMIUM-tier.**

### G.9 Adversarial generator-critic loop (Claude-as-detector + refine)

**The technique:** Claude-as-detector scores each trim; refines until flag-confidence < threshold (0.25); max 3 iterations. The detector loop is the canonical AI-detection-evasion mechanism at PREMIUM-tier — defers to T2-D (§ C.4) for the bullet-trim layer + extends to cover letter at Stage 5.

**Cost projection:** ~$0.005/check inner loop; bounded outer convergence. **Recommended PREMIUM-tier opt-in (`0.3.4.01`).**

**Open question OQ-4 (synthesized):** call live AI-detector APIs (real GPTZero, Originality.ai) at $0.001-0.01/call OR trust the Claude-as-detector-critic loop (cheaper but model-self-critique risks model-self-cooperation)? **Architect recommendation: hybrid — Claude-as-detector for fast inner loop; one real detector API roundtrip at convergence for final verification.**

### G.10 Constitutional ethics layer (pre-flight check)

**The technique:** before any output ships, run a final pre-flight check via a separate Claude call: "Does this output (a) make any factual claim not grounded in the candidate's profile? (b) inflate any title or credential? (c) imply experience the candidate doesn't have?" Output: green-light or red-flag-list.

**Enforcement:** if red-flag-list is non-empty, refuse to ship + surface to user with the specific claim flagged + ask user to confirm or refine.

**Cost:** ~$0.01 per pre-flight call.

**Recommended for FREE-tier (mandatory).** This is the safety net. Combined with citation-grounding (§ G.7), it's the defensibility-and-honesty backbone.

### G.11 Embedding-similar-success retrieval (forward-looking)

**The technique:** when Naavik has multi-user cloud data, retrieve "users who got an interview for similar roles" + extract their resume style fingerprint + use as few-shot in-context examples.

**Out of scope for 0.3.1:** Naavik is single-user self-host today; no multi-user dataset yet. **File as 0.5.0+ row when cloud-tier data scale arrives.**

**Privacy:** opt-in only; only style metrics (sentence-length distribution, lexical diversity), never raw bullet content.

### G.12 Anthropic Computer Use (forward-looking)

**The technique:** Claude operates the ATS form via the Computer Use API — clicking buttons, filling fields, uploading the PDF. Bypasses Playwright form-fill brittleness.

**Out of scope for 0.3.1:** Computer Use is overkill for resume generation. **File as `0.4.0.NN` (auto-apply)** where it's more relevant.
