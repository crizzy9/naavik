### 0.4.0.08 — Sponsorship-gate enforcement at submission (HIGH)

**Type:** safety / belt-and-suspenders.

**Problem:** Scorer's visa filter zeros score at score time, but
`submit_draft` does NOT independently re-check. Race condition: Job
scored before Profile.visa_sponsorship_needed was set, OR scorer logic
bypassed (manual `create_manual` Application), → operator can
auto-submit to sponsorship-restricted job. Violates AGENTS.md § Owner
Profile rule.

**Scope:** Extend `validate_submittable` (`application_service.py:279-300`)
to reject with `ValidationError(code="visa_incompatible")` when:
- `Profile.visa_sponsorship_needed == VisaSponsorship.NEEDED_NOW` AND
- `Application.job_id IS NOT NULL` (manual entries bypass — operator
  chose to log it) AND
- `Job.visa_restrictions ∈ {US_CITIZEN_ONLY, GREEN_CARD_REQUIRED}`.

Files: `application_service.py` (~10 LOC), tests
(`test_application_service.py` ~30 LOC, 3 cases).

**Cluster:** Plan 76.

## D · Sponsorship-gate enforcement — locked decision

Per AGENTS.md § Owner Profile, the H1B+i-140 owner requires scoring
sponsorship-restricted jobs at 0. The scorer already honors this at
score time (`scorer/visa.py:35-67`). **But the submission path does
not re-validate.** Risk surfaces in three scenarios:

1. **Race condition** — Job scored before Profile.visa_sponsorship_needed
   was set. `Job.score` is non-zero. Operator right-swipes → DRAFT
   queues → cron submits.
2. **Manual entry** — Operator creates Application via
   `application_service.create_manual` (Add manually button). No
   `job_id`, no scoring. Operator could submit to a no-sponsorship
   job by mistake (e.g. importing a saved external link).
3. **Stale Job.visa_restrictions** — Scraper didn't extract
   visa_restrictions on first pass; LLM extraction filled it later;
   the existing Job.score reflects the pre-extraction null value.

**Decision (architect; owner approval implicit via H1B profile rule):**
Belt-and-suspenders enforcement at `validate_submittable`:

```python
# In application_service.validate_submittable(...)
if application.job_id is not None:
    profile = await session.exec(
        select(Profile).where(Profile.user_id == application.user_id)
    ).one_or_none()
    job = await session.exec(
        select(Job).where(Job.id == application.job_id)
    ).one_or_none()
    if (
        profile is not None
        and job is not None
        and visa.needs_visa_zero_out(profile, job)
    ):
        raise ValidationError(
            "Job requires sponsorship Naavik can't provide. Submission blocked. "
            "Override by clearing Profile.visa_sponsorship_needed if you have a "
            "valid US work authorization for this role.",
            code="visa_incompatible",
        )
```

Reuses the existing `scorer.visa.needs_visa_zero_out` predicate (zero
new logic). Manual entries (`application.job_id IS NULL`) bypass —
operator explicitly chose to log it.

**Filed as 0.4.0.08** (HIGH priority; first task to ship in 0.4.0
cycle; Plan 76 ships it).
